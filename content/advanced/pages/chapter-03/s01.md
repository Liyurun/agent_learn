## 真实问题

一位准备面试的工程师被问：「从技术演进看，Agent 是怎么发展来的？」他一口气背出十几个论文名和框架名——CoT、ReAct、AutoGPT、LangChain、CrewAI……面试官打断他：「你能说清 ReAct 相比 CoT 到底多了什么、为什么它是分水岭吗？」他卡住了。这是一个典型失败：**把名词的堆砌当成理解**。真正的脉络不是一张论文清单，而是一条「能力逐步补齐」的主线——每一步都在解决上一步做不到的事。看不清这条主线，你既答不好面试，也无法判断某个新框架到底补了什么、值不值得学。

本节的目标，是让你能在白板上默画出这条主线，并说清每一跳「补」了什么能力。

## 原理：四个阶段，四次能力跃迁

Agent 不是某一天被发明出来的，而是四个关键思想逐步叠加的结果。理解这条脉络，关键在于始终问一句：「这一步补上了上一步缺的什么能力？」

**第一阶段：让模型「会思考」（2022）**

- CoT（Chain-of-Thought，思维链）：引导模型「一步步思考」，把复杂问题拆成中间推理步骤，显著提升了算术、常识与符号推理任务的表现 [来源](https://arxiv.org/abs/2201.11903)。它给了模型一张「草稿纸」，是「规划能力」的雏形。但此时模型只在脑子里想，想完还是只能吐出一段文字，**不能与外部世界交互**。

**第二阶段：让模型「会行动」（2022–2023）**

- ReAct（Reasoning and Acting，推理并行动）：把推理与行动交织，让模型按 `Thought → Action → Observation`（思考 → 行动 → 观察）循环运行，既能思考又能调用工具查外部信息，再把观察结果喂回下一轮思考 [来源](https://arxiv.org/abs/2210.03629)。这一跳补上的正是「与外部世界交互并根据结果调整」的能力，是现代 Agent 的直接原型。
- Toolformer：探索让语言模型通过自监督学习，自主决定何时、调用哪个 API（Application Programming Interface，应用程序接口）、传什么参数、如何把结果并入生成 [来源](https://arxiv.org/abs/2302.04761)。它把「用不用工具」的决策权交还给了模型自己。

**第三阶段：让模型「会反思」与「会规划得更好」（2023）**

- Reflexion：用语言化的反馈信号让 Agent 反思失败——把失败经验写成自然语言存进「情景记忆」，下次尝试前读回来，从而在不更新模型权重的前提下改进决策 [来源](https://arxiv.org/abs/2303.11366)。它补上的是「从自己的失败里学习」的能力。
- Tree of Thoughts（ToT，思维树）：在 CoT 的单链推理上再进一步，让模型在每一步探索多条「思考」分支、自评优劣、必要时回溯，形成一棵搜索树 [来源](https://arxiv.org/abs/2305.10601)。它补上的是「不吊死在一条路上、可以择优而行」的规划升级。

**第四阶段：从论文走向工程与标准（2023–2026）**

- 方法论沉淀：Lilian Weng 的《LLM Powered Autonomous Agents》把 Planning（规划）/ Memory（记忆）/ Tool Use（工具使用）体系化 [来源](https://lilianweng.github.io/posts/2023-06-23-agent/)；Anthropic 的《Building Effective Agents》提出五种工作流模式与「从简单开始」的设计原则 [来源](https://www.anthropic.com/engineering/building-effective-agents)。
- 框架百花齐放：LangGraph、smolagents、PydanticAI、CrewAI、OpenAI Agents SDK（Software Development Kit，软件开发工具包）等（卷四详解）。
- 互操作标准确立：Anthropic 于 2024 年 11 月发布 MCP（Model Context Protocol，模型上下文协议），把工具与数据源的集成标准化，被称为「AI 应用的 USB-C」 [来源](https://www.anthropic.com/news/model-context-protocol)。

一句话概括这条脉络：**会思考（CoT）→ 会行动（ReAct）→ 会反思（Reflexion）→ 会协作与标准化（框架 + MCP）**。

## 最小可运行演示

把这条脉络写成一段不联网的纯 Python 数据结构，你就能在代码里「查」每个里程碑补了哪种能力，而不是死记年份。
```python
from dataclasses import dataclass


@dataclass
class Milestone:
    year: str
    name: str
    added_capability: str   # 相比上一步补上的能力
    one_line: str           # 一句话记忆


TIMELINE = [
    Milestone("2022", "CoT", "规划雏形：写出中间推理步骤", "给模型一张草稿纸"),
    Milestone("2022-2023", "ReAct", "行动闭环：思考→行动→观察", "想一步、做一步、看一步"),
    Milestone("2023", "Toolformer", "自主决定何时调工具", "模型自己决定用不用工具"),
    Milestone("2023", "Reflexion", "从失败中语言化学习", "自己给自己批改作业"),
    Milestone("2023", "Tree of Thoughts", "多路径搜索+回溯", "不止一条路，择优而行"),
    Milestone("2024-2026", "框架+MCP", "工程化与工具标准化", "从论文变成能上线的产品"),
]


def main() -> None:
    print(f"{'阶段':<10}{'里程碑':<18}补齐的能力")
    print("-" * 52)
    for m in TIMELINE:
        print(f"{m.year:<12}{m.name:<16}{m.added_capability}")
    print("\n主线：", " → ".join(m.name for m in TIMELINE))


if __name__ == "__main__":
    main()
```
保存为 `agent_timeline.py`，运行 `python agent_timeline.py`。预期输出：
```text
阶段        里程碑               补齐的能力
----------------------------------------------------
2022        CoT             规划雏形：写出中间推理步骤
2022-2023   ReAct           行动闭环：思考→行动→观察
2023        Toolformer      自主决定何时调工具
2023        Reflexion       从失败中语言化学习
2023        Tree of Thoughts多路径搜索+回溯
2024-2026   框架+MCP          工程化与工具标准化

主线： CoT → ReAct → Toolformer → Reflexion → Tree of Thoughts → 框架+MCP
```
这段代码的价值在于：它把「脉络」从一段需要背诵的文字，变成一个可以逐条追问「补了什么」的结构。面试前把 `added_capability` 那一列蒙住自己复述，比反复读论文标题有效得多。

## 把脉络画成一条时间轴

文字分阶段容易记不牢，用一条时间轴把「每一步在补什么能力」串起来，你会发现整条脉络其实是在**逐个补齐 Agent 的核心原语**：
```text
  能力维度   2022        2022-23       2023           2023-2026
  ─────────────────────────────────────────────────────────────▶
  会思考     CoT ───────────────────────────────────────────────
  (规划雏形) 一步步想，写出中间步骤

  会行动               ReAct ──────────────────────────────────
  (工具使用)           Thought→Action→Observation
                       Toolformer(自监督学会调 API)

  会反思                            Reflexion ─────────────────
  (规划升级)                        语言化反馈，反思失败存入记忆
                                    Tree of Thoughts(多路径搜索+回溯)

  会协作与标准化                                框架(LangGraph 等)
  (工程落地)                                    + MCP(工具标准化)
```
看这条轴的关键洞察：**从 CoT 到 ReAct 的那一跳，是「思考」加上了「行动」——这正是第 1 章所说「LLM 在循环中使用工具」的诞生时刻**。CoT 让模型会想，但它只在脑子里想；ReAct 让模型想完能去做、做完能看结果、再接着想，闭环由此形成。可以说，**ReAct 是 Agent 从「会推理的语言模型」变成「会行动的智能体」的分水岭**。

## 一张表：每个里程碑「补」了什么

| 里程碑 | 核心贡献 | 对应能力原语 | 一句话记忆 |
|---|---|---|---|
| CoT | 显式写出推理链 | 规划（雏形） | 给模型一张草稿纸 |
| ReAct | 推理 + 行动闭环 | 规划 + 工具使用 | 想一步、做一步、看一步 |
| Toolformer | 自主决定调工具 | 工具使用 | 模型自己决定何时用工具 |
| Reflexion | 反思失败、自我改进 | 规划（升级） | 自己给自己批改作业 |
| Tree of Thoughts | 多路径搜索与回溯 | 规划（升级） | 不止一条路，择优而行 |
| 框架 + MCP | 工程化、标准化 | 全部（落地） | 从论文变成能上线的产品 |

## MCP 为什么被叫做「AI 应用的 USB-C」

MCP 值得单独多说两句，因为它是这条脉络里「工程标准化」阶段最重要的产物。在 MCP 之前，每个 Agent 框架、每个工具都有自己的接入方式：你为某个框架写的工具，换到别的框架要重写；每接一个新数据源（数据库、文件系统、第三方 API），都要写一套专门的胶水代码。这像 USB-C 出现之前，每个设备一种充电口。

MCP 定义了一套**统一协议**：工具/数据源作为「MCP Server（服务端）」暴露能力，Agent 应用作为「MCP Client（客户端）」按标准协议接入，一次实现、处处可用 [来源](https://modelcontextprotocol.io/)。
```text
   MCP 之前（N×M 的胶水地狱）           MCP 之后（N+M 的标准接口）
   AppA ──自定义──▶ 工具1               AppA ─┐            ┌─ MCP Server:工具1
   AppA ──自定义──▶ 工具2                     ├─ MCP 协议 ─┤
   AppB ──自定义──▶ 工具1               AppB ─┘            └─ MCP Server:工具2
   AppB ──自定义──▶ 工具2
   每个组合都要单独适配                  各写一次，即可互通
```
理解 MCP 的意义在于：**它把「工具集成」从每个项目的重复劳动，变成了一个可复用的生态**。它的技术细节是卷五的主题，这里你只需记住它在脉络中的位置——它标志着 Agent 从「各家自己造轮子」进入了「共享生态」的阶段。

## 真实系统对应

**官方公开机制**：MCP 由 Anthropic 于 2024 年 11 月发布 [来源](https://www.anthropic.com/news/model-context-protocol)；2025 年 12 月，MCP 与 Block 的 goose、OpenAI 的 AGENTS.md 一起，成为 Linux 基金会新设立的 Agentic AI Foundation（AAIF，智能体 AI 基金会）的创始项目，OpenAI、Google、微软、AWS、Cloudflare、Bloomberg 等均有支持，治理从「单一厂商」迁入「中立基金会」 [来源](https://blog.modelcontextprotocol.io/posts/2025-12-09-mcp-joins-agentic-ai-foundation/)。这一步坐实了「标准的价值在于网络效应」——一个协议被越多厂商采纳，越没有人能独占它。**通用工程模式**：把「N×M 胶水」重构为「N+M 标准接口」是软件工程里反复出现的抽象手法，不限于 AI。**教学参考实现**：上面 `agent_timeline.py` 里的能力标注是本书为讲清脉络而做的归纳，各论文原文的措辞与侧重可能不同，以链接原文为准。

CoT、ReAct、Reflexion、ToT 均为公开发表的学术论文，可直接核验；框架的能力边界以各自官方文档为准，本书不臆测其内部实现。

## 思考：ReAct 相比 CoT 到底多了什么，为什么说它是分水岭？

### 回答

CoT 只让模型在「一次生成」内部写出中间推理步骤，它的推理全部发生在模型内部，产出仍是一段静态文本，无法在推理过程中获取任何外部新信息。ReAct 多了两样东西：**行动（Action）** 与 **观察（Observation）**。模型可以在推理中途发起一个动作（比如查资料、调工具），拿到真实世界返回的观察结果，再据此调整下一步思考，如此循环。这就把「一次性推理」变成了「可以与环境交互并自我修正的闭环」。之所以是分水岭，是因为「LLM 在循环中使用工具」正是 Agent 的定义性特征——CoT 之前的模型只是「会推理的语言模型」，ReAct 之后才是「会行动的智能体」。

### 面试精简表达

CoT 是「在脑子里想」，ReAct 是「想一步、做一步、看一步」。多出来的「做」和「看」把开环推理接成了闭环，这正是智能体诞生的那一跳。

## 事故回放：把「新框架」误当「新能力」

某团队在 2025 年评估是否把技术栈从旧框架迁到一个热门新框架，理由是「它支持多智能体、支持 MCP、社区活跃」。迁移耗时三周，上线后核心指标（任务成功率、延迟）几乎没变。复盘发现，他们真正的瓶颈是「单步工具调用成功率只有 88%」，而新框架并没有改变这一点——它换的是「协作与标准化」层的能力，而团队缺的是「工具使用可靠性」层的能力。

用本节的脉络就能提前避免这次浪费：先问「我缺的是哪个阶段的能力？」。如果缺的是规划，去看 CoT/ToT 方向的做法；缺的是行动可靠性，去打磨工具校验与重试；缺的是从失败学习，去引入 Reflexion 式的反思记忆；只有当你缺的确实是「多工具、跨框架的互操作」，MCP 与新框架才是对症的药。**把脉络当成一张诊断图，而不是一张流行榜**，这是它最实用的价值。
