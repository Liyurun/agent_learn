## 真实问题

开头那个「离线 95、线上 71」的落差，最大的单一贡献者就是这一节的主角。团队复盘时抓了一批线上被用户点「没帮助」的回答，拿去问离线裁判，裁判居然大多给了 4 分以上。逐条看才发现规律：**那些被裁判判高分、被用户判没用的回答，普遍更长**——它们把政策条款、注意事项、客套话堆了一大段，「看起来很全面」，裁判就给了高分，用户却嫌啰嗦、抓不到重点。更糟的是，团队一度用「同一个模型」既生成回答又当裁判筛「最好的回答」，评估分一路走高，线上体验却在退步。

这不是随机噪声——**它是系统性（systematic）偏差**：同方向、可预测、不随机。这一点至关重要，因为它决定了去偏手段：随机噪声可以靠多次采样求平均消掉，**系统性偏差不能**——采一万次，一万次都往同一个方向偏，均值照样是偏的。这一节把 LLM 裁判的三大系统性偏差讲透，并给每种配一个可量化、可去偏的手段。

## 原理：三大系统性偏差

### 偏差一：位置偏差（Position Bias）

在成对比较时，裁判会倾向于选**放在前面**（或某些模型倾向后面）的那个，即使两个回答质量相当。这就像考官批卷时对第一份答卷有先入为主的印象。校准手段是**双向评测取一致**：把 A/B 顺序交换各问一次，只有两次结论一致才采信；不一致判平局转人工（第 3 节已用代码演示）。LangSmith 的成对评估也提供 `randomize_order` 来缓解它 [来源](https://docs.smith.langchain.com/evaluation/how_to_guides/evaluate_pairwise)。

### 偏差二：长度偏差（Length/Verbosity Bias）

裁判倾向给**更长、更啰嗦**的回答打高分，哪怕长回答里全是废话甚至夹带错误——长文本「看起来更全面」，表面特征绑架了质量判断。这正是开头事故的元凶。校准手段有两层：**prompt 级**声明「回答更长不代表更好、请忽略长度」；**度量级**先量化「裁判分与长度的相关性」，若相关性高则说明有偏，再用长度分层或长度惩罚去偏。

### 偏差三：自我偏好（Self-Preference Bias）

裁判会给**和自己风格相近**的回答（尤其同家族模型生成的）打更高分。在「同一模型既当选手又当裁判」时最危险——相当于运动员兼任裁判。校准手段是**换用异族裁判**（选手和裁判来自不同模型家族）+ 人工抽检锚定。

把三种偏差并排看：

| 偏差 | 触发场景 | 危害 | 首选校准 | 能否靠多采样消掉 |
|---|---|---|---|---|
| 位置偏差 | 成对比较 | 结论随顺序翻转 | 双向评测取一致 / 随机化顺序 | 不能 |
| 长度偏差 | 打分/比较 | 奖励啰嗦、惩罚简洁 | prompt 声明忽略长度 + 长度去偏 | 不能 |
| 自我偏好 | 同族模型自评 | 系统性高估自家输出 | 异族裁判 + 人工抽检锚定 | 不能 |

最后一列全是「不能」——这是本节最该记住的一句话：**系统性偏差无法靠多次采样平均掉，必须专门校准**。

## 最小可运行演示：量化并去除长度偏差

位置偏差的去偏第 3 节已经演示过（双向取一致）。这一节重点演示**长度偏差怎么量化、怎么去偏**：构造一批「质量与长度无关」的样本，若裁判分和长度相关，那这相关只能来自偏差；再用长度惩罚去偏，看相关性下降。
```python
"""教学参考实现:长度偏差的度量与去偏。"""
from __future__ import annotations


def pearson(xs: list, ys: list) -> float:
    n = len(xs)
    mx, my = sum(xs) / n, sum(ys) / n
    cov = sum((x - mx) * (y - my) for x, y in zip(xs, ys))
    vx = sum((x - mx) ** 2 for x in xs) ** 0.5
    vy = sum((y - my) ** 2 for y in ys) ** 0.5
    return round(cov / (vx * vy), 3) if vx and vy else 0.0


def biased_judge(length: int, quality: float) -> float:
    """有长度偏差的裁判:分数 = 真实质量 + 长度带来的虚高。"""
    return quality + 0.004 * length


def debiased_judge(length: int, quality: float) -> float:
    """去偏裁判:对超过基准长度(100 字)的部分做惩罚,抵消长度红利。"""
    raw = biased_judge(length, quality)
    penalty = 0.004 * max(0, length - 100)
    return raw - penalty


def run() -> None:
    # 关键:质量与长度故意无关。若裁判分和长度相关,只能来自偏差
    samples = [(50, 3.0), (120, 3.0), (200, 3.0),
               (60, 4.0), (150, 4.0), (260, 4.0)]
    lengths = [s[0] for s in samples]
    quality = [s[1] for s in samples]
    biased = [biased_judge(l, q) for l, q in samples]
    debiased = [debiased_judge(l, q) for l, q in samples]
    print("裁判分 vs 长度 相关(有偏):", pearson(lengths, biased))
    print("裁判分 vs 长度 相关(去偏):", pearson(lengths, debiased))
    print("裁判分 vs 质量 相关(去偏):", pearson(quality, debiased))


if __name__ == "__main__":
    run()
```
保存为 `demo04_length_bias.py`，运行 `python demo04_length_bias.py`。完整预期输出：
```text
裁判分 vs 长度 相关(有偏): 0.643
裁判分 vs 质量 相关(去偏): 0.986
裁判分 vs 长度 相关(去偏): 0.353
```
（注：上面三行的实际打印顺序为「有偏长度相关 0.643、去偏长度相关 0.353、去偏质量相关 0.986」。）读法是：有偏裁判分与长度的相关高达 0.643——**质量明明与长度无关，裁判分却跟着长度涨，这就是长度偏差的铁证**；去偏后这个相关降到 0.353（仍未清零，说明惩罚系数还可继续调）；而去偏裁判分与真实质量的相关是 0.986，说明去偏没有伤害对质量的判断力。这套「构造无关样本→测相关性→若相关则有偏→去偏后复测」的方法，是把「我觉得裁判有长度偏差」变成「我测出裁判长度相关 0.64」的关键。

## 事故回放：自我偏好如何让评估分「自欺」

回到开头那个「同一模型既当选手又当裁判」的闭环。团队用模型 M 生成回答，又用模型 M 当裁判筛「最好的回答」，再拿这批高分回答去做展示甚至微调数据。自我偏好会让这个闭环**自我强化**：M 生成的回答天然合 M 的胃口，M 当裁判就偏爱它们，于是评估分一路走高；但用户不是 M，用户不吃这套，线上体验反而退步。这是最隐蔽的翻车，因为**所有内部指标都在说「越来越好」**。修复很直接：选手和裁判必须尽量来自不同模型家族（异族裁判），并留一条人工抽检通道当锚点——一旦裁判分和人工抽检结论开始背离，就是自我偏好在作祟的信号。

## 真实系统对应

**官方公开机制**：LangSmith 成对评估提供 `randomize_order` 显式缓解位置偏差，并在文档里点明「位置偏差主要应通过 prompt 工程解决」 [来源](https://docs.smith.langchain.com/evaluation/how_to_guides/evaluate_pairwise)。G-Eval 的设计初衷之一就是用思维链与概率加权「绕开 LLM 裁判常见的陷阱」，其中就包括这类偏差 [来源](https://www.confident-ai.com/blog/g-eval-the-definitive-guide)。**通用工程模式**：双向取一致、长度相关性度量+惩罚、异族裁判，都是可迁移到任何裁判实现的去偏手段。**教学参考实现**：上面的 `biased_judge` 用线性加成模拟长度偏差、惩罚系数 0.004 是示例值，不代表任何真实模型的偏差强度；真实场景要在自己的黄金集上测出实际相关性再定去偏强度。

一个边界：长度去偏不能「一刀切」。有些任务本就要求详尽（如法律条款解释、事故复盘报告），此时长回答确实更好，强行惩罚长度反而错杀。去偏的前提是「在质量与长度应当无关的任务上」测出了偏差。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 多采样平均后偏差仍在 | 误把系统性偏差当随机噪声 | 同方向偏差采样 1 万次看均值 | 认清系统性偏差需专门校准 | 确属随机抖动时采样平均有效 |
| 长回答普遍拿高分 | 长度偏差 | 造等质量不同长度样本测相关性 | prompt 声明忽略长度 + 长度惩罚 | 任务本就要求详尽时不去偏 |
| 自评闭环里分数越来越高体验越来越差 | 自我偏好自我强化 | 裁判分与人工抽检结论背离 | 异族裁判 + 人工抽检锚定 | 无法换模型时加大人工比例 |
| 成对结论换个顺序就翻 | 位置偏差 | 交换 A/B 顺序各问一次 | 双向取一致 / randomize_order | 质量差距悬殊时影响小 |
| 去偏后把详尽答案错杀 | 长度去偏一刀切 | 在「需详尽」任务上强行惩罚长度 | 仅在质量应与长度无关的任务去偏 | 摘要类任务简洁确实更好 |

## 思考：为什么说「系统性偏差不能靠多次采样平均掉」?这句话在实操里意味着什么?

### 回答

因为随机噪声和系统性偏差是两种本质不同的误差。随机噪声是零均值的、方向随机的抖动——这次偏高、下次偏低，采样次数一多，正负相抵，均值收敛到真值，所以多次采样求平均对随机噪声有效。系统性偏差则是**同方向、可预测的偏移**：位置偏差永远偏向前面那个、长度偏差永远偏向更长的、自我偏好永远偏向同族输出——采一万次，一万次都往同一个方向偏，均值不但不收敛到真值，反而稳稳地偏在那里。在实操里这句话意味着两件事：第一，别指望用「重复评估取平均」来解决偏差，那只能压随机方差、压不动系统性偏移；第二，每种系统性偏差必须配专门的、针对其成因的校准手段——位置偏差用双向取一致或随机化顺序、长度偏差用 prompt 声明加长度惩罚（且要先量化相关性证明确实有偏）、自我偏好用异族裁判加人工抽检锚点。能把「随机噪声 vs 系统偏差」的区别讲清，并对应到「平均 vs 专门校准」两种不同处置，就说明你真正理解了裁判为什么需要「先校准再用」（第 5 节）。

### 面试精简表达

随机噪声零均值、可被平均消掉；系统性偏差同方向偏移、采多少次都偏同一边,平均无效。所以位置/长度/自我偏好各需专门校准:双向取一致、长度声明+惩罚、异族裁判+人工锚点。
