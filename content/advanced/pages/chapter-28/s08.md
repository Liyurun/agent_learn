## 真实问题

「离线 95、线上 71」结案后，团队想把整章教训沉淀成一份能防复发的清单，却发现难点不在「知道要校准裁判」，而在**评估体系的失败太隐蔽**：它不像程序崩溃那样有堆栈，而是「所有指标都在往好的方向骗你」。裁判有偏你不知道、评估集泄题你不知道、评估集被污染你不知道——直到线上出事、人工抽检倒查，才后知后觉。把这类「静默失败」拆成可定位的层、每层配上「症状—根因—观测—修复—边界」，才是这份清单的价值。

这一节做两件事：先给一张覆盖评估进阶各层的生产建议大表与一个可运行的「评估体系体检器」，再用多道「思考+回答」把全章方法论收口，直接对齐高频面试题。

## 诊断顺序：评估体系怎么自检

遇到「离线好、线上崩」，不要先归结为「模型不行」，而要按评估链条分层排查，每层都有可观测证据：

1. **裁判层**：裁判和人工黄金集的 Cohen's Kappa（科恩卡帕系数）是多少？低于 0.6 说明裁判本身不可信，一切建立其上的分数都存疑。
2. **偏差层**：裁判分与回答长度的相关性高吗？成对结论换个顺序会翻吗？选手和裁判同族吗？——分别对应长度、位置、自我偏好三种偏差。
3. **数据层**：评估集有没有被用来调 prompt（优化泄漏）？同源样本有没有切到两侧（切分泄漏）？有没有用未来信息（时间泄漏）？评估集 hash 和训练集重叠吗（污染）？
4. **覆盖层**：评估集的 persona（用户画像）覆盖了对抗型用户吗？还是只有合作型？
5. **轨迹层**：只评了结果，还是也评了工具选择、参数、顺序、步数？危险顺序在离线能被拦下吗？
6. **在线层**：离线到全量之间，有没有影子流量、A/B、灰度这几层过渡带？A/B 看的是业务指标还是离线代理指标？做显著性检验了吗？

## 生产建议：评估进阶症状矩阵

下面把全章各层的坑汇成一张矩阵，每行都是一个真实会发生、可观测、有修复、也有不适用边界的条目。它是这份清单的主体。

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 离线分高线上崩 | 泄漏+裁判有偏且未校准的复合成因 | 对比离线通过率与线上人工抽检率 | 逐层排查:Kappa→偏差→泄漏→覆盖→轨迹 | 分布确实剧变时需重建评估集 |
| 裁判分随回答变长升高 | 长度偏差 | 造等质量不同长度样本测相关性 | prompt 声明忽略长度 + 长度惩罚 | 任务本就要求详尽时不去偏 |
| 成对结论换顺序就翻 | 位置偏差 | 交换 A/B 顺序各问一次 | 双向取一致或 randomize_order | 质量差距悬殊时影响小 |
| 自评闭环分越来越高体验越来越差 | 自我偏好自我强化 | 裁判分与人工抽检结论背离 | 异族裁判 + 人工抽检锚定 | 无法换模型时加大人工比例 |
| 一致率 0.9 却选到坏裁判 | 只看一致率、忽略类别失衡 | 造 9 成同类样本让裁判无脑全判 | 用 Cohen's Kappa 判读 | 类别本就均衡时一致率也够用 |
| 上线数月后裁判悄悄变差 | 供应商升级模型、rubric 改动 | 定期在固定黄金集重算 Kappa | 把 Kappa 检查放进 CI | 封闭裁判漂移风险低 |
| 答案对但过程危险却判通过 | 只评结果、未评轨迹 | 回放「先退款后查政策」 | 加顺序约束断言进 CI | 无先后依赖任务不设顺序 |
| 合理并行路径被误判失败 | 对无依赖子任务强求顺序 | 打乱可并行工具顺序 | 集合匹配 in-any-order | 有强安全序任务仍需顺序 |
| 随机切分仍泄漏 | 同源样本被切到两侧 | 按样本 id 随机切看同事件是否分家 | 按 event_id 哈希整组切分 | 样本确实独立时随机切可用 |
| 时序任务离线好上线亏钱 | 时间泄漏:用未来信息评过去 | 检查样本是否含决策后信息 | 按时间点严格切分 | 无时序依赖任务不涉及 |
| 涨 3 个点就上线后回落 | 未做显著性检验、样本量不足 | 小样本重复实验看波动 | 双比例 z 检验 + 最小样本量 | 差距悬殊时较稳 |
| A/B 反复偷看一显著就停 | 序贯检验假阳性 | 每小时看一次见显著就停 | 预设样本量或用序贯检验方法 | 一次性固定样本实验不涉及 |
| 影子版真扣了款 | 有副作用工具未 mock | 影子版直接调真实支付 | 副作用工具在影子环境 mock | 纯只读工具影子执行安全 |
| 模型升级评估分虚假变好 | 评估集被新模型训练数据污染 | 比对评估集 hash 与已知公开数据 | 版本化 + 污染检查 + 私有样本 | 全新能力确有提升属真改善 |
| 评估集只覆盖合作型用户 | persona 单一、缺对抗样本 | 统计 persona 分布看失衡 | 主动补对抗/边界试探 persona | 业务确实单一用户群时另说 |
| 分数聚堆在 4-5 分区分不出 | 直接取整数分、无锚点 | 统计分数直方图 | G-Eval 概率加权 + rubric 锚点 | 二分类通过/不通过任务无需 |
| 越权但礼貌的回复拿高分 | 未设红线一票否决 | 造「无条件退款」样本 | 合规维度一票否决 | 无合规风险任务另设 |
| 全自动评估、无人工兜底 | 迷信裁判、无漂移报警 | 裁判悄悄漂移无人察觉 | 固定比例人工抽检当报警器 | 极低风险场景可放宽 |

TTL（Time To Live，生存时间）适用于可过期的缓存与偏好，不应用于删除法律保留或未完成事务。PII（Personally Identifiable Information，个人可识别信息）在写入评估日志与追踪前应最小化与脱敏——评估集里混入真实用户隐私是常被忽视的合规风险。

## 最小可运行演示：评估体系体检器

把上面的诊断顺序固化成一个规则树，输入一组评估体系的健康指标，输出首要风险层，避免「离线好线上崩」时抓瞎。
```python
"""教学参考实现:评估体系体检器(纯 Python),把「离线好线上崩」拆到可行动的层。"""
from __future__ import annotations


def audit(m: dict) -> list:
    findings = []
    if m["judge_kappa"] < 0.6:
        findings.append(f"裁判层:Kappa={m['judge_kappa']}<0.6,裁判不可信,先校准或换模型")
    if m["length_corr"] > 0.3:
        findings.append(f"偏差层:裁判分与长度相关={m['length_corr']},疑似长度偏差,需去偏")
    if m["evalset_used_for_tuning"]:
        findings.append("数据层:评估集被用于调优(优化泄漏),锁死 held-out")
    if m["train_eval_hash_overlap"] > 0:
        findings.append(f"数据层:评估集与训练集 hash 重叠 {m['train_eval_hash_overlap']} 条,剔除或换私有样本")
    if m["adversarial_persona_ratio"] < 0.1:
        findings.append("覆盖层:对抗型 persona 占比过低,评估集测不出最要命的失败")
    if not m["trajectory_evaluated"]:
        findings.append("轨迹层:只评结果未评轨迹,危险顺序无法在离线拦下")
    if not m["online_ab_significance"]:
        findings.append("在线层:A/B 未做显著性检验,涨的点可能只是噪声")
    return findings or ["评估体系健康:各层指标达标,保留人工抽检当漂移报警器"]


def run() -> None:
    metrics = {
        "judge_kappa": 0.52,
        "length_corr": 0.64,
        "evalset_used_for_tuning": True,
        "train_eval_hash_overlap": 3,
        "adversarial_persona_ratio": 0.05,
        "trajectory_evaluated": False,
        "online_ab_significance": False,
    }
    for line in audit(metrics):
        print(line)


if __name__ == "__main__":
    run()
```
保存为 `demo09_audit.py`，运行 `python demo09_audit.py`。完整预期输出：
```text
裁判层:Kappa=0.52<0.6,裁判不可信,先校准或换模型
偏差层:裁判分与长度相关=0.64,疑似长度偏差,需去偏
数据层:评估集被用于调优(优化泄漏),锁死 held-out
数据层:评估集与训练集 hash 重叠 3 条,剔除或换私有样本
覆盖层:对抗型 persona 占比过低,评估集测不出最要命的失败
轨迹层:只评结果未评轨迹,危险顺序无法在离线拦下
在线层:A/B 未做显著性检验,涨的点可能只是噪声
```
七条全中——这恰好是开头那套「离线 95、线上 71」的评估体系的完整病历：裁判没校准、有长度偏差、评估集泄漏且被污染、覆盖不到对抗用户、没评轨迹、上线没做显著性。这个规则树只用于**缩小范围、排出优先级**，不替代具体归因：它告诉你先看哪一层，真正的修复仍要回到每一节的方法。

## 真实系统对应

**官方公开机制**：LangSmith 提供离线/在线评估、LLM 裁判评估器、成对评估（含 `randomize_order`）、与人工标注对照的能力 [来源](https://docs.smith.langchain.com/evaluation/concepts) [来源](https://docs.smith.langchain.com/evaluation/how_to_guides/evaluate_pairwise)；G-Eval 公开了思维链评分与人工相关性校准的方法 [来源](https://www.confident-ai.com/blog/g-eval-the-definitive-guide)；Anthropic 主张把评估放进开发闭环、保持简单与透明 [来源](https://www.anthropic.com/engineering/building-effective-agents)。**通用工程模式**：分层体检、症状矩阵、把校准与显著性放进流程，是可迁移到任何平台的排障框架。**教学参考实现**：上面的体检器阈值（Kappa 0.6、长度相关 0.3、对抗占比 0.1）是教学示例，需按业务风险实测校准，不是普适常数。

## 思考：面试官问「你怎么知道你的评估本身是对的?」该怎么答?

### 回答

这是评估进阶最核心的一道题，答案要落在「评估体系能自证可信」这个点上，分四层展开。第一层校准裁判：裁判是把秤，上线前必须用人工黄金集算 Cohen's Kappa，因为一致率在类别失衡时会虚高（九成通过时无脑全判通过也能拿 0.9），Kappa 扣除瞎猜蒙对后才诚实，0.6 以上可用、0.8 以上可放量，且要放进 CI 防漂移。第二层去偏：裁判有位置、长度、自我偏好三种系统性偏差，它们无法靠多采样平均掉，必须分别用双向取一致、长度声明加惩罚、异族裁判专门校准，而且长度偏差要先量化相关性证明确实有偏。第三层防泄漏与污染：评估集要防优化/切分/时间三种泄漏，用 event_id 哈希整组切、按时间切、held-out 锁死，还要用版本加内容 hash 做污染追踪，识破「模型升级导致评估分虚假变好」。第四层轨迹加在线：不能只评结果，要用工具选择/参数/顺序/步数四维断言评轨迹，把危险顺序在离线拦下；离线到线上要有影子流量、A/B（看业务指标显著性、别偷看）、灰度这几层过渡带。收尾时用「离线 95、线上 71」这个具体落差把四层串起来——每一层不做，都会贡献那 24 个百分点里的一块。能答到「评估要能证明它自己可信」这个层次，而不只是「我用了 LLM 裁判」，就是这道题的满分答案。

### 面试精简表达

评估要能自证可信:裁判用 Kappa 校准并放进 CI、三大系统偏差专门去偏、评估集防三种泄漏加污染追踪、结果之外评轨迹、离线到线上走影子/A/B/灰度过渡带。用一个真实落差把四层串起来。

## 思考：自动评估和人工评估该怎么分工?能全自动吗?

### 回答

不能全自动，正确姿势是三者组成金字塔、便宜的在下面挡大多数、贵的在上面守关键。最底层是规则评估：处理确定性判定，如结构化字段、轨迹的工具/参数/顺序约束、红线，最便宜、跑在最前面当快检。中间层是 LLM 裁判：处理规则搞不定的开放输出，如回答质量的 rubric 打分、版本 PK 的成对比较，规模化但有偏差，所以要定期用人工黄金集校准。最顶层是人工：最贵最准，只聚焦两件自动化干不了的事——校准裁判（给黄金标签算 Kappa）和审边界案例（模型和裁判都吃不准的疑难样本）。一个高效闭环是主动学习：裁判给全部样本打分，挑低置信度（接近通过线或双向不一致）样本转人工，人工结果回流成校准集反哺裁判。为什么不能全自动？因为哪怕裁判 Kappa 到 0.85，供应商升级、rubric 改动都可能让它悄悄漂移，而漂移是静默的——所以必须留一条固定比例的人工抽检通道（如每天随机抽 1% 线上对话复核），它不为覆盖，而是裁判漂移时的报警器。能说清「金字塔分工 + 主动学习闭环 + 人工抽检当报警器」，就说明你理解评估是个需要持续治理的系统，而非一次性的跑分。

### 面试精简表达

不能全自动:规则(结构/轨迹/红线,最便宜打底)→LLM 裁判(开放输出,规模化但需校准)→人工(校准裁判算 Kappa、审边界)三层金字塔;用主动学习把低置信样本转人工回流;永远留固定比例人工抽检当漂移报警器。

## 思考：本章和第 16 章「评估基础」到底有什么区别，进阶在哪?

### 回答

第 16 章是地基，本章是深水区，区别在于「从会用到能自证可信」。第 16 章解决「为什么必须评估、怎么起步」：结果 vs 轨迹两个维度、标准答案与 LLM 裁判的入门用法、评估集从失败中生长。它让你能搭起一个能跑的评估。但它刻意回避了几个会在生产里翻车的问题，正是本章的进阶点：其一，第 16 章说「裁判有偏差」但没展开，本章把位置/长度/自我偏好三种系统性偏差讲透并给出可量化的去偏；其二，第 16 章教你用裁判，本章教你先证明裁判可信——用 Cohen's Kappa 校准、放进 CI 防漂移；其三，第 16 章提了「泄题」，本章挖到优化/切分/时间三种泄漏形态加污染追踪；其四，第 16 章的评估停在离线，本章补上影子流量、A/B 显著性、灰度这条离线到线上的完整管线；其五，本章把轨迹评估细化到工具/参数/顺序/步数四维可断言，并补上成对比较汇总胜率、G-Eval 概率加权、合成评估集这些第 16 章没有的具体方法。一句话概括：第 16 章让你「能评」，本章让你「评得准、还能证明自己评得准」。这也是面试从初级到高级的分水岭——初级问「你怎么评估」，高级问「你怎么知道你的评估是对的」。

### 面试精简表达

第 16 章是地基(为什么评、结果 vs 轨迹、裁判入门、评估集生长),本章是深水区(三大偏差去偏、Kappa 校准防漂移、三种泄漏+污染追踪、离线到线上管线、轨迹四维+成对+G-Eval+合成集)。前者让你能评,后者让你评得准并能自证可信。
