## 真实问题

「离线 95、线上 71」复盘到最后，团队问了一个此前从没问过的问题：**我们凭什么相信这个裁判？** 没人算过它和人类判断到底有多一致。有人说「一致率应该挺高吧，我们抽看过几条，感觉差不多」——这句「感觉差不多」正是问题所在。团队补做了一次实验：拿 100 条有人工黄金标签的样本让裁判去判，一致率算出来 0.90，看着很高。可细看数据发现，这 100 条里有 90 条人工标的是「通过」——裁判只要**无脑全判通过**，一致率照样 0.90，实则毫无鉴别力。

这就是本节要解决的问题：**用一个能扣除「瞎猜也能蒙对」的指标，量化裁判到底有多可信**。裁判是一把秤，上线前必须先过检——而 Cohen's Kappa（科恩卡帕系数）就是那台校秤的标准砝码。

## 原理：一致率的陷阱与 Cohen's Kappa 的修正

最直观的指标是**与人类的一致率**（agreement rate）：裁判和人工标签相同的比例。它的致命缺陷在类别失衡时暴露无遗：如果 90% 样本都是「通过」，裁判无脑全答「通过」也能拿 0.90，看着很高，其实没本事。

**Cohen's Kappa** 修正了这一点。它的公式是 `κ = (p_o - p_e) / (1 - p_e)`，其中 `p_o` 是实际一致率、`p_e` 是「两边按各自类别分布瞎猜时会碰巧一致的比例」。直觉是：**先算出「就算瞎猜也能蒙对多少」，再看裁判比瞎猜好出多少**。经验阈值 [来源](https://www.confident-ai.com/blog/g-eval-the-definitive-guide)：

- **κ ≥ 0.8**：强一致，可直接放量使用。
- **0.6 ≤ κ < 0.8**：可用，但需持续监控漂移。
- **0.4 ≤ κ < 0.6**：勉强，需回去改 rubric 或换裁判模型。
- **κ < 0.4**：裁判基本在乱评，禁止上线。

关键洞察：在开头那个「一致率 0.90 但无脑全判通过」的例子里，`p_e` 会非常接近 `p_o`（因为裁判和人工都几乎全是「通过」，瞎猜也能蒙对九成），于是 `κ` 会掉到接近 0——**Kappa 一眼揭穿了一致率的虚高**。

## 最小可运行演示：一致率 + Kappa + 阈值判读

下面这段代码同时算一致率和 Kappa，并给出可操作的判读结论，用「类别均衡」和「类别失衡+无脑全判」两个场景对比，看 Kappa 如何揭穿一致率的谎言。
```python
"""教学参考实现:裁判校准——一致率 + Cohen's Kappa + 阈值判读。"""
from __future__ import annotations


def agreement_rate(judge: list, human: list) -> float:
    assert len(judge) == len(human)
    same = sum(j == h for j, h in zip(judge, human))
    return round(same / len(judge), 3)


def cohen_kappa(judge: list, human: list, classes=("good", "bad")) -> float:
    n = len(judge)
    po = sum(j == h for j, h in zip(judge, human)) / n   # 实际一致率
    pe = 0.0                                             # 随机一致率
    for c in classes:
        pj = sum(x == c for x in judge) / n
        ph = sum(x == c for x in human) / n
        pe += pj * ph
    return round((po - pe) / (1 - pe), 3) if pe != 1 else 1.0


def verdict(kappa: float) -> str:
    if kappa >= 0.8:
        return "强一致,可直接放量使用"
    if kappa >= 0.6:
        return "可用,但需持续监控漂移"
    if kappa >= 0.4:
        return "勉强,需改 rubric 或换裁判模型"
    return "基本在乱评,禁止上线"


def run() -> None:
    # 场景一:类别均衡,一致率与 Kappa 都诚实
    judge = ["good", "bad", "good", "good", "bad", "bad", "good", "bad"]
    human = ["good", "bad", "bad", "good", "bad", "bad", "good", "good"]
    k1 = cohen_kappa(judge, human)
    print(f"[均衡] 一致率={agreement_rate(judge, human)} Kappa={k1} -> {verdict(k1)}")

    # 场景二:类别极不均衡(9 成 good),裁判无脑全 good
    human2 = ["good"] * 9 + ["bad"]
    judge2 = ["good"] * 10
    k2 = cohen_kappa(judge2, human2)
    print(f"[失衡] 一致率={agreement_rate(judge2, human2)} Kappa={k2} -> {verdict(k2)}")


if __name__ == "__main__":
    run()
```
保存为 `demo05_kappa.py`，运行 `python demo05_kappa.py`。完整预期输出：
```text
[均衡] 一致率=0.75 Kappa=0.5 -> 勉强,需改 rubric 或换裁判模型
[失衡] 一致率=0.9 Kappa=0.0 -> 基本在乱评,禁止上线
```
这两行的对比是本节的高潮：`[失衡]` 场景一致率高达 0.9、看着比 `[均衡]` 的 0.75 好得多，但 Kappa 是 **0.0**——裁判无脑全判 good，扣除「瞎猜蒙对」后没有任何鉴别力，判读结论直接是「禁止上线」。而 `[均衡]` 场景一致率虽只有 0.75，Kappa 却有 0.5，比失衡场景**实际上更可信**。**如果只看一致率，你会选错裁判、放行一台坏秤。** 这就是为什么裁判校准必须用 Kappa 而非一致率。

## 校准不是一次性的：把它放进 CI

裁判校准最容易被忽视的一点是：**它会漂移**。换裁判模型、改 rubric、甚至供应商悄悄升级了模型版本，都可能让 Kappa 掉下去。稳妥做法是把「裁判 vs 人工黄金集」的一致性检查也放进持续集成（Continuous Integration，CI），像监控业务指标一样监控你的裁判——裁判漂移了你却不知道，等于仪表盘坏了还在照着开。一个高效闭环是：裁判给全部样本打分 → 挑**低置信度**（接近通过线、或双向不一致）样本转人工 → 人工结果回流成校准集 → 反哺裁判并重算 Kappa。这正是**主动学习（active learning）**：把宝贵的人力花在信息量最大的样本上。

## 真实系统对应

**官方公开机制**：G-Eval 相关文档明确把「与人工标注的相关性/一致性」作为衡量裁判可信度的核心方式，并讨论用统计指标校准 [来源](https://www.confident-ai.com/blog/g-eval-the-definitive-guide)。LangSmith 支持把评估器结果与人工标注（annotation queues、人工反馈）对照，用于校准与监控 [来源](https://docs.smith.langchain.com/evaluation/concepts)。Anthropic 在工具开发方法里也强调用真实数据构建评估集、让人工与自动评估协同 [来源](https://www.anthropic.com/engineering/writing-tools-for-agents)。**通用工程模式**：用一致率 + Cohen's Kappa 量化裁判可信度、设阈值、放进 CI 监控漂移，是可迁移到任何裁判实现的做法。**教学参考实现**：上面的阈值（0.4/0.6/0.8）是学界与业界常用经验值，但具体该卡多高取决于任务风险；高风险场景（医疗、金融）应要求更高的 Kappa，低风险场景可适当放宽。

一个边界：Cohen's Kappa 适用于两名评判者、分类标签的场景。若是多名标注者，应改用 Fleiss' Kappa；若是有序/连续分数，应改用加权 Kappa 或相关系数（如 Spearman）。选错统计量会得到误导性的可信度。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 一致率 0.9 却选到坏裁判 | 只看一致率、忽略类别失衡 | 造 9 成同类样本让裁判无脑全判 | 一律用 Cohen's Kappa 判读 | 类别本就均衡时一致率也够用 |
| 上线三个月后裁判悄悄变差 | 供应商升级模型、rubric 改动 | 定期在固定黄金集重算 Kappa | 把 Kappa 检查放进 CI 持续监控 | 从不改动的封闭裁判漂移风险低 |
| 多标注者用 Cohen's Kappa 得怪值 | 统计量选错(只支持两评判者) | 三人标注硬套 Cohen's | 多标注者改 Fleiss' Kappa | 恰好两名评判者时适用 |
| 有序分数硬套二分类 Kappa | 忽略「差1分」和「差4分」不同 | 把 1-5 分强转 good/bad | 用加权 Kappa 或 Spearman 相关 | 本就是二分类判定时适用 |
| 黄金集太小、Kappa 抖动大 | 校准样本量不足 | 用 10 条样本反复算看波动 | 扩大黄金集、给 Kappa 置信区间 | 快速冒烟检查可容忍小样本 |

## 思考：为什么裁判「先校准再用」是铁律?一致率高就够了吗?

### 回答

不够，而且只看一致率会让你放行一台坏秤。裁判本质是一把用来量回答质量的秤，一把没校准的秤，读数越精确越危险——你会拿着虚高的评估分做上线、做微调、做展示，而它和真实质量根本不对齐，这正是「离线 95、线上 71」落差的核心成因之一。校准的正确指标是 Cohen's Kappa 而非一致率：一致率在类别失衡时会严重虚高，比如九成样本是「通过」，裁判无脑全判「通过」就能拿 0.9 的一致率，但它毫无鉴别力；Kappa 通过先扣除「瞎猜也能蒙对」的比例 `p_e`，再看裁判比瞎猜好多少，能一眼揭穿这种虚高——同样这个例子 Kappa 会掉到接近 0，直接判「禁止上线」。经验阈值是 0.8 以上强一致可放量、0.6 到 0.8 可用但需监控、0.4 到 0.6 得改 rubric 或换模型、0.4 以下禁止上线；高风险场景要求更高。而且校准不是一次性的：换模型、改 rubric、供应商升级都会让 Kappa 漂移，所以要把 Kappa 检查放进 CI，像监控业务指标一样监控裁判。能说清「一致率会虚高、Kappa 才诚实、还要放进 CI 防漂移」，就是这道高频面试题的满分答案。

### 面试精简表达

裁判是把秤,没校准的秤读数越精确越危险。用 Cohen's Kappa 而非一致率:一致率在类别失衡时虚高(全判通过也能 0.9),Kappa 扣掉瞎猜蒙对后能揭穿它;阈值 0.6 可用、0.8 可放量;还要放进 CI 防漂移。
