> 对应故障板指标：**幻觉率 6.1% → ≤ 1.0%**。这是原书**场景 1「你的 Agent 上线后经常胡说八道，怎么排查和解决」**的加深版。

## 真实问题

小蜜上线第 14 天，运营抽查了 500 条对话，标出 6.1% 的回答「无依据硬答」。最扎眼的一条：用户问「3C 产品过了 7 天还能退吗」，小蜜答「可以，我们支持 30 天无理由退货」——可知识库里白纸黑字写的是「3C 类目 7 天无理由，超过需符合三包」，根本没有 30 天这一说。用户拿着这句截图要求退货，客服团队被迫兑现，直接造成损失。

复盘会上，产品第一反应是「加个 Prompt 让它别瞎说不就行了？」——这正是最典型的新手答案。真相是：这条幻觉的根因根本不在 Prompt 层，而在**检索层压根没召回到那篇 3C 政策文档**，模型在「没有资料」的情况下凭训练知识编了一个数。不定位就加 Prompt，改了也没用。这一节要把幻觉拆成可定位的四层，逐层给药。

## 原理：幻觉不是一种病，而是四层里任意一层的失效

「幻觉」是个笼统的现象词。把它拆开，会发现它可能发生在检索增强生成（Retrieval-Augmented Generation，RAG）链路的任意一层，每一层的药方完全不同：
```text
用户提问
   │
   ▼
① 检索层：有没有召回到相关资料？
   │  失效表现：Trace 里命中的文档跟问题无关，或根本没命中
   │  → 模型「无米下锅」，只能靠训练知识编 → 幻觉
   ▼
② 融合层：召回了，但模型用了吗、用对了吗？
   │  失效表现：资料里明明有答案，模型却答错/曲解
   │  → 无关上下文干扰、或模型没「基于资料」回答
   ▼
③ Prompt 层：有没有约束「无依据不作答」？
   │  失效表现：没资料时也硬编一个答案，而不是说「未找到」
   │  → 缺「拒答」指令和拒答示例
   ▼
④ 输出层：结论能不能溯源？
      失效表现：给了结论但没有任何引用，无法核验
      → 缺引用护栏，无来源的结论没被拦截或标注
```
关键洞察：**同样是「胡说八道」，检索层失效要去优化召回，Prompt 层失效要去加拒答约束，两者的修法南辕北辙**。所以第一步永远是用 Trace 定位到底哪一层先偏离，而不是笼统地「加 Prompt」。Anthropic 的降低幻觉官方指南把「让模型只依据提供的上下文作答、允许它说不知道、并让每个结论都能引用来源核验」列为核心手段，正对应这里的融合层、Prompt 层与输出层 [来源](https://docs.anthropic.com/en/docs/minimizing-hallucinations)。

## 现象与输入：一条幻觉的分层归因

拿故障板上那条「30 天」幻觉做归因。Trace 里能看到三个关键字段：`retrieved_docs`（本轮召回的文档 ID）、`grounded`（回答是否基于召回内容）、`citations`（输出是否带引用）。这条幻觉的 Trace 长这样：
```text
question: 3C 产品过了 7 天还能退吗
retrieved_docs: [KB-RETURN-GENERAL]          ## 只召回了总则，没召回 3C 专项
grounded: false                               ## 模型没有基于召回内容
citations: []                                 ## 输出无任何引用
answer: 可以，我们支持 30 天无理由退货         ## 凭空编造
```
一眼定位：`retrieved_docs` 缺了 `KB-RETURN-3C`（检索层失效在前），`grounded=false` + `citations=[]`（输出层也没兜住）。这就是分层排查的价值——它把「小蜜又乱说了」这句抱怨，变成了「检索层漏召 + 输出层无护栏」两个可独立修复的工程问题。

## 最小可运行演示

下面用一段纯 Python 的 mock 演示「四层排查器」：给它一条回答的四层信号，它告诉你幻觉最先发生在哪一层、该怎么修。它不调用任何真实检索或模型，用确定性数据讲清定位逻辑。
```python
"""第24.2节：幻觉四层排查器（纯 Python，无需 API Key）。"""
from dataclasses import dataclass


@dataclass
class TurnSignals:
    question: str
    gold_doc: str            ## 该问题的正确证据文档
    retrieved: list          ## 实际召回的文档
    grounded: bool           ## 模型是否基于召回内容作答
    has_citation: bool       ## 输出是否带引用
    refused_when_empty: bool ## 无资料时是否触发拒答


def locate_hallucination(s: TurnSignals) -> str:
    ## 按四层顺序定位「最先偏离」的那一层
    if s.gold_doc not in s.retrieved:
        return "① 检索层：漏召正确文档 → 扩召回/优化 chunk/加 rerank"
    if not s.grounded:
        return "② 融合层：召回了却没用 → Prompt 强制'基于以下资料回答'、减无关上下文"
    if not s.retrieved and not s.refused_when_empty:
        return "③ Prompt 层：无资料仍硬答 → 加'找不到就说未找到'与拒答示例"
    if not s.has_citation:
        return "④ 输出层：结论不可溯源 → 要求附引用，无来源则拦截/标注待核实"
    return "四层均通过：本轮回答可溯源、有依据"


def run() -> None:
    cases = [
        TurnSignals("3C 过 7 天能退吗", "KB-RETURN-3C",
                    ["KB-RETURN-GENERAL"], False, False, True),
        TurnSignals("七天无理由怎么退", "KB-REFUND-FLOW",
                    ["KB-REFUND-FLOW"], True, False, True),
        TurnSignals("你们 CEO 是谁", "NONE",
                    [], False, False, False),
        TurnSignals("退款多久到账", "KB-REFUND-FLOW",
                    ["KB-REFUND-FLOW"], True, True, True),
    ]
    for c in cases:
        print(f"[{c.question}] -> {locate_hallucination(c)}")


if __name__ == "__main__":
    run()
```
保存为 `s2_halluc.py`，运行 `python s2_halluc.py`。完整预期输出：
```text
[3C 过 7 天能退吗] -> ① 检索层：漏召正确文档 → 扩召回/优化 chunk/加 rerank
[七天无理由怎么退] -> ④ 输出层：结论不可溯源 → 要求附引用，无来源则拦截/标注待核实
[退款多久到账] -> 四层均通过：本轮回答可溯源、有依据
[你们 CEO 是谁] -> ③ Prompt 层：无资料仍硬答 → 加'找不到就说未找到'与拒答示例
```
四条样例正好覆盖三种不同根因：第一条是检索层漏召（最常见），第二条是召回和依据都对但没带引用（输出层），第三条是无资料却硬答（Prompt 层缺拒答），最后一条四层全过。同样是「答错」，排查器把它们分到了三个不同的修复入口——这就是「分层排查」相对「一律加 Prompt」的价值。

## 真实系统对应

**官方公开机制**：Anthropic 在《Reduce hallucinations》里给出的手段与这里四层高度对应——「只依据提供的上下文作答」（融合层）、「允许说 I don't know」（Prompt 层拒答）、「用引用让回答可审计，找不到支持引用就撤回该结论」（输出层溯源）[来源](https://docs.anthropic.com/en/docs/minimizing-hallucinations)。更进一步，Anthropic 的 Citations（引用）能力把「输出带引用」从「靠 Prompt 央求模型」升级为「API 层保证的结构化引用对象」，官方称其内部评估显示内建引用的召回准确率比自定义实现最多高约 15%，且返回字符级偏移、文档索引与来源摘录 [来源](https://www.anthropic.com/news/introducing-citations-api)。**通用工程模式**：四层分层排查、把失败样本收进评估集做回归，可迁移到任何 RAG 系统。**教学参考实现**：上面的 `locate_hallucination` 用确定性布尔信号模拟四层判定，真实系统里这些信号来自检索评分、grounded 分类器或 LLM-as-a-judge（Large Language Model as a Judge，用大模型当裁判）；不代表任何产品的内部实现。**边界**：Citations 的具体字段、支持的文档类型与计费以当前官方文档为准。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 无资料时凭空编数字 | Prompt 缺拒答约束 | 问一个知识库没有的问题看是否硬答 | 加「找不到就说未找到」+ 拒答 few-shot（少样本示例） | 闲聊型场景允许通用回答 |
| 召回对了模型仍答错 | 无关上下文干扰融合 | 对比只喂 gold 文档 vs 喂全量召回 | 精简召回、Prompt 强制「基于以下资料」 | 证据本身自相矛盾时 |
| 检索漏召导致硬答 | chunk 切分或 embedding 差 | 看 Trace 里 retrieved_docs 是否含 gold | 优化切块、加 rerank（重排）、扩召回 top-k | 知识库确实没有该信息 |
| 结论无法核验 | 输出层无引用护栏 | 抽查回答有无 citation 字段 | 用 Citations 或强制附来源，无源拦截 | 纯创意生成不需溯源 |
| 引用了但引用是编的 | 引用与结论不匹配 | 校验引用文本是否真含该结论 | 引用忠实性校验（claim↔source 比对） | 引用作装饰、不承诺忠实时 |
| 改好 A 又冒出 B | 无回归防线 | 改动后只测新样本不测老样本 | 幻觉样本全进评估集，每次跑回归 | 一次性 demo 不需回归 |
| 幻觉率忽高忽低说不清 | 无量化基线 | 只靠人眼抽查不统计 | 用固定评估集算幻觉率，盯趋势 | 无评估集的早期原型 |

> **加分对照·幻觉排查的红旗 vs 加分**：

| 维度 | 红旗回答 ❌ | 加分回答 ✅ |
|---|---|---|
| 排查方式 | 「加个 Prompt 让它别瞎说」 | 分检索/融合/Prompt/输出四层逐层排查 |
| 定位依据 | 凭感觉猜哪里错 | 看 Trace 里实际 retrieved_docs 和 grounded 标记 |
| 溯源 | 不提引用 | 输出附引用，无依据拦截或标注待核实 |
| 闭环 | 改完就完事 | 把幻觉样本收进评估集，跑回归防复发 |
| 深度 | 只说「模型会幻觉」 | 能说清检索漏召和 Prompt 缺拒答是两种病 |

## 思考：为什么「加个 Prompt 让它别瞎说」在很多幻觉场景里根本没用？

### 回答

因为这句话默认了幻觉的根因在 Prompt 层，但实际最高频的根因在检索层——**模型没有召回到相关资料，是在「无米下锅」的情况下用训练知识硬编的**。这种情况下，你把 Prompt 改成「请不要编造」十遍也没用，因为模型手里压根没有那篇 3C 政策文档，它「不知道自己不知道」。举个具体的：故障板那条「30 天」幻觉，Trace 显示 `retrieved_docs` 只有总则、缺了 3C 专项，`grounded=false`。真正的修法是去优化召回（改 chunk 切分、加 rerank、扩 top-k），让那篇 3C 文档能被检索到；召回对了，再配 Prompt 层「基于以下资料回答、无依据就说未找到」和输出层「附引用、无源拦截」双保险。所以「加个 Prompt」之所以常常没用，是因为它只对「资料召回对了但模型没约束」这一种情况有效，而对「资料压根没召回」这种最常见的情况完全无能为力。能说清「幻觉不是一种病，而是四层里任意一层的失效，检索漏召和 Prompt 缺拒答的修法完全不同」，就说明你真正排查过幻觉，而不是背了个万能咒。

### 面试精简表达

「加 Prompt」只对「召回对了但没约束」有效；而最常见的幻觉根因是检索层压根没召回，模型无米下锅硬编——这时只能去优化召回，改 Prompt 无济于事。所以要先用 Trace 看 retrieved_docs 定位到底哪层失效，再对症下药。

## 深入：优化前后对比与「用数据说话」的闭环

优化前，小蜜对幻觉的处理是「事后靠客服兜」——出一条赔一条，幻觉率 6.1% 且无从下降，因为根本没有量化基线，改动全凭感觉。优化后，按四层依次落地：检索层把召回 top-k 从 3 提到 8 并加 rerank，让 3C 文档能进候选；融合层在 Prompt 里显式写「只依据【资料】区块回答」；Prompt 层补拒答示例；输出层接入引用护栏，无来源的结论标注「待核实」不直接放行。每落地一层，都把当时的 60 条幻觉样本跑一遍评估集，观察幻觉率的下降曲线：检索层修复后从 6.1% 降到 2.4%（说明近六成幻觉来自漏召），加拒答后降到 1.3%，加引用护栏后降到 0.7%，达标。

这条曲线本身就是最好的面试素材：它证明你**不是笼统地「优化了一下」，而是能量化每一层各贡献了多少改善**。而这只有在「有评估集 + 每步单独验证」的前提下才可能——这也是为什么本章反复强调，幻觉治理的终点不是「感觉不说胡话了」，而是「幻觉率在固定评估集上稳定低于阈值，且新样本持续回流进评估集防复发」。把幻觉样本沉淀成回归资产的做法，会在第 5 节「评估从零构建」里进一步展开。
