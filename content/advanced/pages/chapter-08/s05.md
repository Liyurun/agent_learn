## 真实问题

前四节把生命周期、协议、并行、流式分别拆开讲清了，但面试官真正想看的是：你能不能把它们组装成一个**能自我纠错、能防死循环、能拒绝非法参数**的完整闭环，并且让人一眼看懂运行轨迹。“少减五元”故障之所以拖了半天，根因之一就是团队手里从来没有一个可复现、可打印每一步的参照实现——出了问题只能对着零散日志猜。

这一节给出一个完全离线、无需 API（Application Programming Interface，应用程序编程接口）Key、纯 Python 的多轮工具调用协议状态机。它把前四节的机制固化成四个可测试的部件：工具注册与 JSON（JavaScript Object Notation）Schema 轻量校验、带五道关口的安全执行器、确定性“假模型”、带轮次上限的主循环。跑起来你会看到模型伪造了一个越界枚举参数、被校验层挡下、收到结构化错误后自我纠错、最终自然终止的全过程。

## 工程边界

这份代码是**教学参考实现**：`ScriptedModel` 是确定性假模型，用来让输出可逐字复核，不代表任何厂商的推理逻辑；`ToolRegistry.validate` 是最小 Schema 校验器，只覆盖必填、类型、枚举，真实生产应换成成熟的 JSON Schema 校验库（如 `jsonschema`），本文为“无需第三方依赖即可运行”而手写。消息结构统一采用 Anthropic 风格的 `tool_use` / `tool_result` 块（**通用工程模式**），接 OpenAI 时只需在第 2 节的归一化层做一次转换即可，主循环骨架一行不改。

## 状态机的四个状态与转移

把主循环抽象成一个只有四个状态的有限状态机，是理解 Function Calling 端到端的关键。任何一次多轮工具调用，都是这四个状态之间的转移：
```text
        ┌─────────────┐  用户消息   ┌──────────────┐
        │   START     │──────────▶ │  CALL_MODEL  │ 向模型发起（重发完整历史）
        └─────────────┘            └──────┬───────┘
                                          │ 收到 assistant 响应
                                 ┌────────▼─────────┐
                                 │ 含 tool_use 块？ │
                                 └───┬──────────┬───┘
                              有 │            │ 无（纯文本）
                                 ▼            ▼
                          ┌───────────┐  ┌──────────┐
                          │  EXECUTE  │  │  FINISH  │ 返回最终答案
                          └─────┬─────┘  └──────────┘
                                │ 回填 tool_result（带 id）
                                └────────▶ 回到 CALL_MODEL（轮次+1）
                                          触顶 max_turns 则强制降级 FINISH
```
- **START**：装入用户消息，初始化空历史。
- **CALL_MODEL**：把**完整历史**重新发给无状态模型（第 1 节铁律二）。
- **EXECUTE**：模型返回了 `tool_use`，逐个过安全执行器，按 `id` 回填 `tool_result`（第 1、3 节）。
- **FINISH**：模型返回纯文本（自然终止），或触顶 `max_turns`（强制降级），两条路径都收敛到这里。

FINISH 有两个入口——自然终止与轮次触顶——是这份实现最容易被面试追问的点：**只有自然终止不够，必须有轮次上限兜底**，否则模型换着关键词无限重试会把预算烧光。

## 安全执行器的五道关口

`SafeExecutor.execute` 是“模型不可信”这条铁律的落地。模型给的 `name` 和 `input` 都当成不可信输入，依次过五道关口，任一关口不过就转成带 `is_error=True` 的结构化结果回传，而不是抛异常崩溃：

| 关口 | 检查什么 | 不过时的动作 | 对应第 1 节阶段 |
|---|---|---|---|
| ① 存在性 | 工具名是否已注册 | 回传“未知工具 + 可用列表” | 阶段③校验 |
| ② 参数校验 | 必填/类型/枚举是否合 Schema | 回传“参数非法 + 原因” | 阶段③校验 |
| ③ 危险动作 | 有副作用工具是否已获批 | 回传“需人工审核，已拒绝” | 阶段③权限 |
| ④ 执行 | 真正调用函数 | —— | 阶段③执行 |
| ⑤ 异常兜底 | 执行抛异常 | 回传“执行失败 + 异常类型” | 阶段③异常 |

关口②是“少减五元”故障里缺失的那一环：模型把 `rule_version` 写成不存在的 `v0`，如果没有校验就会放行。下面这份实现里，模型故意伪造了 `unit="k"`（越界枚举），你会看到它被关口②精确拦下。

## 完整可运行实现

下面是完整的状态机实现，一个文件即可运行，不联网、不需要任何密钥与第三方库。
```python
"""端到端实现实战：Function Calling 多轮协议状态机（纯 Python，无需 API Key）。"""
from __future__ import annotations
from dataclasses import dataclass, field


## ---------- 1. 工具注册与轻量 Schema 校验 ----------
class ToolRegistry:
    def __init__(self) -> None:
        self._tools: dict[str, dict] = {}

    def register(self, name: str, schema: dict, fn, dangerous: bool = False) -> None:
        self._tools[name] = {"schema": schema, "fn": fn, "dangerous": dangerous}

    def __contains__(self, name: str) -> bool:
        return name in self._tools

    def get(self, name: str) -> dict:
        return self._tools[name]

    def names(self) -> list[str]:
        return sorted(self._tools)

    @staticmethod
    def validate(args: dict, schema: dict) -> tuple[bool, str]:
        for key in schema.get("required", []):
            if key not in args:
                return False, f"缺少必填参数 {key}"
        props = schema.get("properties", {})
        for key, val in args.items():
            spec = props.get(key)
            if spec is None:
                return False, f"未知参数 {key}"
            want = spec.get("type")
            type_map = {"string": str, "integer": int, "number": (int, float),
                        "boolean": bool, "object": dict, "array": list}
            if want in type_map and not isinstance(val, type_map[want]):
                return False, f"参数 {key} 类型应为 {want}"
            if "enum" in spec and val not in spec["enum"]:
                return False, f"参数 {key} 取值须在 {spec['enum']} 内"
        return True, "ok"


## ---------- 2. 安全执行器：五道关口 ----------
def tool_result(cid: str, content: str) -> dict:
    return {"type": "tool_result", "tool_use_id": cid, "content": str(content),
            "is_error": False}


def tool_error(cid: str, msg: str) -> dict:
    return {"type": "tool_result", "tool_use_id": cid, "content": msg,
            "is_error": True}


class SafeExecutor:
    def __init__(self, registry: ToolRegistry, approved: bool = False) -> None:
        self.registry = registry
        self.approved = approved

    def execute(self, call: dict) -> dict:
        cid, name, args = call["id"], call["name"], call["input"]
        if name not in self.registry:                            # 关口1 存在性
            return tool_error(cid, f"未知工具 {name}，可用：{self.registry.names()}")
        tool = self.registry.get(name)
        ok, msg = ToolRegistry.validate(args, tool["schema"])    # 关口2 校验
        if not ok:
            return tool_error(cid, f"参数非法：{msg}")
        if tool["dangerous"] and not self.approved:              # 关口3 危险动作
            return tool_error(cid, "该操作需人工审核，已拒绝执行")
        try:
            out = tool["fn"](**args)                             # 关口4 执行
        except Exception as exc:                                 # 关口5 异常
            return tool_error(cid, f"执行失败：{type(exc).__name__}: {exc}")
        return tool_result(cid, out)


## ---------- 3. 确定性假模型 ----------
@dataclass
class ScriptedModel:
    """按脚本产出：先并行两个查询，再一个非法调用（被校验挡下），最后给文本。"""
    step: int = 0

    def create(self, messages: list[dict]) -> dict:
        self.step += 1
        if self.step == 1:
            return {"role": "assistant", "content": [
                {"type": "text", "text": "先并行查两地天气。"},
                {"type": "tool_use", "id": "c1", "name": "get_weather",
                 "input": {"city": "北京", "unit": "c"}},
                {"type": "tool_use", "id": "c2", "name": "get_weather",
                 "input": {"city": "上海", "unit": "c"}},
            ]}
        if self.step == 2:
            ## 模型"伪造"越界枚举 unit=k，会在关口2 被挡下，触发自我纠错
            return {"role": "assistant", "content": [
                {"type": "tool_use", "id": "c3", "name": "get_weather",
                 "input": {"city": "广州", "unit": "k"}},
            ]}
        if self.step == 3:
            ## 收到"参数非法"后改用合法枚举重试
            return {"role": "assistant", "content": [
                {"type": "tool_use", "id": "c4", "name": "get_weather",
                 "input": {"city": "广州", "unit": "c"}},
            ]}
        ## 信息够了，纯文本自然终止
        return {"role": "assistant", "content": [
            {"type": "text", "text": "北京晴12C；上海多云15C；广州阴20C。"}]}


## ---------- 4. 工具实现 ----------
def get_weather(city: str, unit: str = "c") -> str:
    table = {"北京": "晴12C", "上海": "多云15C", "广州": "阴20C"}
    return table.get(city, "未知城市")


WEATHER_SCHEMA = {
    "type": "object",
    "properties": {
        "city": {"type": "string"},
        "unit": {"type": "string", "enum": ["c", "f"]},
    },
    "required": ["city"],
}


## ---------- 5. 主循环状态机 ----------
@dataclass
class Runtime:
    model: ScriptedModel
    executor: SafeExecutor
    max_turns: int = 8
    trace: list[str] = field(default_factory=list)

    def run(self, user_msg: str) -> str:
        messages: list[dict] = [{"role": "user", "content": user_msg}]
        for turn in range(1, self.max_turns + 1):
            resp = self.model.create(messages)          ## CALL_MODEL：重发完整历史
            messages.append(resp)
            calls = [b for b in resp["content"] if b.get("type") == "tool_use"]
            if not calls:                               ## FINISH：自然终止
                text = next(b["text"] for b in resp["content"]
                            if b["type"] == "text")
                self.trace.append(f"T{turn} STATE=FINISH answer={text}")
                return text
            self.trace.append(                          ## EXECUTE
                f"T{turn} STATE=EXECUTE calls="
                f"{[c['name'] + '#' + c['id'] for c in calls]}")
            results = []
            for call in calls:
                r = self.executor.execute(call)
                tag = "ERR" if r["is_error"] else "OK"
                self.trace.append(f"     -> {call['id']} [{tag}] {r['content']}")
                results.append(r)
            messages.append({"role": "user", "content": results})  ## 回填，带 id
        return "触及最大轮次上限，返回降级答案"          ## FINISH：强制降级


def build_runtime() -> Runtime:
    reg = ToolRegistry()
    reg.register("get_weather", WEATHER_SCHEMA, get_weather)
    return Runtime(model=ScriptedModel(), executor=SafeExecutor(reg))


def run() -> None:
    rt = build_runtime()
    answer = rt.run("北上广今天天气如何？")
    print("=== 状态机运行轨迹 ===")
    print("\n".join(rt.trace))
    print("=== 最终答案 ===")
    print(answer)


if __name__ == "__main__":
    run()
```
保存为 `state_machine.py`，运行 `python state_machine.py`。完整预期输出：
```text
=== 状态机运行轨迹 ===
T1 STATE=EXECUTE calls=['get_weather#c1', 'get_weather#c2']
     -> c1 [OK] 晴12C
     -> c2 [OK] 多云15C
T2 STATE=EXECUTE calls=['get_weather#c3']
     -> c3 [ERR] 参数非法：参数 unit 取值须在 ['c', 'f'] 内
T3 STATE=EXECUTE calls=['get_weather#c4']
     -> c4 [OK] 阴20C
T4 STATE=FINISH answer=北京晴12C；上海多云15C；广州阴20C。
=== 最终答案 ===
北京晴12C；上海多云15C；广州阴20C。
```
## 逐帧读懂这段轨迹

这段轨迹把本章前四节全部串了起来，值得逐帧读：

- **T1**：模型一轮提议两个调用 `c1`、`c2`（第 3 节并行），执行器都通过校验、正常返回，按 `id` 回填两条结果。这是“一轮多调用 + id 配对”的最小实证。
- **T2**：模型伪造了 `unit="k"`，关口②的枚举校验精确拦下，回传 `is_error=True` 的结构化错误。注意运行时**没有崩溃、也没有把 `k` 当有效数据执行**——这正是“少减五元”里缺的那道关。
- **T3**：模型读到“参数非法：unit 取值须在 ['c','f'] 内”，改用合法的 `unit="c"` 重试成功。这演示了**错误是给模型的信号**：好的错误文案能让模型自我纠错（第 6 节深入）。
- **T4**：信息集齐，模型给出纯文本，无 `tool_use`，状态机自然终止。

把 `ScriptedModel` 换成真实客户端、把 `get_weather` 换成真实函数、把 `validate` 换成 `jsonschema`，`Runtime.run` 这段主循环一行都不用改。这就是把协议抽象成状态机的价值：**业务在变，骨架不变**。

## 真实系统对应

**官方公开机制**：本节主循环与 OpenAI 五步流程、Anthropic `tool_use`/`tool_result` 往返完全对应 [来源](https://platform.openai.com/docs/guides/function-calling) [来源](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)；`is_error=true` 是 Anthropic `tool_result` 的官方字段，用于告知模型该次工具执行失败 [来源](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)。**通用工程模式**：把“提议—校验—执行—回填”抽象为带轮次上限的有限状态机，用统一的 `tool_result` 结构承载成功与失败，是可迁移到任何厂商与任何 Agent 框架的骨架。**教学参考实现**：`ScriptedModel` 与手写 `validate` 仅为可运行、可复核而设，不复刻任何产品内部实现。

值得点明一个边界：真实生产里，工具执行往往并发（第 3 节）、带超时（第 6 节），主循环还会接入观测（每轮记录 `turn`、`tool_use_id`、`args_digest`、`latency_ms`）。本节为讲清状态转移把执行写成串行、把观测简化为 `trace`；把这两处替换成线程池与结构化日志，就是一个可上生产的骨架。

## 思考：为什么把 Function Calling 主循环建模成有限状态机，而不是一串 if-else？

### 回答

因为状态机让“循环何时结束、错误往哪走、轮次如何计数”这三件最容易出错的事变成显式的、可测试的转移，而不是散落在嵌套条件里的隐式假设。第一，终止条件被收敛到唯一的 FINISH 状态，且有两个明确入口（自然终止与轮次触顶），你不会漏掉“无限重试”这条最烧钱的路径。第二，EXECUTE 里任何关口失败都统一转成 `is_error` 结果再回到 CALL_MODEL，错误不会冒泡成崩溃，也不会被静默吞掉，这让“错误即信号”的自我纠错成为默认行为。第三，状态与转移可以逐条写断言测试（本节的三个 test 就是），协议退化会被立刻抓到。一串 if-else 能跑通 happy path，但终止、错误、轮次这三处的边界会随着功能增加而失控——而这三处恰恰是生产事故的高发区。

### 面试精简表达

状态机把“何时停、错误去哪、轮次多少”变成显式可测的转移；if-else 只在顺利路径上成立，边界一多就失控。

## 思考：这份教学实现要上生产，最少还得补哪三块？

### 回答

第一块是**真正的 Schema 校验**：把手写的 `validate` 换成 `jsonschema` 之类的成熟库，覆盖嵌套对象、数组、格式约束，并对齐厂商的 `strict` 模式，避免“合 Schema 但越业务界”的值蒙混过关（业务校验仍要独立于结构校验）。第二块是**并发与超时**：EXECUTE 里对独立、只读、幂等的调用用线程池并发，每个调用套独立超时罩，超时转 `is_error` 不阻塞其余（第 3、6 节）。第三块是**观测与幂等**：每轮记录结构化日志（`turn`、`tool_use_id`、`name`、`args_digest`、`latency_ms`、`exit`），对有副作用的工具加幂等键，保证重试不产生重复扣款、重复发信。这三块补齐，主循环骨架仍然不变——这正是状态机抽象的回报。

### 面试精简表达

补三块：成熟 Schema 校验 + 并发超时 + 观测与幂等；骨架不动，把简化处换成生产件即可。
