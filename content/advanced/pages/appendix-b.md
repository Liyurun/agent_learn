## B.1 如何读这些论文

不必逐字精读全部。**推荐三档读法**：
- **必读档**（⭐）：ReAct、Toolformer、Reflexion、RAG——理解现代 Agent 的骨架；
- **理解核心即可档**（✅）：CoT、ToT、GoT、Least-to-Most、Self-RAG、CRAG、Self-Consistency、Self-Refine、Voyager、多 Agent 相关——知道核心思想和适用场景；
- **了解存在档**（📖）：MRKL、综述类——需要时当索引查。

读论文的高效姿势：**先读 Abstract + Introduction + 结论图表**，抓住"解决什么问题、核心方法、效果"，再决定要不要深入方法细节。有两处务必多看一眼——**消融实验**（去掉某模块掉了多少分）和**失败分析**（方法在什么情况下失效），这两处恰恰是面试深挖时的高价值素材。

不要孤立记忆一篇篇论文，那样很快就忘。正确做法是记住它们的演进关系——CoT 给了"会推理"，ReAct 加上"会行动"，Reflexion 再加上"会反思"，一条线串起来就再也忘不掉。按主题还可以拎出三条支线：**推理结构**在不断放开（链 → 树 → 图），**检索**在不断学会自我把关（RAG → Self-RAG/CRAG → Agentic RAG），**记忆**在不断升级载体（存文本 → 存可执行技能，如 Voyager）。
```
        推理能力演进线（记住这条线，串起半部 Agent 史）
CoT ──────────► ReAct ──────────► Reflexion
"一步步想"      "边想边做"         "做错了会反思重来"
  │               │                    │
  ▼               ▼                    ▼
ToT→GoT       Toolformer/          Self-Refine/Voyager
"链→树→图"     工具调用             自我批评/技能沉淀
```

## B.2 推理与规划

### ⭐ ReAct: Synergizing Reasoning and Acting in Language Models

arXiv: [来源](https://arxiv.org/abs/2210.03629)

- **解决什么问题**：纯推理（CoT）无法与环境交互、易幻觉，模型"想得头头是道却用的是编造的事实"；纯行动缺乏规划，走一步看一步、容易迷路。二者各有短板。
- **核心思想**：让模型交替生成"推理(Thought)"和"行动(Action)"，中间穿插工具返回的真实"观察(Observation)"，形成 Thought → Action → Observation 循环。推理让行动更有计划，行动的真实反馈让推理不至于跑偏进幻觉——二者相互纠偏。整个过程无需微调，纯靠少样本提示即可跑通。
- **对工程的启示**：这是今天 90% 的 Agent 主循环的直系祖先。你在任何框架里看到的"模型输出一个动作、执行、把结果喂回去、再想下一步"，本质都是 ReAct 的变体。它也奠定了"轨迹(trajectory)"这个可观测、可评估的核心概念——你的 tracing 和评估集，记录的正是这条轨迹。工程实现可对照 smolagents 主循环 [来源](https://github.com/huggingface/smolagents)。
- **一句面试话术**："ReAct 让模型交替产出推理和行动，用行动的真实反馈纠正推理，是现代 Agent 主循环的原型，也是'轨迹'这个可观测单位的来源。"

### ✅ Chain-of-Thought Prompting

arXiv: [来源](https://arxiv.org/abs/2201.11903)

- **解决什么问题**：模型直接给答案时，在算术、常识、符号推理这类多步任务上表现差，一步到位错误率高。
- **核心思想**：在少样本示例里给出"问题—详细推理步骤—答案"的范例，诱导模型回答新问题时也先写出中间推理链再给结论；后续衍生出"Let's think step by step"的零样本触发写法。它把"推理"从黑箱变成可引导、可观察的显式过程。有效的本质是"把一步到位的难题拆成若干小步、降低每步难度"。
- **对工程的启示**：CoT 是 Agent"会思考"的地基。没有可靠的分步推理，规划、工具选择、错误诊断都无从谈起。ReAct 的"Thought"部分、几乎所有规划模块，都建立在 CoT 之上。工程上要注意：CoT 增加了输出 token 与延迟，对简单任务是浪费，要按任务难度决定用不用。
- **一句面试话术**："CoT 让模型把中间推理说出来，靠'拆小步降难度'提升多步任务准确率，是 ReAct 里'推理'那一半的基础。"

### ✅ Tree of Thoughts (ToT)

arXiv: [来源](https://arxiv.org/abs/2305.10601)

- **解决什么问题**：CoT 是单线推理，一步错则全错，无法探索多种可能、也不能反悔。
- **核心思想**：把推理显式建模成一棵可搜索的"思维树"——每个节点是一个中间思维状态。三件套：思维分解（把问题拆成若干思维步）、状态评估（让模型给每个中间状态打分或投票）、搜索策略（用广度/深度优先在树上找最优路径），并允许回溯。相当于给推理装上"深思熟虑、可以反悔"的能力，在 24 点、创意写作等需探索的任务上明显优于 CoT。
- **对工程的启示**：为需要"试错 + 回溯"的复杂任务提供了范式，是很多"深度规划型 Agent"的思想来源。但它提醒一条铁律：更强的推理往往以更多模型调用（更高 token 成本、更高延迟）为代价，生产上要严格权衡是否值得。
- **一句面试话术**："ToT 把推理从一条链扩展成一棵可评估、可回溯的树，用探索换准确，代价是成倍的 token 和延迟。"

### ✅ Graph of Thoughts (GoT)

arXiv: [来源](https://arxiv.org/abs/2308.09687)

- **解决什么问题**：ToT 只能在"树"结构上探索——分支之间彼此独立、无法合并，遇到"需要把几条思路的中间产物聚合起来"的问题就力不从心。
- **核心思想**：把 LLM 产生的每个"思维"建模成图(graph)里的顶点，边表示思维之间的依赖关系。图结构比树多了两种关键操作——**聚合**（把多条思维链的产物合并成一个更优结果）与**精炼**（对一个思维反复迭代改进）。相当于把推理从"一棵树"进一步放开成"任意有向图"，能表达比树更复杂的思考拓扑。
- **对工程的启示**：GoT 是 CoT → ToT → GoT 这条"推理结构不断放开"演进线的最新一环，适合能拆解、能合并的复杂任务（如排序、集合运算、多文档归并）。但结构越复杂，编排与调用成本越高，工程上很少直接照搬，更多是借它"允许聚合与回环"的思想去设计自定义的推理编排。
- **一句面试话术**："GoT 把推理结构从树进一步放开成任意图，多了'聚合多条思路'和'迭代精炼'两种操作，是 CoT→ToT→GoT 演进线的最新一环。"

### ✅ Least-to-Most Prompting（由易到难分解）

arXiv: [来源](https://arxiv.org/abs/2205.10625)

- **解决什么问题**：CoT 在"训练样本简单、测试题却更难"的泛化场景（如更长的组合推理）上会失效，模型无法把学到的推理迁移到更复杂的问题。
- **核心思想**：分两阶段——先让模型把复杂问题**分解**成一串由易到难、层层递进的子问题，再**依次求解**，并把已解出的子问题答案作为解决后续子问题的上下文。核心是"先拆再逐个击破，且后一步能用上前一步的结果"，让难题沿着"由易到难"的阶梯被逐级攻克。
- **对工程的启示**：它是 Agent"任务分解 + 规划"能力的重要理论支撑，说明了"显式拆解 + 逐步求解"为什么比一步到位更能对付难题。今天 Agent 里的"先规划出子任务列表、再逐个执行并累积中间结果"，正是这一思想的工程化。
- **一句面试话术**："Least-to-Most 先把难题分解成由易到难的子问题再逐个求解、后一步复用前一步结果，是 Agent 任务分解与规划的理论支撑。"

## B.3 工具使用

### ⭐ Toolformer: Language Models Can Teach Themselves to Use Tools

arXiv: [来源](https://arxiv.org/abs/2302.04761)

- **解决什么问题**：如何让模型自主决定"何时、用哪个工具、传什么参数"，而不是靠人工硬编规则。
- **核心思想**：自监督地学会用工具。先让模型在大量文本里"猜测"哪里该插入什么 API 调用（计算器、搜索、翻译、日历），实际执行这些调用，再用一个准则筛选——只保留那些"插入后能显著降低后续 token 预测损失"的调用样本，用这批高质量样本微调模型。本质是"用工具是否真的帮到了预测"当监督信号。
- **对工程的启示**：它是今天 Function Calling / Tool Use 的思想先驱，论证了"工具使用是可学习、可泛化的能力"，为后续把工具调用做成模型原生能力（结构化函数调用）铺了路。今天的实现更多靠指令微调 + 结构化输出，而非它那套自监督插桩，但"让模型自己决定调不调工具"的思想一脉相承。向后接第 8 章 Function Calling、第 9 章 MCP 标准化连接 [来源](https://modelcontextprotocol.io/)。
- **一句面试话术**："Toolformer 证明模型能自监督地学会何时怎样调工具，是 Function Calling 的思想先驱；今天靠指令微调实现，但思路同源。"

### 📖 MRKL Systems（模块化推理、知识与语言）

arXiv: [来源](https://arxiv.org/abs/2205.00445)

- **解决什么问题**：纯神经网络语言模型不擅长精确计算、访问实时/私有知识，且推理不可靠；如何补上这些短板。
- **核心思想**：提出"神经-符号"的模块化架构——一个 LLM 充当路由器，把子问题分派给一组专家模块（可以是神经网络，也可以是计算器、数据库查询、API 等符号系统），再汇总结果。它把"语言理解"和"精确执行"解耦，是"LLM 做大脑、外部工具做手脚"这一范式的早期系统性论述。
- **对工程的启示**：MRKL 是"路由 + 工具调用"这一整套现代 Agent 架构的思想前身，比很多人以为的更早。今天的意图路由子 Agent、工具层、专家 Agent 分工，都能在它的框架里找到影子。理解它有助于回答"为什么要给 LLM 配外部工具而不是让它硬算"。
- **一句面试话术**："MRKL 早在 2022 年就提出'LLM 当路由器、把子任务分派给符号/神经专家模块'，是'路由+工具'这套 Agent 架构的思想前身。"

## B.4 反思与自我改进

### ⭐ Reflexion: Language Agents with Verbal Reinforcement Learning

arXiv: [来源](https://arxiv.org/abs/2303.11366)

- **解决什么问题**：Agent 犯错后如何改进？重新训练成本高、慢，能不能不改权重就让它"越试越好"。
- **核心思想**：提出"言语强化学习(verbal reinforcement)"——不更新任何模型权重，而是让 Agent 把每次失败的教训用自然语言写成"反思笔记"存进记忆，下一次尝试时读取。三个角色协同：执行者(Actor，产生行动轨迹)、评估者(Evaluator，判断成功还是失败)、自我反思模块(把失败原因总结成文字反馈)。反思文本作为下一轮的额外上下文，形成"尝试—失败—反思—重试"的闭环，把强化学习"从奖励中学习"的思想用纯语言、零训练的方式实现了。
- **对工程的启示**：它是"自我改进型 Agent"和"从经验中学习"这条路线的代表作，直接影响了带记忆、能迭代的 Agent 设计，与评估者-优化者工作流模式思想相通。但要认清边界：它靠上下文里的语言反馈，成本低、可解释，但改进不持久——换个会话就忘，除非把反思持久化进长期记忆。
- **一句面试话术**："Reflexion 不改权重，靠把失败写成语言反思存进记忆来自我改进，代表'从经验中学习'路线，但改进不持久、需持久化记忆才留得住。"

### ✅ Self-Refine（迭代自我批评）

arXiv: [来源](https://arxiv.org/abs/2303.17651)

- **解决什么问题**：不引入额外训练或外部标注，能不能让模型自己把初稿改得更好。
- **核心思想**：同一个模型"既当运动员又当裁判"——单模型三步循环：生成(produce)初稿、反馈(自评并指出具体问题)、精修(据反馈重写)，靠提示切换角色，多轮迭代后质量稳步提升。适用于写作、代码、对话优化等"有明确改进方向"的开放任务。
- **对工程的启示**：它是评估者-优化者(Evaluator-Optimizer)这一工作流模式的直接理论支撑，也解释了"为什么让 Agent 自己检查一遍常能提质"。但边界很关键：当模型对某类错误本身就没有判断力时，自我批评会失效甚至自我强化错误——评判能力必须强于生成能力，自评才有增益。
- **一句面试话术**："Self-Refine 让同一模型生成→自评→精修迭代提质，是评估者-优化者模式的支撑；但当评判力不强于生成力时自评无效。"

### ✅ Voyager: An Open-Ended Embodied Agent

arXiv: [来源](https://arxiv.org/abs/2305.16291)

- **解决什么问题**：如何让 Agent 在开放环境里**终身学习**——不断探索、把学到的技能沉淀下来复用，而不是每个任务从零开始，且全程无需人工干预。
- **核心思想**：在《我的世界》里落地的三件套——**自动课程**（让模型按当前能力自动生成"下一个该学的任务"，最大化探索）、**技能库**（把验证过的行为写成可执行代码存起来，需要时检索复用，越攒越多）、**迭代提示机制**（把环境反馈、执行报错、自我验证结果喂回去改进代码）。它把"记忆"从存文本升级成存**可执行技能**，把"反思"落到了代码级的自我纠错。
- **对工程的启示**：Voyager 是"技能库 / 工具自生成 / 终身学习型 Agent"的代表作，示范了"用代码当记忆载体、把成功经验沉淀成可复用组件"这一强大范式，对构建能自我扩展工具集的 Agent 很有启发。它也印证了 Reflexion 的思路——用语言/代码反馈迭代改进，无需改权重。
- **一句面试话术**："Voyager 靠自动课程+可执行技能库+环境反馈迭代，在开放世界里终身学习、越玩越强，代表'用代码当记忆、把经验沉淀成可复用技能'的范式。"

## B.5 检索增强与知识接入

### ⭐ RAG: Retrieval-Augmented Generation

arXiv: [来源](https://arxiv.org/abs/2005.11401)

- **解决什么问题**：模型只靠参数里记住的知识作答，会知识陈旧、无法溯源、容易幻觉；如何让它引用最新、可查证的外部知识。
- **核心思想**：把"参数化知识（模型权重里记的）"和"非参数化知识（外部可检索的文档）"结合。检索器把问题编码成向量、从向量库召回相关文档，生成器把召回内容拼进上下文、据此生成答案，两段式协作，可端到端联合优化也可各自独立。
- **对工程的启示**：RAG 是 Agent 记忆与知识接入的地基（第 5 章），更是"Agentic RAG"的前身——当"要不要检索、检索几次、如何改写查询"都交给 Agent 自主决定时，RAG 就升级为 Agentic RAG。工程高频对比题"RAG vs 微调"：知识频繁更新、需溯源用 RAG，改变行为风格、内化稳定知识用微调，二者可结合。
- **一句面试话术**："RAG 先检索外部知识再生成，缓解知识陈旧和幻觉、支持溯源；把检索决策权交给 Agent 就成了 Agentic RAG。"

### ✅ Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection

arXiv: [来源](https://arxiv.org/abs/2310.11511)

- **解决什么问题**：普通 RAG 不管问题需不需要都固定检索，检索到的段落还可能无关或矛盾，反而拖累答案；且模型不会评估"我引用的证据到底支不支持我的结论"。
- **核心思想**：训练模型生成特殊的"反思 token(reflection tokens)"，让它在生成过程中自主决策三件事——**要不要检索**（按需触发，而非每次都查）、**召回段落是否相关**、**生成内容是否被证据支持**。相当于把"检索 + 生成 + 自我批评"缝进一个模型，让它边写边给自己的证据链打分，不达标就重检索或修正。
- **对工程的启示**：Self-RAG 是从"固定 RAG"迈向"Agentic RAG"的关键一步，把检索的决策与质量自评显式化。它对工程的直接启发是：生产级 RAG 不该无脑检索，应加"要不要检索"的判断和"引用是否支撑结论"的校验——这正是防幻觉的两道实用闸门。
- **一句面试话术**："Self-RAG 用反思 token 让模型自主决定要不要检索、召回是否相关、结论是否被证据支持，是从固定 RAG 走向 Agentic RAG 的关键一步。"

### ✅ CRAG: Corrective Retrieval-Augmented Generation

arXiv: [来源](https://arxiv.org/abs/2401.15884)

- **解决什么问题**：普通 RAG 一旦检索到的文档不相关或质量差，会把错误信息一起喂给模型、放大幻觉；缺少一道"检索结果到底靠不靠谱"的质检关。
- **核心思想**：加一个**轻量级检索评估器**，给召回文档的整体质量打分并分成三档动作——**Correct**（质量高，做"分解-再重组"提炼关键信息后使用）、**Incorrect**（质量差，丢弃本地文档，改用大规模网络搜索补充）、**Ambiguous**（不确定，两者结合）。相当于给 RAG 装上"检索质检 + 自动纠偏"，检索不好就换个来源重来，而不是硬着头皮用。
- **对工程的启示**：CRAG 与 Self-RAG 是"让 RAG 学会自我把关"的两条代表路线，都指向同一条生产经验——**不要无条件信任检索结果**，要加质量评估与兜底来源（如 Web 搜索）。它是构建鲁棒 RAG/Agentic RAG 的实用蓝本，且可即插即用地嵌到已有 RAG 流程里。
- **一句面试话术**："CRAG 用一个检索评估器给召回质量打分，好就提炼后用、差就转网络搜索兜底，是给 RAG 加'质检 + 自动纠偏'的代表方案。"

## B.6 多智能体

### ✅ 多 Agent 协作代表工作（AutoGen、CAMEL、Generative Agents 等）

代表作 arXiv：Generative Agents [来源](https://arxiv.org/abs/2304.03442)、CAMEL [来源](https://arxiv.org/abs/2303.17760)、AutoGen [来源](https://arxiv.org/abs/2308.08155)

- **解决什么问题**：单个 Agent 上下文放不下、角色易冲突时，如何组织多个 Agent 分工、通信、协作完成复杂任务。
- **核心思想**：给每个 Agent 设定角色/系统提示，定义它们之间的对话协议与终止条件。AutoGen 提出可编程的多 Agent 对话框架，CAMEL 探索角色扮演驱动的自主协作，Generative Agents 展示了带"记忆流 + 检索 + 反思 + 规划"的 Agent 群体如何涌现出可信的类人行为。它们共同论证了"分工 + 通信"能突破单 Agent 的能力边界。
- **对工程的启示**：它们是多 Agent 系统设计的思想源头，但也暴露了核心代价——通信开销大、易发散、调试困难、成本高。成熟的工程共识是"能单 Agent 解决就别上多 Agent，把多 Agent 当最后手段"。落地时对照第 11 章的中心化/去中心化、编排者-工作者、交接(handoff)设计，以及 OpenAI Agents SDK 的 handoff 实现。
- **一句面试话术**："多 Agent 靠角色分工+对话协作突破单 Agent 边界，但通信开销大、易发散、难调试；只在任务能拆成弱耦合子任务、单 Agent 真搞不定时才用。"

### ✅ Self-Consistency：给推理链投票

arXiv: [来源](https://arxiv.org/abs/2203.11171)

- **解决什么问题**：CoT 只生成一条推理链，一旦这条链走偏，答案就错，稳健性不足。
- **核心思想**：指出"最优推理路径不唯一"。在生成时提高采样温度、产出多条不同推理链，抽取各自最终答案后投票取众数，用集成思想显著提升推理稳健性。简单、无需训练、即插即用。
- **对工程的启示**：是"用冗余换可靠"的典型，思路可迁移到 Agent 的多次尝试与结果聚合；也再次印证"更准往往更贵"——多采样几倍就多花几倍 token。
- **一句面试话术**："Self-Consistency 采样多条 CoT 再对答案投票，用冗余换稳健，是'多花 token 买准确率'的典型。"

## B.7 综述（📖 当索引查）

### 📖 LLM-based Autonomous Agents 综述

arXiv: [来源](https://arxiv.org/abs/2308.11432)

- **解决什么问题**：Agent 研究散落各处，缺一张统一的地图，新手不知从何入手、也难找细分方向的原始文献。
- **核心思想**：用文献综述与分类学(taxonomy)把 Agent 研究整理成统一框架（构建 / 应用 / 评估三大块），系统盘点规划、记忆、工具、行动等模块的代表方法，通常配一张覆盖全领域的结构图。
- **对工程的启示**：它本身不提新方法，价值在"降低进入门槛"和"提供检索索引"——想深挖某方向时，顺着它的分类和引用能快速找到该读哪些原始论文。要配合官方博客和 Release Notes 补最新进展，因为综述天然有发表滞后。
- **一句面试话术**："综述当地图用，先看它的分类框架建全局观，再顺引用找原文；但它有滞后，最新进展靠官方博客补。"

## B.10 四篇必读的"深挖锦囊"（被追问时的加分点）

面试官若顺着你的话术往下追问，往往问的正是各论文的**边界与失败模式**。提前备好这几句，被深挖时能稳住：

- **ReAct 被追问"它有什么局限"**：答"依赖工具/环境返回可靠观察，观察本身若含噪或被污染（提示注入），推理会被带偏；且轨迹变长后 token 成本和上下文压力上升，需要配终止条件和上下文管理。"
- **Toolformer 被追问"为什么今天不用它那套自监督"**：答"它的自监督插桩训练成本高、可扩展性有限；今天靠指令微调 + 结构化函数调用就能达到同样'自主决定调工具'的效果，工程上更简单，但'工具使用可学习'这个核心结论仍然成立。"
- **Reflexion 被追问"和 RLHF/微调比呢"**：答"Reflexion 是运行时、零训练、可解释的'言语强化'，改进快但不持久（不落库就随会话消失）；RLHF/微调改权重，持久但慢且贵。二者不冲突，可先用 Reflexion 快速迭代、再把稳定经验沉淀进训练。"
- **RAG 被追问"它什么时候反而拖后腿"**：答"检索到无关或矛盾文档时会放大幻觉——这正是 Self-RAG/CRAG 要加'检索质检'的原因；此外分块不当、embedding 不匹配、关键信息落在长上下文中间（Lost in the Middle）都会让 RAG 失效，要靠 Rerank、质量评估和引用校验兜底。"

> **用法**：这四条不用全背，挑你话术里最可能被追问的一两个准备即可。能主动说出方法的"失败模式"，比只会背优点更能体现工程判断力。

## 本附录小结

- **四篇必读**：ReAct（推理+行动）、Toolformer（自主用工具）、Reflexion（从失败中反思）、RAG（检索增强）——现代 Agent 的骨架。
- 每篇统一用"解决什么问题 → 核心思想 → 对工程的启示 → 一句面试话术"四段结构，覆盖 CoT、ToT、GoT、Least-to-Most、Self-Consistency、Self-RAG、CRAG、Self-Refine、Voyager、MRKL、多 Agent 系列与综述，全部附 arXiv 链接。
- 读论文用"三档读法"：必读精读、核心理解、了解存在；先看 Abstract + Intro + 图表，重点看消融与失败分析。
- 记住"CoT → ReAct → Reflexion"这条推理能力演进主线，再挂三条支线——推理结构（链→树→图）、检索自查（RAG→Self-RAG/CRAG）、记忆载体（文本→可执行技能）；孤立记忆很快忘，串成网才记得牢。
- B.9 的面试话术总表可直接背用，能说清 ReAct、Toolformer、Reflexion、RAG 的核心思想是明确加分项。
