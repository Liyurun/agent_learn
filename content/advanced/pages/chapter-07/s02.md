## 真实问题

一个做多步网页问答的 Agent，任务是「查出某开源库最新稳定版本号并给出发布日期」。第一次尝试，它点进了一个第三方镜像站，读到一个过期的版本号，答错了。系统告诉它「答案错误」。第二次尝试，它又点进了同一个镜像站，读到同一个过期版本号，又答错了。第三次、第四次……它像被鬼打墙一样，每次都从同一个错误来源出发。

问题不在于它「不会反思」——事实上，每次失败后它都生成了一段「我应该更仔细核对来源」的话。问题在于：**这段反思没有被存下来，也没有在下一次尝试时带回去。** 每一次尝试都是「失忆的重新开始」。它「反思」了，但反思像写在沙滩上的字，下一轮就被冲掉了。

Reflexion 要解决的正是这个「反思留不住」的问题：把失败的教训用**自然语言**写下来，**存进记忆**，并在**下一次尝试时带回来**，从而实现跨尝试的经验积累。

## 原理：Reflexion 的三个不可省要素

Reflexion 论文（arXiv:2303.11366）提出的核心机制是：不通过更新模型权重，而是把环境给的二元或标量反馈（成功/失败、得分）转化为**语言化的反馈**（一段文字总结），作为额外上下文加到下一轮，从而指导 Agent 改进 [来源](https://arxiv.org/abs/2303.11366)。论文里有一句很精炼的话：这种自我反思的反馈充当了一种「语义梯度信号（semantic gradient signal）」，给 Agent 指出一个具体的改进方向，就像人类通过少量尝试迭代学会复杂任务一样 [来源](https://arxiv.org/abs/2303.11366)。

拆开看，Reflexion 有三个缺一不可的要素：
```text
要素一：真实的结果反馈（不是凭空空想）
    Actor 执行任务 → Evaluator 判定成功/失败/得分
    这一步必须来自环境（测试、工具、真值），不能是模型自己拍脑袋。

要素二：把反馈"语言化"（转成一段可读的文字教训）
    Self-Reflection 模型读入 [失败轨迹 + 任务 + 评估结果]
    → 生成一段自然语言反思：诊断哪里错了、为什么、下次怎么改。

要素三：把反思"存进记忆"并在下一轮"带回来"
    反思写入情景记忆缓冲区（episodic memory buffer）
    下一次尝试时，这段反思作为上下文喂给 Actor → 表现改进。
```
论文里对应的三个角色是：**Actor**（执行任务、产出动作轨迹）、**Evaluator**（对轨迹打分）、**Self-Reflection**（把打分结果转成语言反思）[来源](https://arxiv.org/abs/2303.11366)。开头那个「鬼打墙」的 Agent，缺的正是要素三——它有 Actor，也做了类似 Self-Reflection 的事，但没有把反思存进记忆并带回下一轮。

## 为什么用「语言」而不是「更新权重」

Reflexion 最反直觉、也最精妙的一点，是它不做梯度下降、不改模型参数，而是把经验写成一句话存起来。这不是「因为改权重太难所以退而求其次」，而是这种做法本身有独特优势。对比两条学习路径：

| 维度 | 传统强化学习（更新权重） | Reflexion（语言反思） |
|---|---|---|
| 学习载体 | 模型参数（数十亿浮点数） | 一段自然语言经验 |
| 一次学习成本 | 极高（要梯度计算、训练迭代） | 极低（一次推理即可产出反思） |
| 见效速度 | 慢，需要大量样本 | 快，一次失败即可总结出教训 |
| 可解释性 | 差，参数变化无法直接读懂 | 好，经验就是人能读的一句话 |
| 可迁移性 | 绑定在这个模型的权重里 | 可复制、可编辑、可跨模型共享 |

这张表的核心是：**用「写笔记」代替「重新学习」。** 一个人考试错了一道题，不需要重读三年课本，只需在错题本上记一句「这类题要先看单位」。Reflexion 就是给 Agent 配了本错题本——语言化的经验既便宜、又快、又能被人读懂和编辑。这也是它被归为「上下文内学习（in-context learning）」的原因：知识不进权重，而进上下文。

顺带澄清一个常见混淆：这里的 RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习，见 InstructGPT [来源](https://arxiv.org/abs/2203.02155)）是**训练阶段**改权重的方法，而 Reflexion 是**推理阶段**不改权重的方法。二者不冲突，也不是一回事——一个塑造模型的底层倾向，一个在具体任务中即时纠错。面试里若把两者混为一谈，是典型的概念不清。

## 最小可运行演示

下面这段可运行代码在「猜数字」任务上完整体现 Reflexion 的三个要素：每次尝试后把「猜大了还是小了」写成语言反思，存进记忆，带进下一轮。它虽小，却把 Actor / Evaluator / Self-Reflection / Memory 四件事都落地了：
```python
def actor(memory, low, high):
    """Actor：带着记忆（收窄的区间）做决策。"""
    return (low + high) // 2


def evaluator(guess, target):
    """Evaluator：给出真实的结果反馈（不是模型空想）。"""
    if guess == target:
        return True, "猜对了"
    if guess < target:
        return False, f"{guess} 太小了，目标更大"
    return False, f"{guess} 太大了，目标更小"


def self_reflection(feedback):
    """Self-Reflection：把反馈转成一句语言化教训。"""
    return f"经验：{feedback}，据此缩小搜索范围"


def reflexion_agent(target, max_trials=8):
    memory = []                                   # 情景记忆：存历次语言反思
    low, high = 1, 100
    for trial in range(1, max_trials + 1):
        guess = actor(memory, low, high)          # ① 带记忆决策
        success, feedback = evaluator(guess, target)   # ② 真实反馈
        print(f"第{trial}次: 猜 {guess} -> {feedback}")
        if success:
            print(f"在第 {trial} 次成功；累计语言反思 {len(memory)} 条")
            return
        lesson = self_reflection(feedback)        # ③ 反馈语言化
        memory.append(lesson)                     # ④ 写入记忆
        # ⑤ 把语言反思"落地"成对下一轮的约束（真实 LLM 里这一步是隐式的）
        if "太小" in feedback:
            low = guess + 1
        else:
            high = guess - 1
    print("达到最大尝试次数，未成功")


if __name__ == "__main__":
    reflexion_agent(target=73)
```
保存为 `reflexion_guess.py`，运行 `python reflexion_guess.py`，预期输出：
```text
第1次: 猜 50 -> 50 太小了，目标更大
第2次: 猜 75 -> 75 太大了，目标更小
第3次: 猜 62 -> 62 太小了，目标更大
第4次: 猜 68 -> 68 太小了，目标更大
第5次: 猜 71 -> 71 太小了，目标更大
第6次: 猜 73 -> 猜对了
在第 6 次成功；累计语言反思 5 条
```
逐点讲解：

- **标注 ④（反思入记忆）**：`memory.append(lesson)` 是 Reflexion 的灵魂——把教训用语言存下来。真实系统里这段记忆会作为上下文拼进下一轮的提示（prompt）。
- **标注 ①（带记忆决策）**：`actor` 的决策不是瞎猜，而是被历史反思收窄后的区间 `low/high` 约束着。这就是「带着反思再尝试」。
- **标注 ②（真实反馈）**：`evaluator` 的反馈来自「与 target 比较」这个客观事实，不是模型自己想象的。这是 Reflexion 有效的前提。
- **标注 ⑤（反思落地为约束）**：这里显式地把「太小/太大」翻译成区间收窄。真实 LLM Agent 里这一步是隐式的——模型读到上下文里的反思「上次 50 太小了」，自然会往大了猜，不需要写 if-else。这段代码把隐式过程「显式化」，方便看清机制。

把「猜数字」换成「写代码通过测试」「多轮检索答复杂问题」，机制完全一样：**真实反馈 → 语言反思 → 带着反思改进下一次尝试。**

## 反思在真实 LLM Agent 里到底怎么「带进下一轮」

上面用 `low/high` 落地反思是为了直观。真实 LLM Agent 里，反思是**以自然语言拼进下一轮提示**的。把这个「拼接」画出来，就懂了 Reflexion 的工程实质：
```text
第 1 轮 prompt：
    [系统提示] 你要完成任务 X
    [任务] ...
        │ 模型执行 → 失败（Evaluator 判定）
        ▼
    Self-Reflection：「这次失败是因为没先检查文件是否存在」→ 写入 memory

第 2 轮 prompt：            ← 关键：把上一轮的反思拼进来了
    [系统提示] 你要完成任务 X
    [历史反思] 上次教训：「没先检查文件是否存在导致失败，这次先检查」
    [任务] ...
        │ 模型带着教训执行 → 成功
        ▼
    （经验沉淀在 memory 里，可跨任务复用）
```
这张图点出 Reflexion 的落地本质：**它不改模型，只改喂给模型的上下文。** 反思模块产出的那句话，会作为「历史教训」区块拼进下一轮提示的固定位置。模型每一轮都是「无状态」地重新读一遍完整上下文——正是靠这段被反复带上的反思，它表现得像「记住了」上次的教训。这也揭示了它的容量上限：**反思攒得太多，同样会撑爆上下文窗口**，这时需要第 5 章的记忆压缩来配合。

## 三种反思形态：从「错题本」到「策略手册」

工程上常见三种反思形态，深浅不同、用途各异：

| 反思形态 | 内容 | 例子 | 适用范围 |
|---|---|---|---|
| 单次教训（episodic） | 针对这一次失败的具体教训 | 「路径 /data/x 不存在」 | 当前任务内立即纠错 |
| 模式总结（pattern） | 从多次失败中抽象出的规律 | 「读文件前都要先确认路径存在」 | 跨尝试、同类任务复用 |
| 策略手册（strategy） | 沉淀成可复用的操作准则 | 「文件类任务标准流程：先 list 再 read」 | 跨任务、长期知识库 |

三者是「由具体到抽象」的递进：单次教训最廉价、最即时，但换个任务就没用了；策略手册最有价值、可长期复用，但需要模型有能力从多次经验里归纳规律。**成熟的 Agent 记忆系统会把三者分层存储**——单次教训放短期记忆（当轮用完即弃），模式总结与策略手册沉淀进长期记忆（第 5 章的向量库）。这是「反思」与「记忆」两块原语咬合的地方：反思负责「产出经验」，记忆负责「存取经验」。

## 真实系统对应

**官方公开机制**：Reflexion 是一篇有公开代码与实验的论文，其 Actor / Evaluator / Self-Reflection 三角色结构、以及「把反馈语言化存入情景记忆」的机制均有原文支撑 [来源](https://arxiv.org/abs/2303.11366)。**通用工程模式**：把「执行—评估—语言反思—写记忆—带回下一轮」做成一个可复用循环，可迁移到任何支持多轮上下文的模型。**教学参考实现**：上面的猜数字代码和「三种反思形态」的分层存储，是为讲清机制而构造的，Reflexion 原论文并没有规定「必须分三层存」这种工程细节。

要特别强调一个边界：Reflexion 论文报告了在若干基准上的提升，但那些数字绑定于特定模型、特定任务与特定实验设置。不能把「Reflexion 在某任务上提升 X%」当成「反思总能提升 X%」的普适承诺——第 06 节会用 DeepMind 的反证说明，换个任务（纯推理、无外部反馈）时反思可能无效甚至有害。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 反思了却依然重复犯错 | 反思没写进记忆，或写了但没带进下一轮提示 | 打印每轮实际提示，检查「历史反思」区块是否存在 | 确保反思持久化并拼进下一轮上下文 | 单次性任务无需跨轮记忆 |
| 反思越攒越多撑爆窗口 | 只往记忆里加，不做压缩或淘汰 | 统计记忆条数与提示总 Token（Token，词元） | 分层存储 + 摘要压缩（配合第 5 章记忆） | 短任务反思很少时无需压缩 |
| 反思内容空泛无指导性 | Self-Reflection 只说「我要更认真」而无具体诊断 | 抽查反思文本，看是否包含「哪里错、为什么、怎么改」 | 给反思模板明确要求三要素 | 反馈本身就模糊时先修反馈信号 |
| 反思基于错误反馈越改越偏 | Evaluator 的判定不可信 | 核对 Evaluator 结果与真值是否一致 | 用客观信号（测试/工具）做 Evaluator | 无法获得客观信号时降低对反思的信任 |

## 思考：Reflexion 为什么属于「上下文内学习」而不是「训练」？

### 回答

因为它**不改动任何模型参数**。传统「学习」意味着用样本更新权重；Reflexion 从头到尾模型权重不变，它改变的只是「喂给模型的上下文」——把上一轮的失败教训以自然语言拼进下一轮提示。模型每轮都是无状态地重读完整上下文，之所以表现得像「记住了」，是因为反思被反复带上。这就是「上下文内学习（in-context learning）」的定义：能力提升来自上下文，而非参数。

从这个角度看，Reflexion 的「记忆」和人脑的长期记忆不同——它更像「随身带着的错题本」，一旦不把本子带进考场（不拼进提示），就等于没学过。

### 面试精简表达

Reflexion 不改权重，只改上下文。它把失败写成一句话带进下一轮，是「写笔记」而非「重新训练」，所以属于上下文内学习。

## 思考：如果反思攒得太多、装不下窗口，怎么办？

### 回答

三个层次处理。第一，**分层与淘汰**：单次教训用完即弃，只把「模式总结」和「策略手册」沉淀进长期记忆，短期噪声不长期占用窗口。第二，**压缩**：把多条同类反思合并成一条更抽象的规律（比如三条「路径 X/Y/Z 不存在」合并为「读文件前先确认路径存在」），这既省空间又提升了反思的抽象层次。第三，**检索式召回**：把反思存进外部向量库，下一轮只召回与当前子任务相关的少数几条，而不是把全部历史反思都拼进提示。这三点正是本章「反思」与第 5 章「记忆系统」的接口——反思负责产出经验，记忆负责在有限窗口里高效存取经验。

需要注意的反例：压缩不是越狠越好。把「补丁 A 改动第 12 行未修复用例 3」压成「代码没改对」，就丢失了可定位的信息，下一轮反思又变成瞎猜。压缩要保住「可定位、可执行」的关键字段。
