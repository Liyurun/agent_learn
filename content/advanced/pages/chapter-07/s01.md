## 真实问题

一个「批量重命名 + 归档」的运维 Agent 收到任务：把 `/logs` 下过去 30 天的日志按日期归档。它的第一步动作是 `read_dir("/logs/2026-08")`，返回 `FileNotFoundError`。它的第二步动作是……`read_dir("/logs/2026-08")`，一模一样。第三步、第四步还是同一个。直到跑满 20 步的硬上限被强制杀掉，它一共对同一个不存在的路径发起了 20 次读取，烧掉了 20 次模型调用的钱，什么也没归档。

事后看日志，问题一目了然：真实目录是 `/var/logs`，`/logs` 根本不存在。一个人在第二次 `FileNotFoundError` 时就会停下来想「是不是路径错了，我先 `ls` 看看」。但这个 Agent 没有这个「停下来想一下」的环节——它的循环里只有「执行下一步」，没有「审视上一步」。

这就是普通 ReAct（Reasoning and Acting，推理与行动）循环的结构性盲点：它默认每一步都是对的，缺少一个「回头看」的监督层。反思要解决的，正是这个「一次做错就沿着错误方向一路走到黑」的问题。

## 原理：给 Agent 加一个「元认知层」

回顾第 4 章的 ReAct 循环：`Thought → Action → Observation`，三步一轮，向前推进。它有一个隐含假设——**每一步的 Thought 都是可靠的**。ReAct 里的 `Thought` 是「向前看」：思考下一步做什么。它不会回过头问「我刚才那步做得对吗」。

反思（Reflection）补的就是这个环节。它给 Agent 加一层「元认知（metacognition）」：不只是「做」，还要「审视自己做得对不对」。用结构表达：
```text
普通 ReAct（只有执行层）：
    Thought → Action → Observation → Thought → Action ...
    （埋头往前，错了也不知道）

带反思的 Agent（多了监督层）：
    ┌─────────── 监督层（元认知）───────────┐
    │  我刚才那步靠谱吗？结果符合预期吗？    │
    │  如果不符合，问题在哪，下一步要不要换？ │
    └───────────────┬───────────────────────┘
                    │ 审视 & 修正
                    ▼
    执行层：Thought → Action → Observation
```
Lilian Weng 在关于自主 Agent 的综述里，把「自我反思（self-reflection）」列为 Agent 规划能力的关键组成：Agent 通过对过去行动的自我批评与反思，从错误中学习并改进后续步骤 [来源](https://lilianweng.github.io/posts/2023-06-23-agent/)。这里的重点是「从错误中学习」——普通 ReAct 会犯错，但不会「从错误中学习」，它只是继续往前。

执行层负责「做」，监督层负责「判断做得对不对、要不要调整」。这也正是人类专家与新手的差别：专家一边做一边监控「我是不是跑偏了」，新手往往一条道走到黑。给 Agent 加反思，本质上是让它从「新手」向「专家」靠拢。

## 现象与输入：三种「没有反思」的典型崩法

「没有反思」不是一种崩法，而是三种，它们的输入特征不同：
```text
崩法一：重复失败动作（原地打转）
    输入信号：连续两步 Action 完全相同，Observation 都是失败
    例子：反复 read_dir("/logs") 20 次
    本质：没有"这步失败了，别再做同样的事"的记忆

崩法二：沿错误假设一路走到黑（方向错误）
    输入信号：每步都在"局部微调"，但始终没质疑最初的大方向
    例子：认定 bug 在函数 A，改了 11 版都在 A 里打转，没看函数 B
    本质：没有"整体方向是不是错了"的回顾

崩法三：一次成型就交卷（无自查）
    输入信号：首版输出直接返回，从不检查是否满足要求
    例子：写完报告不核对"论据是否充分"就提交
    本质：没有"生成后先自己评一遍"的环节
```
三种崩法对应反思的三种价值：崩法一需要「跨步骤记忆 + 重复检测」（第 02、06 节），崩法二需要「阶段性回顾整体策略」（第 03、06 节），崩法三需要「生成-批评-修订」（第 03 节）。这也解释了为什么反思不是单一技术，而是一组围绕「审视自己」展开的机制。

## 最小可运行演示

下面这段代码用「有反思」和「无反思」两个版本跑同一个「找路径」任务，直观对比二者的差别。它完全可运行、不需要任何模型或网络：
```python
def fake_exec(path):
    """模拟执行：只有 /var/logs 存在，其它路径都失败。"""
    if path == "/var/logs":
        return True, "ok: 3 files"
    return False, f"FileNotFoundError: {path}"


def agent_without_reflection(max_steps=5):
    """无反思：认死一个路径，反复重试。"""
    path = "/logs"
    for step in range(1, max_steps + 1):
        ok, obs = fake_exec(path)
        print(f"[无反思] 第{step}步: read_dir({path!r}) -> {obs}")
        if ok:
            return f"成功于第 {step} 步"
        # 没有反思：下一步还是同一个 path
    return "失败：耗尽步数仍在原地打转"


def agent_with_reflection(max_steps=5):
    """有反思：失败就记教训，重复失败就换策略。"""
    path = "/logs"
    tried = []                                  # 记忆：试过哪些路径
    for step in range(1, max_steps + 1):
        ok, obs = fake_exec(path)
        print(f"[有反思] 第{step}步: read_dir({path!r}) -> {obs}")
        if ok:
            return f"成功于第 {step} 步"
        tried.append(path)                      # 反思①：记下失败的路径
        if path in tried[:-1]:                  # 反思②：这个路径已失败过，别再试
            pass
        # 反思③：换策略——已知 /logs 失败，改猜带前缀的常见位置
        candidates = ["/var/logs", "/opt/logs"]
        path = next((c for c in candidates if c not in tried), path)
    return "失败：耗尽步数"


if __name__ == "__main__":
    print(agent_without_reflection())
    print("-" * 40)
    print(agent_with_reflection())
```
保存为 `reflection_vs_not.py`，运行 `python reflection_vs_not.py`，预期输出：
```text
[无反思] 第1步: read_dir('/logs') -> FileNotFoundError: /logs
[无反思] 第2步: read_dir('/logs') -> FileNotFoundError: /logs
[无反思] 第3步: read_dir('/logs') -> FileNotFoundError: /logs
[无反思] 第4步: read_dir('/logs') -> FileNotFoundError: /logs
[无反思] 第5步: read_dir('/logs') -> FileNotFoundError: /logs
失败：耗尽步数仍在原地打转
----------------------------------------
[有反思] 第1步: read_dir('/logs') -> FileNotFoundError: /logs
[有反思] 第2步: read_dir('/var/logs') -> ok: 3 files
成功于第 2 步
```
对比很清楚：无反思版本第 1 步失败后没有任何「记忆」和「换策略」，于是 5 步全部重复；有反思版本第 1 步失败后，把 `/logs` 记进 `tried`，第 2 步换到 `/var/logs` 就成功了。这段代码里的「换策略」是硬编码的规则；在真实 LLM Agent 里，这一步是模型读到「`/logs` 已失败」的反思后自然产生的——但机制完全一样：**失败 → 记住 → 换策略**。

## 真实系统对应

**官方公开机制**：Anthropic 在《Building Effective Agents》里公开描述了「Evaluator-Optimizer（评估-优化）」工作流——一个 LLM 生成、另一个 LLM 在循环中评估并给反馈，生成者据此迭代 [来源](https://www.anthropic.com/engineering/building-effective-agents)。这是「反思」在产品级工程实践里的一个公开形态。**通用工程模式**：把「执行」和「审视执行」分成两个逻辑层，是可迁移到任何 Agent 框架的做法。**教学参考实现**：上面的 `agent_with_reflection` 只是演示「失败→记忆→换策略」的最小骨架，不代表任何产品内部的重试或纠错逻辑。

需要明确边界：Anthropic 的文档描述了「有这样一种工作流模式」，但没有公开它内部用什么提示模板、什么阈值、如何判断「评估者满意」。这些是我们在第 03、05 节用教学代码演示的，属于推导而非产品承诺。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| Agent 反复重试同一个失败动作 | 循环里没有跨步骤记忆，无法识别「这步已经失败过」 | 打印每步 Action，注入一个必然失败的动作，观察是否重复 | 记录动作历史，检测「连续相同失败动作」并强制换策略 | 幂等的探测类动作（如轮询状态）本就该重复，不应误杀 |
| 沿错误假设一路改到底 | 只做局部反思，从不回顾「大方向对不对」 | 记录每轮改动点，观察是否始终集中在同一处 | 每 N 轮做一次「整体策略回顾」，允许推翻初始假设 | 方向已被外部验证正确时，频繁质疑反而降低效率 |
| 首版输出直接交卷、质量差 | 没有「生成后先自评一遍」的环节 | 对比「有无自查」两版输出的合格率 | 加入生成-批评-修订循环（见第 03 节） | 极简单、几乎不会错的任务加自查是浪费 |
| 加了反思反而更慢更贵 | 每一步都无脑反思 | 统计反思调用次数与其带来的成功率增量 | 只在失败/高风险步骤反思，成本与出错代价成正比 | 不可逆、高价值任务值得每步反思，不算浪费 |

## 思考：反思和 ReAct 里的 Thought 有什么本质区别？

### 回答

关键区别在「时间朝向」和「对象」。ReAct 的 `Thought` 是**向前看**：思考「下一步该做什么」，它属于执行层，是推进任务的一部分。反思是**向后看**：审视「刚才做过的行动质量如何、哪里错了、要不要换方向」，它属于监督层，是评价与修正。一个决定「往哪走」，一个判断「刚才走对了没」。

再补一刀：`Thought` 即使写得很详细，也可能建立在错误前提上（比如「bug 在函数 A」这个假设本身就错了），而它不会质疑这个前提；反思的职责恰恰是质疑前提。所以二者不是替代关系，而是互补——ReAct 提供推进力，反思提供纠偏力。

### 面试精简表达

Thought 是「往前想下一步」，反思是「回头看上一步」；前者推进，后者纠偏。没有反思的 ReAct 会「一次做错，一路错到底」。

## 思考：是不是所有 Agent 都应该加反思？

### 回答

不是。反思是有成本的（多一次或多轮模型调用、更高延迟），投入应与「出错代价」成正比。判断标准有三条：第一，任务是否容易出错且错误不易被后续步骤自然纠正；第二，出错的代价是否高（不可逆操作、高价值决策）；第三，是否存在**可靠的评价信号**——如果拿不到真实反馈，反思就是闭门造车，加了反而可能越改越错（这是第 04、06 节的核心）。三条都不满足的简单任务（比如「把一句话翻译成英文」这种一次成型、错了也好重来的），加反思是浪费。

### 反例

有人以为「反思一定提升质量」，于是给每一步都加反思。但如果评价信号本身不可靠（比如让模型自评一道数学题对不对，而模型本来就不会做），反思不但没用，还可能把原本蒙对的答案「改错」——DeepMind 的研究正是这个反例，我们在第 06 节详述 [来源](https://arxiv.org/abs/2310.01798)。

## 深入：为什么「元认知」这个类比是准确的，而不是过度拟人化

把反思叫「元认知」，容易被批评为过度拟人化——模型并没有真的「意识到自己错了」。这个批评部分成立，但类比在工程上仍然准确，原因在于**结构同构**而非「感受相同」。人类元认知的可观察特征是：在执行任务的同时，维护一个「对自己表现的评估」，并据此调整策略。反思机制在结构上做的是同一件事：在执行循环外，额外维护一个「对已完成动作的评估」，并把评估结果反馈回执行。

关键是不要把类比推过头。人类元认知伴随主观体验，反思机制没有；人类能在完全没有外部反馈时凭「感觉不对」纠错，而 DeepMind 的研究表明模型在纯推理任务上、没有外部反馈时，自我纠正往往无效甚至有害 [来源](https://arxiv.org/abs/2310.01798)。所以本章始终强调：反思的有效性建立在**外部可信反馈**之上，而不是模型「自己觉得对不对」。这一条会在第 04 节展开为「评价信号从哪来」，在第 06 节展开为「反思的边界」。把这条守住，「元认知」这个类比就既好用又不至于误导。
