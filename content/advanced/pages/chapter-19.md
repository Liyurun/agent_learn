## 一个真实的「三周卡在原地」学习故障

设想一位工程师小林，想在三周内把 Agent（智能体）能力练成，能写进简历。他第一天就照着某个「多 Agent 客服系统」教程开工：要同时搞懂工具定义、ReAct（Reasoning and Acting，推理与行动）循环、向量记忆、路由分诊、护栏五六件事。第三天，他的代码跑不通——模型有时不按格式输出、有时重复检索、有时记忆里全是「好的谢谢」这种噪声。他不知道是哪一层坏了，因为五层是一起上的。第十天，他放弃了，简历上只留下一个跑不起来的半成品。

复盘发现，问题不在于他不聪明，而在于**学习变量没有隔离**：五六个陌生概念一起涌进工作记忆，大脑直接过载。如果他改用「阶梯法」——第一周只练单工具 ReAct，第二周加多工具与记忆，第三周做规划、Agentic RAG（Retrieval-Augmented Generation，检索增强生成）与评估——每一级只新增一两个变量，卡住时新增的那层最可疑，三周结束他会有五六个可展示、能讲清设计权衡的小项目。这条阶梯，正是本章要一级一级跑给你看的。

## 你将得到什么

- 能说清「为什么按阶梯练」背后的工作记忆原理，并画出六级阶梯每一级「新增的那一个变量」。
- 能脱离框架、用几十行代码手写一个完整的 ReAct 循环，指着草稿纸说出每一步的 Thought / Action / Observation。
- 能把「多工具选对」这件事的成败定位到工具描述，并用一段可运行代码对照「清晰描述」与「模糊描述」的选择结果。
- 能区分短期记忆、长期记忆、工具观测三层，并用语义召回演示「跨会话记住用户偏好」。
- 能写出「先规划再执行」（plan-and-execute）的骨架，看它如何把一个多跳问题拆成有序子任务，失败时触发重规划。
- 能亲手对比传统 RAG 与 Agentic RAG，看到「控制权从代码转移到模型」这条全书最核心的分界线活生生地跑出来。
- 能用忠实度、答案相关性、上下文召回三个指标搭一套迷你回归评估集，用数字证明「升级到底值不值」。
- 能开出一张覆盖六级阶梯的生产建议清单，并回答与项目实战相关的多道思考题。

## 最小环境核验 / 热身

导读页先给一段不联网、不需要 API Key（Application Programming Interface Key，接口密钥）的热身代码，用来确认解释器可用，并把「六级阶梯各自新增什么变量」固化成一张可打印的清单——读完这一章你应能不看代码复述出来。
```python
import sys


def ladder_gain(level: int) -> str:
    table = {
        1: "单工具：跑通 ReAct 循环",
        2: "多工具：从能调到选对",
        3: "记忆：短期/长期/工具观测分层",
        4: "规划：先拆解再执行",
        5: "RAG：从固定检索到自主检索",
        6: "评估：用回归集守住质量",
    }
    return table.get(level, "未知阶梯")


def run() -> None:
    print(f"Python={sys.version_info.major}.{sys.version_info.minor}")
    for lv in range(1, 7):
        print(f"Level {lv} 新增能力：{ladder_gain(lv)}")
    print("热身通过：环境可用，可以开始逐级练习")


if __name__ == "__main__":
    run()
```
保存为 `warmup.py`，运行 `python warmup.py`。预期输出：
```text
Python=3.10
Level 1 新增能力：单工具：跑通 ReAct 循环
Level 2 新增能力：多工具：从能调到选对
Level 3 新增能力：记忆：短期/长期/工具观测分层
Level 4 新增能力：规划：先拆解再执行
Level 5 新增能力：RAG：从固定检索到自主检索
Level 6 新增能力：评估：用回归集守住质量
热身通过：环境可用，可以开始逐级练习
```
Python 小版本可能不同，但需不低于 3.10（本章代码用到 `list[dict]` 等注解写法）。这段热身没有任何魔法，它的意义是：让你在开始前先把「本章要一级一级点亮什么能力」在脑子里排好序。
