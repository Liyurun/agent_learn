## 真实问题

前面三节暴露了一个必须一次性解决的组合问题：贯穿案例里，用户此刻问「头痛能吃阿司匹林或含青霉素的药吗」，记忆库里有四条记录，其中 M1「用户对青霉素过敏，正在服用华法林抗凝」是救命的硬事实，但它的字面相关度**不是最高**的——字面最像的是 M4「用户今天出现头痛」。如果只按第 03 节的纯相关度检索，M4 会排第一，M1 可能掉出 Top-K，模型就看不到过敏史。这一节从零手写一个**带综合打分的向量记忆**：把「相关度、重要度、近因」三个信号加权融合，让 M1 即便字面不匹配也能被召回。全程纯 Python、无需 API Key、无需外部依赖、输出确定。

## 原理：从纯相关度到综合打分

Generative Agents 论文提出了一个被广泛借鉴的记忆检索打分函数：**综合分 = 近因（recency）+ 重要度（importance）+ 相关度（relevance）**，三者归一化后加权求和，取分数最高的若干条进入上下文 [来源](https://arxiv.org/abs/2304.03442)。其中近因用指数衰减（越近越高），重要度是写入时打的分（越关键越高），相关度是查询与记忆的语义相似度。论文使用的权重是三者各占一定比例（相关度权重最大），核心思想是：**检索不该只看「像不像」，还要看「新不新」和「重不重要」。**

这恰好解决本节的真实问题。M1 的相关度低（字面不匹配），但重要度极高（imp=9，安全硬事实）；只要重要度的权重足够，综合分就能把它顶上来。这也是把第 04 节「重要度打分」和第 03 节「向量相似度」真正接起来的地方。
```text
纯相关度检索：           综合打分检索：
  排序只看 relevance        score = w1·recency + w2·importance + w3·relevance
  → M4(头痛) 排第一          → M1(过敏) 靠 importance 被顶上来
  → M1(过敏) 可能漏掉        → 救命硬事实不再被字面相关度埋没
```
## 完整可运行实现

下面是完整的向量记忆，用**特征哈希**做玩具 embedding（把字符二元组散列到固定维度并归一化），比第 03 节的字袋更接近「稠密向量」的形态，同时依然零依赖、确定性。它同时提供 `search`（纯相关度）和 `retrieve`（综合打分）两个方法，方便对照：
```python
"""纯标准库实现的语义记忆检索（可运行、确定性）。"""
import math
import hashlib
from dataclasses import dataclass, field

DIM = 64  # 玩具 embedding 维度；真实模型是 1536/3072 维

def embed(text: str) -> list[float]:
    """特征哈希 embedding：字符二元组散列到固定维度并归一化。
    教学玩具，近似字面重合；真实系统用训练好的模型看深层语义。"""
    vec = [0.0] * DIM
    grams = [text[i:i + 2] for i in range(len(text) - 1)] or [text]
    for g in grams:
        h = int(hashlib.md5(g.encode("utf-8")).hexdigest(), 16)
        idx = h % DIM
        sign = 1.0 if (h // DIM) % 2 == 0 else -1.0
        vec[idx] += sign
    norm = math.sqrt(sum(v * v for v in vec))
    return [v / norm for v in vec] if norm else vec

def cosine(a: list[float], b: list[float]) -> float:
    return sum(x * y for x, y in zip(a, b))  # 已归一化，点积即余弦

@dataclass
class MemoryItem:
    text: str
    hours_ago: float          # 距当前多少小时（越小越新）
    importance: int           # 1-10，写入时打分
    vec: list[float] = field(default_factory=list)

class VectorMemory:
    def __init__(self, decay: float = 0.98):
        self.items: list[MemoryItem] = []
        self.decay = decay

    def add(self, text: str, hours_ago: float, importance: int) -> None:
        self.items.append(MemoryItem(text, hours_ago, importance, embed(text)))

    def search(self, query: str, top_k: int = 3):
        """纯相关度检索（第 03 节的做法）。"""
        q = embed(query)
        scored = [(cosine(q, it.vec), it.text) for it in self.items]
        scored.sort(key=lambda x: x[0], reverse=True)
        return scored[:top_k]

    def retrieve(self, query: str, top_k: int = 3):
        """Generative Agents 式综合打分：近因 + 重要度 + 相关度。"""
        q = embed(query)
        rows = []
        for it in self.items:
            recency = self.decay ** it.hours_ago       # 指数衰减
            importance = it.importance / 10.0
            relevance = max(0.0, cosine(q, it.vec))
            composite = 0.5 * recency + 2.0 * importance + 3.0 * relevance
            rows.append((composite, recency, importance, relevance, it.text))
        rows.sort(key=lambda r: r[0], reverse=True)
        return rows[:top_k]

def main() -> None:
    mem = VectorMemory()
    mem.add("用户对青霉素过敏，正在服用华法林抗凝", hours_ago=1560, importance=9)
    mem.add("用户最近开始跑马拉松，每周三次", hours_ago=840, importance=5)
    mem.add("用户喜欢清淡口味，不吃辣", hours_ago=600, importance=4)
    mem.add("用户今天出现头痛，问该吃什么药", hours_ago=0, importance=6)

    q = "头痛能吃阿司匹林或含青霉素的药吗"
    print("=== 纯相关度检索 ===")
    for score, text in mem.search(q, top_k=3):
        print(f"  rel={score:.3f}  {text}")

    print("\n=== 综合检索（近因+重要度+相关度）===")
    for comp, rec, imp, rel, text in mem.retrieve(q, top_k=3):
        print(f"  score={comp:.3f} (rec={rec:.2f} imp={imp:.2f} rel={rel:.2f})  {text}")

if __name__ == "__main__":
    main()
```

## 逐行读懂输出

对照两段输出，能看清综合打分到底改变了什么：

- **纯相关度检索**里，「今天头痛」以 rel=0.224 排第一（字面最像查询），「青霉素过敏」rel=0.067 排第二，「清淡口味」和「马拉松」几乎为零。如果 `top_k` 收紧到 2，过敏史勉强还在；若库里再多几条字面更像「头痛/阿司匹林」的噪声，过敏史就会被挤出去——这正是纯相关度的危险。
- **综合检索**里，「青霉素过敏」的综合分冲到 2.000（主要来自 imp=0.90 × 权重 2.0 = 1.8），稳稳排进第二，即便它 rec=0.00（1560 小时前，近因衰减到近乎为零）、rel 只有 0.07。**重要度权重把这条救命事实从「字面不相关」的坑里拉了回来。** 这就是综合打分的价值：它不让高风险硬事实被字面相似度埋没。
- 「今天头痛」仍排第一是合理的——它既是本轮意图（rec=1.00）又有中等重要度，本就该进上下文。

一个诚实的边界：这里的玩具 embedding 只捕捉字面重合，所以 rel 值偏低且区分度有限；换成真实 embedding 模型，「含青霉素的药」与「青霉素过敏」的语义相关度会显著更高，两条路径的差距会缩小。但**综合打分的意义不因 embedding 强弱而消失**——即使语义模型很强，「近因」和「重要度」这两个维度也是纯相关度永远给不了的。想验证这一点，把 `retrieve` 里 `importance` 的权重从 2.0 改成 0，重跑一遍，会看到过敏史立刻掉到最后，这就是重要度权重的作用。

## 真实系统对应

**官方公开机制**：Generative Agents 论文公开了「recency + importance + relevance」三信号加权的记忆检索机制，以及用指数衰减建模近因、用模型对记忆打重要度分的做法 [来源](https://arxiv.org/abs/2304.03442)。LangGraph 提供跨线程的长期记忆 store，支持按命名空间存取，可在其上叠加语义检索 [来源](https://docs.langchain.com/oss/python/langgraph/persistence)。**通用工程模式**：把相关度、重要度、近因加权融合做检索排序，是可迁移的做法。**教学参考实现**：特征哈希 embedding、`DIM=64`、`decay=0.98`、权重 `0.5/2.0/3.0` 都是为可运行和确定性设的示例值，不代表任何论文或产品的确切参数；生产中应把 `embed` 换成真实模型、把线性扫描换成向量数据库的 ANN 索引，并用离线评估集调权重。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 高风险事实被字面相似度埋没 | 只用相关度排序 | 用贯穿案例对比 search 与 retrieve | 叠加重要度权重做综合打分 | 无风险差异的场景纯相关度够用 |
| 老旧信息始终压过新信息 | 近因权重过高或无衰减 | 调 decay 观察排序变化 | 校准衰减系数，重要事实不受近因惩罚 | 强时效任务可提高近因权重 |
| 权重拍脑袋、无法解释排序 | 未用评估集校准 | 固定查询集看排序是否符合预期 | 建离线评估集，网格搜索权重 | 早期原型可先用经验值 |
| 换 embedding 后相关度尺度变化 | 不同模型相似度分布不同 | 打印相关度分布直方图 | 换模型后重新校准权重与阈值 | 同模型可复用参数 |
| 综合分被单一维度主导 | 某维度未归一化到同尺度 | 打印各维度原始值 | 三个信号都归一化到 [0,1] 再加权 | — |
| 检索结果无法追溯来源 | 记忆条目未存元数据 | 检查召回条目有无 source/时间戳 | 每条记忆存来源、时间、重要度 | — |

## 思考：既然真实 embedding 模型语义能力很强，为什么还要叠加重要度和近因？

### 回答

因为相关度、重要度、近因回答的是**三个不同的问题**，谁也替代不了谁。相关度回答「这条记忆和当前问题像不像」；重要度回答「这条记忆重不重要、能不能出错」；近因回答「这条记忆新不新、是否可能已过时」。一条「青霉素过敏」和「头痛吃什么药」的语义相关度可能中等，但它的重要度极高——漏掉它的代价是医疗事故，不是「答得不够好」。再强的 embedding 也只优化相关度这一维，它不知道「过敏史比口味偏好更不能漏」，也不知道「三年前的地址可能已经搬了」。综合打分的本质是把「语义匹配」和「业务风险/时效」这两类正交的判断都纳入排序，让检索服务于任务目标而非单纯的相似度。

### 面试精简表达

相关度管「像不像」，重要度管「能不能错」，近因管「过没过时」；三者正交，强 embedding 只提升第一维，另两维必须显式加权。

## 扩展实验：把玩具组件替换成生产组件

这个实战刻意做成「可替换」的骨架，方便你逐步升级到生产：

- **替换 embedding**：把 `embed` 换成对 OpenAI text-embedding-3 或本地 BGE/m3e 模型的调用，返回真实稠密向量。检索逻辑（cosine、综合打分）完全不用改，因为它们只依赖「向量」这个抽象。
- **替换检索后端**：库规模上千后，把 `VectorMemory` 内部的线性扫描换成向量数据库（Faiss、Milvus、pgvector 等）的 ANN 索引，`retrieve` 的综合打分可以在 ANN 召回一批候选后做重排。
- **接入写入/遗忘**：把第 04 节的写入闸门、TTL、淘汰逻辑套在 `add` 上，让记忆库长期保持高信噪比。
- **加元数据与来源**：给 `MemoryItem` 增加 `source`、`created_at`、`confirmed` 字段，检索结果就能追溯来源、支持第 07 节的审计。

这样，从这段几十行的玩具代码到生产级混合记忆系统，中间没有任何「魔法」——每一步替换都对应本章前面讲过的一个原理。骨架不变，组件升级，这正是把教学代码迁移到生产的正确姿势。
