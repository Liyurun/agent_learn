## 真实问题

一家做保险智能核算的团队上线了一个报价 Agent。用户问：“30 岁男性，年缴 8000，缴 20 年，前 5 年有 3% 的额外分红，第 6 年起没有，总共缴多少、大概能拿回多少？”第一版直接让模型“给出结果”，模型自信地回答“总缴 16 万，大约能拿回 21 万”。财务复核发现：总缴其实是 8000×20=16 万（这个对了），但“21 万”是模型凭感觉编的——它把“前 5 年 3% 分红”当成了“整个 20 年 3% 复利”，多算了近 3 万。更糟的是，模型的回答里没有任何中间步骤，复核人员无法定位它错在哪一步，只能整段推翻重来。

团队做的唯一改动是：在提示词里加一句“请一步步列出计算过程，再给结论”。改动后模型输出了“年缴 8000 → 20 年总缴 160000 → 前 5 年分红 8000×3%×5=1200 → …”这样的分步过程，复核人员一眼就看到“分红只应算前 5 年”被正确执行了，即使某步算错也能精确定位。这就是 **CoT（Chain-of-Thought，思维链）** 的两个价值：**提升复杂推理准确率**，以及**让推理过程从黑箱变透明、可审计**。

## 原理：CoT 是规划的雏形

**CoT（Chain-of-Thought，思维链）** 是最基础的推理增强技巧。核心做法极其简单：引导模型在给出答案前，先输出中间推理步骤——最经典的触发语就是“让我们一步步思考（Let's think step by step）”。它的价值在于：把测试期（推理期）的算力，用于把一个大任务在“思考空间”里拆成一串小步，从而显著提升复杂推理任务的准确率。原论文在多个算术、常识与符号推理基准上验证了这一点，并指出 CoT 能力在模型规模足够大时才明显“涌现” [来源](https://arxiv.org/abs/2201.11903)。
```text
普通提问:  17 × 24 = ?           → 模型可能直接猜错
CoT 提问:  17 × 24 = ?,一步步算  → 17×20 + 17×4
                                   = 340 + 68 = 408 ✓
```
CoT 是“规划”的雏形——它让模型的推理过程从“黑箱一步到位”变成“透明的多步展开”。但要牢记它的两个内在局限：第一，CoT 是**单条线性路径**，一旦某一步错了，后面全错，没有回溯能力；第二，它只在模型“脑内”推理，**无法与外部世界交互**，信息全靠模型记忆，容易在需要实时/私有数据时产生幻觉。这两个局限分别由后面的 ToT（多路径）和 ReAct（行动）来补齐。

## CoT 的变体家族：从 Zero-shot 到自洽

CoT 不是一个单点技巧，而是一个技巧家族。理解这些变体，能帮你在实际项目里选对工具：

| 变体 | 做法 | 适用场景 | 相对成本 |
|---|---|---|---|
| Zero-shot CoT | 只加一句“让我们一步步思考” | 快速验证、无示例可用时 | 1× |
| Few-shot CoT | 在 prompt 里给几个“带推理过程”的范例 | 有代表性例题、需要固定推理格式 | 1×（但 prompt 更长） |
| Self-Consistency（自洽） | 采样多条推理路径，对最终答案做多数投票 | 高价值、容错低的推理题 | N× |
| Least-to-Most | 先让模型把问题拆成子问题，再逐个解 | 需要显式分解的组合型难题 | 视子问题数 |

其中 **Least-to-Most（由少到多）** 值得一提：它先让模型把复杂问题分解为一串由易到难的子问题，再依次求解，后一个子问题可以复用前面子问题的答案，特别适合“泛化到比示例更难的问题”这类组合型难题 [来源](https://arxiv.org/abs/2205.10625)。而 **Self-Consistency（自洽解码）** 则是最常用、性价比最稳的增强手段，下面单独展开。

## Self-Consistency：用多条路径的共识纠偏

Self-Consistency 的思路是：既然单条推理链可能在某一步出错，那就用不同的随机性（温度大于 0）采样出 N 条推理链，看哪个“最终答案”出现次数最多就选它。原论文把它描述为“替换贪心解码的一种解码策略”：先采样一组多样的推理路径，再对最终答案做边缘化（多数投票），在多个算术与常识推理基准上稳定、显著地提升准确率，且无需额外训练或辅助模型 [来源](https://arxiv.org/abs/2203.11171)。

它背后有一个朴素的直觉——**通往正确答案的路可能有很多条，但错误往往各错各的。** 正确答案会被多条路径“共识”出来，而错误答案分散、难以形成多数。
```text
Self-Consistency 示意:
  问题 ──┬─▶ 推理链1 ──▶ 答案 = 408
         ├─▶ 推理链2 ──▶ 答案 = 408
         ├─▶ 推理链3 ──▶ 答案 = 412   (某步算错)
         └─▶ 推理链4 ──▶ 答案 = 408
                          ↓
                   多数投票 ──▶ 408 ✓
```
代价当然是**成本翻 N 倍**——你要跑 N 次推理。所以自洽只用在那些“答对的价值远高于多花几次 API 调用”的场景，比如高价值报价、医疗辅助计算、关键数值核算。

## 最小可运行演示

下面这段可运行的 Python 用一个“伪模型”演示自洽的投票逻辑。`fake_llm_reason` 模拟一次带 CoT 的采样：75% 概率算对（408），25% 概率某步算错（412）。真实场景里，把它换成一次温度大于 0 的 LLM 采样即可。
```python
import random
from collections import Counter

def fake_llm_reason() -> tuple[str, str]:
    """模拟一次带 CoT 的采样:多数算对(408),偶尔某步算错(412)。
    真实场景换成一次温度大于 0 的 LLM 采样。"""
    if random.random() < 0.75:
        return "17x20=340; 17x4=68; 340+68=408", "408"
    return "17x20=340; 17x4=72; 340+72=412", "412"

def self_consistency(n: int = 5) -> str:
    answers = []
    for i in range(n):                      # 用不同随机性采样 n 条链
        steps, ans = fake_llm_reason()
        print(f"  链{i + 1}: {steps} -> {ans}")
        answers.append(ans)
    winner, _ = Counter(answers).most_common(1)[0]
    print(f"投票分布: {dict(Counter(answers))} -> 采用 {winner}")
    return winner

def main() -> None:
    random.seed(6)
    print("单次 CoT:", fake_llm_reason()[1])
    print("Self-Consistency:")
    print("最终答案:", self_consistency(5))

if __name__ == "__main__":
    main()
```
保存为 `self_consistency.py`，运行 `python self_consistency.py`。预期输出为：
```text
单次 CoT: 412
Self-Consistency:
  链1: 17x20=340; 17x4=72; 340+72=412 -> 412
  链2: 17x20=340; 17x4=68; 340+68=408 -> 408
  链3: 17x20=340; 17x4=68; 340+68=408 -> 408
  链4: 17x20=340; 17x4=68; 340+68=408 -> 408
  链5: 17x20=340; 17x4=68; 340+68=408 -> 408
投票分布: {'412': 1, '408': 4} -> 采用 408
最终答案: 408
```
注意这个输出的巧妙之处：`random.seed(6)` 下，**单次 CoT 恰好撞上了出错的那次（412）**，而自洽通过 5 条链投票，把答案稳稳纠回 408。这正是“用成本换可靠性”的直观体现。逐段讲解：

- `fake_llm_reason`：模拟一次 CoT 推理。真实工程里，这里就是“带 CoT 提示的一次 LLM 采样”，注意采样温度必须大于 0，否则每次结果一样，投票就没意义了。
- `self_consistency` 里的 `for` 循环：这就是自洽的核心——重复采样。每次采样因为随机性走出不同的推理链。
- `Counter(answers).most_common(1)`：统计所有最终答案的出现频次，取最高票。即便个别链算错（412），只要多数链算对（408），投票就能纠偏。

如果把 `random.seed(6)` 改成别的种子，单次 CoT 大概率会命中 408，但自洽的最终答案几乎总是稳定在 408——这就是“多条独立链共识”带来的鲁棒性。

## 真实系统对应

**官方公开机制**：CoT 论文（Wei et al., 2022）在算术、常识、符号推理基准上验证了“输出中间推理步骤能显著提升大模型准确率” [来源](https://arxiv.org/abs/2201.11903)；Self-Consistency 论文（Wang et al., 2022）公开了“采样多条链 + 多数投票”这一无需训练的解码策略及其在 GSM8K 等基准上的增益 [来源](https://arxiv.org/abs/2203.11171)。**通用工程模式**：把“采样多次 + 投票”封装成一个可复用的可靠性开关，按任务价值决定 N 的大小。**教学参考实现**：上面的 `fake_llm_reason` 用固定概率模拟采样，不代表任何模型的真实错误率；真实模型的错误分布依任务、提示、温度而变。

需要明确边界：论文报告的准确率增益是特定模型、特定基准下的实验结果，不能直接搬到你的业务上当作承诺。自洽是否值得，取决于你自己任务上“答对的边际收益”是否超过“N 倍推理成本”。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 自洽“投票”结果每次都一样，没有纠偏效果 | 采样温度为 0（贪心解码），N 条链完全相同 | 打印每条链，检查是否全同 | 采样温度设为大于 0（如 0.5～0.8） | 需要完全确定性输出的场景不能用自洽 |
| 简单事实题加 CoT 反而变慢变错 | 过度思考（overthinking），把对的绕错 | 对比加/不加 CoT 的准确率与延迟 | 事实召回类走短路径，不强加 CoT | 多步推理题仍需展开 |
| CoT 很长但结论仍错 | 某个中间步骤错误被后续继承 | 逐步核对中间结果，定位首个错误步 | 对关键步骤加校验或改用自洽 | 无法验证的开放推理只能靠多链 |
| few-shot CoT 换个题就失灵 | 示例的推理格式与新题不匹配 | 替换示例做消融 | 用与目标题型同构的示例 | 示例过多会挤占上下文预算 |
| 自洽成本失控 | 对所有请求无差别开 N=10 | 统计每请求的采样次数与成本 | 按任务价值分级设 N，低价值 N=1 | 高价值高风险题不宜省 N |

## 思考：Self-Consistency 为什么能纠偏？它的代价是什么？什么场景才值得用？

### 回答

能纠偏，是因为“通往正确答案的路往往有多条，而错误各错各的”：正确答案容易被多条独立采样的推理链共识出来形成多数，错误答案则分散、难以聚集成多数，于是多数投票能滤掉零星错误。代价是成本随 N 线性增长（跑 N 次推理，延迟和费用都是 N 倍），且要求采样温度大于 0 才有多样性。值得用的场景是“答对的边际价值远高于 N 倍推理成本”的高价值、低容错任务，比如关键数值核算、医疗/金融辅助计算；对低价值、高频、或要求确定性输出的请求则不适合。

### 反例

如果任务本身是“事实召回”（法国首都是哪），错误不是“各错各的”而是“系统性地缺知识”，那么采样 N 次只会 N 次给出同一个错误答案，投票无法纠偏——此时该做的是接入检索（RAG，Retrieval-Augmented Generation，检索增强生成）或工具，而不是加大 N。

## 思考：CoT 让准确率上升，是不是意味着推理链越长越好？

### 回答

不是。CoT 的收益来自“把该分步的计算摊开”，而不是“字数越多越好”。对简单问题强加长 CoT，会出现“过度思考”：模型在冗长推理中引入本不存在的复杂度，反而把原本正确的直觉答案绕错，同时白白消耗 token 和延迟。正确做法是按任务匹配推理深度——事实召回类走短路径，多步推理类才展开 CoT，高价值难题再叠加自洽。推理链的长度应由任务的内在步骤数决定，而非人为拉长。

## 机制推导：为什么中间步骤能“落地”成算力

把 CoT 放回自回归机制看会更清楚。模型每生成一个 token，都会把它拼回输入序列，作为下一次前向传播的一部分。因此“17×20=340”这串中间 token 一旦生成，就成了后续推理的既定事实，模型在算“340+68”时不必再重新推导“17×20”，可以直接引用。这等价于把一次深层计算，拆成了若干次浅层计算，每次浅层计算的结果被“物化”成上下文里的文字。

这也解释了两个现象。其一，CoT 在小模型上收益有限、在大模型上才明显——因为“把中间步骤写对”本身就需要足够的单步能力，小模型连中间步骤都写错，摊开也没用，这正是论文强调 CoT 是“涌现能力”的原因 [来源](https://arxiv.org/abs/2201.11903)。其二，中间步骤一旦写错就会被后续继承，因为它已经成了“既定前缀”，模型不会回头质疑自己刚写下的东西——这正是单链 CoT 的致命弱点，也是自洽（多链投票）和 ToT（评估回溯）要解决的核心问题。

## 优化前后对比

| 维度 | 直接要答案 | Zero-shot CoT | Self-Consistency |
|---|---|---|---|
| 可审计性 | 无，结论是黑箱 | 有，中间步骤可核对 | 有，且能看到多链分歧 |
| 单步错误处理 | 无法发现 | 可定位但会被继承 | 多数投票可纠零星错误 |
| 成本 | 1× | 1×（输出更长） | N× |
| 外部信息 | 不可访问 | 不可访问 | 不可访问 |
| 适用 | 简单事实题 | 多步推理题 | 高价值低容错推理题 |

这张表清楚地显示：CoT 家族解决的是“纯推理”的可靠性与可审计性，但**始终有一条它跨不过的红线——无法访问外部世界**。当任务需要查实时汇率、查数据库、调计算器时，再强的 CoT 也补不上“没有观察”的缺口。这正是下一节 ReAct 要登场的地方。
