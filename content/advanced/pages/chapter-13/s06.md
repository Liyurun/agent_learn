## 真实问题

前五节把「透明内核、代码即动作、ReAct（Reasoning and Acting，推理与行动）循环、工具描述、安全执行」分别拆开讲清了，但面试官真正想看的、也是把知识焊死的唯一办法，是这一句追问：「不用任何框架，你能不能从零写一个能跑的 CodeAgent 出来？」很多人这时才发现，自己会「调 `agent.run`」，却说不清那一行背后自己该写哪几个部件、部件之间怎么接。

这一节就补上这最后一块拼图：用不到一百三十行纯 Python、不联网、不需要 API（Application Programming Interface，应用程序编程接口）Key、也不安装 smolagents，手写一个迷你 CodeAgent，把前五节的机制固化成四个可测试、可打印每一步的部件。跑起来你会看到模型先写了一段把工具名拼错的代码（报 `NameError`）、读到报错后自我纠错、算出合计、判断预算、最后调用 `final_answer` 自然终止的完整闭环。**能亲手写出这一百多行，你对「smolagents 到底在替你做什么」的理解，就从「会用」升级成了「能造」。**

## 原理：CodeAgent 的四个核心部件

真实 smolagents 的内核虽然做了大量工程封装，但把它抽象到最小，一个能跑的 CodeAgent 只需要四个部件，缺一不可：
```text
┌────────────────────────────────────────────────────────────┐
│ 迷你 CodeAgent 的四个部件（对应前五节）                        │
│                                                              │
│ ① 工具注册表 ToolRegistry ── 把普通函数登记成工具，并生成      │
│    「工具说明书」拼进提示（对应第 4 节：描述即提示词）          │
│                                                              │
│ ② 受限执行器 RestrictedExecutor ── 用 AST（Abstract Syntax   │
│    Tree，抽象语法树）白名单拒绝 import 等危险节点，捕获 print   │
│    输出与异常作为 Observation（对应第 5 节：不是裸 exec）      │
│                                                              │
│ ③ 确定性假模型 ScriptedModel ── 按脚本产出代码动作，让输出可   │
│    逐字复核（教学参考实现，替代真实 LLM）                      │
│                                                              │
│ ④ 带上限的主循环 run() ── 调模型→执行→捕获 Observation→判断   │
│    final_answer→回填历史，受 max_steps 兜底（对应第 3 节循环） │
└────────────────────────────────────────────────────────────┘
```
四个部件的接线方式，正是第 3 节那张循环图的代码化：主循环④每一轮先向模型③要一个「代码动作」，把代码交给执行器②运行，执行器用工具注册表①提供的函数作为可调用环境，执行结果（`print` 输出、返回值或报错）被捕获成 Observation 回填历史；只要代码里调用了 `final_answer` 就自然终止，否则进下一轮，直到触顶 `max_steps` 强制降级。

## 工程边界

这份代码是**教学参考实现**，三个部件都做了刻意简化，必须诚实说清，避免你把它当安全边界或产品实现：`ScriptedModel` 是确定性假模型，用固定脚本产出代码，让输出可逐字复核，不代表任何厂商的推理逻辑；`RestrictedExecutor` 的 AST 白名单只演示「拒绝 import、不是裸 `exec`」的思路，**它绝不是安全边界**——真实不可信代码必须进 E2B / Docker / Wasm 等隔离执行器（第 5 节已反复强调）；`final_answer` 被实现成一个普通可调用对象，呼应第 3 节「终止也是一次工具调用」的设计。这份实现的价值不在「能上生产」，而在「能让你把前五节的机制在一个文件里全部看清、亲手接通」。

## 最小可运行演示：一百多行手写 CodeAgent

下面是完整实现，一个文件即可运行，不联网、不需要任何密钥与第三方库。它复用本章贯穿任务——「把 100 美元、80 欧元、5000 日元换成人民币，合计是否超过 2000 元预算」，并特意让假模型第一轮写错工具名，好让你看到「报错 → 自我纠错」的真实循环。
```python
"""端到端实战：手写一个离线迷你 CodeAgent（纯 Python，无需 API Key，无需安装 smolagents）。

它复刻 smolagents CodeAgent 的四个核心部件：
  1) 工具注册表：把普通函数登记成 Agent 可调用的工具
  2) 受限执行器：只用 AST 白名单允许的操作，模仿『不是裸 exec』的思路（教学级，非安全边界）
  3) 确定性假模型：按脚本产出代码动作，让输出可逐字复核
  4) 带 max_steps 上限的主循环：解析代码→执行→捕获 Observation→判断 final_answer→回填

贯穿任务：把 100 美元、80 欧元、5000 日元换成人民币，合计是否超过 2000 元预算？
"""
from __future__ import annotations
import ast
from dataclasses import dataclass, field


## ---------- 1. 工具注册表 ----------
class ToolRegistry:
    def __init__(self) -> None:
        self._tools: dict = {}

    def register(self, name: str, fn, description: str) -> None:
        self._tools[name] = {"fn": fn, "description": description}

    def as_dict(self) -> dict:
        return {name: t["fn"] for name, t in self._tools.items()}

    def manual(self) -> str:
        ## 工具说明书——真实 smolagents 会把它拼进系统提示（第 4 节）
        return "\n".join(f"- {n}: {t['description']}" for n, t in self._tools.items())


## ---------- 2. 受限执行器（AST 白名单，教学级，非安全边界）----------
class SecurityError(Exception):
    pass


def check_ast(code: str) -> None:
    """扫描 AST，拒绝白名单外的节点（如 import）——模仿『不是裸 exec』的思路。"""
    tree = ast.parse(code)
    for node in ast.walk(tree):
        if isinstance(node, (ast.Import, ast.ImportFrom)):
            raise SecurityError(f"禁止 import（不可信操作）：{ast.dump(node)[:40]}")


class RestrictedExecutor:
    """在受限命名空间里执行代码；捕获 print 输出与异常作为 Observation。"""
    def __init__(self, tools: dict) -> None:
        self.buffer: list[str] = []
        self.answer = None

        def _print(*args):
            self.buffer.append(" ".join(map(str, args)))

        def _final_answer(x):
            self.answer = x

        self.env = {"print": _print, "final_answer": _final_answer,
                    "sum": sum, "round": round, **tools}

    def execute(self, code: str) -> tuple[str, bool]:
        """返回 (observation, is_error)。"""
        self.buffer.clear()
        try:
            check_ast(code)                       ## 关口：AST 白名单校验（教学级）
            exec(compile(code, "<agent>", "exec"), self.env)  ## 受限命名空间执行
        except SecurityError as exc:
            return f"安全拒绝：{exc}", True
        except Exception as exc:                  ## 执行异常转成给模型的信号，不崩溃
            return f"执行报错：{type(exc).__name__}: {exc}", True
        if self.answer is not None:
            return str(self.answer), False
        return (self.buffer[-1] if self.buffer else "(无输出)"), False


## ---------- 3. 确定性假模型 ----------
@dataclass
class ScriptedModel:
    """按脚本产出代码动作：先写一段含笔误的代码（报错），纠错后再算，最后 final_answer。"""
    step: int = 0

    def generate(self, history: list[dict]) -> dict:
        self.step += 1
        if self.step == 1:
            ## 第 1 步：模型写了段代码，但把工具名拼错成 get_rat（会报 NameError）
            return {"thought": "先查三种货币汇率并换算合计。",
                    "code": ('amounts = {"USD": 100, "EUR": 80, "JPY": 5000}\n'
                             'total = sum(get_rat(c) * n for c, n in amounts.items())\n'
                             'print(round(total, 2))')}
        if self.step == 2:
            ## 第 2 步：读到 NameError 后，模型自我纠错，用正确的 get_rate
            return {"thought": "工具名写错了，改成 get_rate 重试。",
                    "code": ('amounts = {"USD": 100, "EUR": 80, "JPY": 5000}\n'
                             'total = sum(get_rate(c) * n for c, n in amounts.items())\n'
                             'print(round(total, 2))')}
        if self.step == 3:
            ## 第 3 步：拿到合计，调用预算判断工具
            last = history[-1]["observation"]
            return {"thought": "算出合计了，判断是否超预算。",
                    "code": f'print(apply_budget({last}, 2000))'}
        ## 第 4 步：给最终答案，终止
        last = history[-1]["observation"]
        return {"thought": "给出最终结论。",
                "code": f'final_answer("{last}")'}


## ---------- 4. 工具实现 ----------
RATES = {"USD": 7.10, "EUR": 7.75, "JPY": 0.048}


def get_rate(currency: str) -> float:
    """查询 1 单位外币兑人民币的汇率。参数 currency 为三字母货币代码。"""
    return RATES[currency]


def apply_budget(total: float, limit: float) -> str:
    """判断合计金额 total 是否超过预算 limit，返回一句结论。"""
    return f"合计 {total} 元，{'超过' if total > limit else '未超过'}预算 {limit} 元"


## ---------- 5. 主循环 ----------
@dataclass
class MiniCodeAgent:
    model: ScriptedModel
    registry: ToolRegistry
    max_steps: int = 6
    trace: list[str] = field(default_factory=list)

    def run(self, task: str) -> str:
        executor = RestrictedExecutor(self.registry.as_dict())
        history: list[dict] = []
        self.trace.append(f"任务：{task}")
        self.trace.append(f"可用工具：\n{self.registry.manual()}")
        for step in range(1, self.max_steps + 1):
            act = self.model.generate(history)             ## ① 调模型
            obs, is_err = executor.execute(act["code"])    ## ②③ 解析+执行，捕获 Observation
            tag = "ERR" if is_err else "OK"
            self.trace.append(
                f"[Step {step}] Thought: {act['thought']}\n"
                f"           Code: {act['code'].splitlines()[-1]} ...\n"
                f"           Observation[{tag}]: {obs}")
            if executor.answer is not None:                ## ④ final_answer=终止
                self.trace.append(f"[Step {step}] 命中 final_answer，循环结束")
                return str(executor.answer)
            history.append({"thought": act["thought"], "observation": obs})
        return "触及 max_steps 上限，强制降级返回"          ## 循环必须有终止兜底


def build_agent() -> MiniCodeAgent:
    reg = ToolRegistry()
    reg.register("get_rate", get_rate, "查询 1 单位外币兑人民币汇率，参数为三字母货币代码")
    reg.register("apply_budget", apply_budget, "判断合计金额是否超过预算，返回结论")
    return MiniCodeAgent(model=ScriptedModel(), registry=reg)


def run() -> None:
    agent = build_agent()
    answer = agent.run("把 100 美元、80 欧元、5000 日元换成人民币，合计是否超过 2000 元预算？")
    print("=== 迷你 CodeAgent 运行轨迹 ===")
    print("\n".join(agent.trace))
    print("=== 最终答案 ===")
    print(answer)


if __name__ == "__main__":
    run()
```
保存为 `mini_codeagent.py`，运行 `python mini_codeagent.py`。完整预期输出：
```text
=== 迷你 CodeAgent 运行轨迹 ===
任务：把 100 美元、80 欧元、5000 日元换成人民币，合计是否超过 2000 元预算？
可用工具：
- get_rate: 查询 1 单位外币兑人民币汇率，参数为三字母货币代码
- apply_budget: 判断合计金额是否超过预算，返回结论
[Step 1] Thought: 先查三种货币汇率并换算合计。
           Code: print(round(total, 2)) ...
           Observation[ERR]: 执行报错：NameError: name 'get_rat' is not defined
[Step 2] Thought: 工具名写错了，改成 get_rate 重试。
           Code: print(round(total, 2)) ...
           Observation[OK]: 1570.0
[Step 3] Thought: 算出合计了，判断是否超预算。
           Code: print(apply_budget(1570.0, 2000)) ...
           Observation[OK]: 合计 1570.0 元，未超过预算 2000 元
[Step 4] Thought: 给出最终结论。
           Code: final_answer("合计 1570.0 元，未超过预算 2000 元") ...
           Observation[OK]: 合计 1570.0 元，未超过预算 2000 元
[Step 4] 命中 final_answer，循环结束
=== 最终答案 ===
合计 1570.0 元，未超过预算 2000 元
```
逐帧解读这条轨迹，你会看到前五节的机制全部落地：

- **Step 1（报错也是一种 Observation）**：假模型故意把 `get_rate` 拼成 `get_rat`，执行器捕获到 `NameError`，把它转成 `Observation[ERR]` 回填历史，而**不是让整个 Agent 崩溃**——这正是第 5 节「错误变成模型能纠错的信号」的落地。
- **Step 2（自我纠错）**：模型读到上一轮的报错，改用正确的 `get_rate` 重试，解释器精确算出 `1570.0`（`100×7.10 + 80×7.75 + 5000×0.048 = 710 + 620 + 240 = 1570`）——确定性计算交给解释器，不靠模型心算（第 2 节）。
- **Step 3（组合调用）**：模型把上一轮的合计喂给 `apply_budget` 做预算判断，一段代码里连续调用工具（第 2 节代码即动作）。
- **Step 4（终止）**：调用 `final_answer` 自然终止，`executor.answer` 被赋值，主循环立刻返回——终止是一次普通工具调用的自然结果，不是外挂特判（第 3 节）。

把 `ScriptedModel` 换成真实的 `InferenceClientModel`、把 `RestrictedExecutor` 换成隔离沙箱、把 `get_rate` 换成真实汇率 API，这个主循环骨架一行都不用改——这就是「理解了骨架，就理解了所有 CodeAgent」。

## 真实系统对应

**官方公开机制**：smolagents 的 `CodeAgent` 正是「组装提示（含工具说明）→ 调模型得到含代码的文本 → 解析并执行代码 → 未调用 `final_answer` 则把执行日志存回记忆继续 → 调用 `final_answer` 则结束」这一循环，官方 README 直接给出了该 ReAct 循环图 [来源](https://github.com/huggingface/smolagents)；`final_answer` 作为一个工具、工具描述会进系统提示、执行器用 AST 而非裸 `exec`，都是官方公开机制 [来源](https://huggingface.co/docs/smolagents/guided_tour) [来源](https://huggingface.co/docs/smolagents/tutorials/secure_code_execution)。**通用工程模式**：把 Agent 拆成「工具注册 + 受限执行 + 模型 + 带上限主循环」四个部件，是可迁移到任何框架的骨架。**教学参考实现**：本节的 `ToolRegistry`、`RestrictedExecutor`、`ScriptedModel` 都是为在无网络无依赖下讲清机制而构造，AST 白名单只是「拒绝 import」的最小演示，绝非安全边界，也不代表 smolagents 内部执行器的确切实现。

需要点明边界：真实 smolagents 的执行器在 AST 校验上远比本节严格（逐节点求值、操作次数上限、导入白名单等），本节只挑「拒绝 import」一条来传达「不是裸 `exec`」的核心思路；真实模型也不会像 `ScriptedModel` 那样按固定脚本产出代码，它的措辞、纠错路径都会随模型变化。本节要你记住的是**结构**——四个部件如何接线成一个闭环，而不是某个版本的确切实现细节。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 一次工具名笔误让整个 Agent 崩溃 | 执行异常没被捕获成 Observation | 故意写错工具名看是否抛到主循环外 | 每次执行 try 捕获，转 is_error 回填 | 致命错误确需整体中止时例外 |
| 模型拿到报错却不纠错反复重试 | 报错文案太笼统模型读不懂 | 把报错改成一句「出错了」复现空转 | 回填具体异常类型与信息（如 NameError） | 模型能力上限仍需换更强后端 |
| 循环永不终止烧 token | 只靠 final_answer 没设上限 | 让假模型永不调 final_answer 复现 | for step in range(1, max_steps+1) 兜底 | 明确单步任务可不设循环 |
| 把教学 AST 白名单当安全边界上生产 | 误以为拒绝 import 就安全 | 构造绕过白名单的 attribute 访问复现 | 不可信代码一律进 E2B/Docker/Wasm | 完全可信内部代码风险较低 |
| final_answer 被调用后循环没停 | 主循环没在赋值后立即返回 | 让 final_answer 后还有代码复现多跑 | 检测到 answer 非空立刻 return | 需要收尾清理时显式处理 |
| Observation 拼错到别的步骤 | 回填历史时索引取错 | 打印每步 history 长度对不上复现 | 每轮末尾统一 append 一条记录 | 单步任务不涉及多轮回填 |
| 工具说明书没进提示模型不会用 | 忘了把 registry.manual() 拼进上下文 | 去掉 manual() 看模型是否乱调 | 每轮把工具说明书拼进提示（第 4 节） | 无工具的纯问答不涉及 |

## 思考：不用框架，从零写一个能跑的 CodeAgent，最少需要哪几个部件？

### 回答

最少需要四个部件，缺一不可，而且它们的接线方式就是 ReAct 循环的代码化。第一是**工具注册表**：把普通 Python 函数登记成 Agent 可调用的工具，并生成一份「工具说明书」拼进给模型的提示——因为模型只能用它「知道存在」的工具（第 4 节）。第二是**受限执行器**：负责把模型生成的代码跑起来，捕获 `print` 输出、返回值和异常作为 Observation；关键是它要**捕获异常而不是崩溃**，把报错转成模型能读懂的信号供其纠错，同时对不可信代码要用真正的沙箱（第 5 节），教学里可以用 AST 白名单演示「不是裸 `exec`」的思路。第三是**模型**：产出「思考 + 代码动作」，教学里可以用确定性假模型让输出可复核，生产里换成真实 LLM（Large Language Model，大语言模型）。第四是**带上限的主循环**：把前三者接起来——调模型、执行代码、捕获 Observation、判断是否调用了 `final_answer`（是则自然终止，否则回填历史进下一轮），并且**一定要有 `max_steps` 兜底**防止无限循环。把这四个部件在一个文件里写通、能打印出「报错→自我纠错→算出结果→终止」的完整轨迹，你就真正理解了 `agent.run` 那一行背后发生的全部事情。

### 面试精简表达

四个部件：①工具注册表（生成说明书进提示）②受限执行器（捕获输出/异常作 Observation，不可信代码要沙箱）③模型（产出思考+代码动作）④带 max_steps 上限的主循环（调模型→执行→回填→判 final_answer 终止）。它们接起来就是 ReAct 循环的代码化。

### 反例

一个常见反例是把执行器写成「直接 `exec`，出错就往上抛」。这样一旦模型写错一个工具名，异常会冲出主循环、整个 Agent 崩溃，模型也拿不到报错、无法自我纠错——本节的 Step 1 演示的正是「把 `NameError` 捕获成 `Observation[ERR]` 回填」的正确做法。另一个反例是「只靠 `final_answer` 终止、不设 `max_steps`」：只要模型陷入「换个关键词无限重试」的循环，token 就会一直烧，直到预算耗尽。这两个反例都印证了同一条原则：**执行器要把错误变成信号而非崩溃，循环要有硬上限兜底。**

## 深入：为什么「先写假模型」是学习 Agent 的最佳路径

本节最容易被忽略、却极具方法论价值的一点，是**用 `ScriptedModel` 这个确定性假模型替代真实 LLM**。很多人学 Agent 一上来就接真实模型，结果每次运行输出都不一样，循环走几步、模型怎么纠错都不可控，根本没法逐帧对照理解。而假模型把「模型这一环」固定成可复核的脚本，你就能把全部注意力放在**循环结构**上——它这一步产出什么代码、执行器怎么处理、Observation 怎么回填、什么时候终止，每一帧都可预测、可复现。

这套「先用假模型跑通结构，再换真实模型体会多变」的思路，贯穿本章：第 1 节的 `mini_loop.py`、第 3 节的 `react_trace.py`、本节的 `mini_codeagent.py`，都是同一方法的递进。它对应软件工程里的**依赖倒置与可测试性**——把「不确定、难复现」的外部依赖（真实模型、网络、汇率 API）抽象成可替换的接口，测试时注入确定性的假实现。你在第 14 章 PydanticAI 的依赖注入、第 15 章 LangGraph 的可测试节点里会再次遇到这个思想。**真正的高手不是先接最强的模型，而是先用假模型把骨架焊死，再让真实模型来填血肉。**
