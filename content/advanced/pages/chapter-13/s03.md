## 真实问题

面试现场，面试官问：「你说你懂 ReAct（Reasoning and Acting，推理与行动）循环，那具体讲讲每一步在做什么？」候选人张口就来：「Thought、Action、Observation 三个词循环。」面试官追问：「Action 具体是什么形态？Observation 从哪来？循环靠什么终止？」——候选人卡住了。他背过定义，但从没「看见」过一次真实运行，所以只能复述三个名词，说不出画面。

这是最典型的「学了理论却没有画面感」的困境。本节要做的，就是用 smolagents 的第一个 Agent，把 `Thought → Action → Observation` 从抽象概念变成你屏幕上逐字滚动的文字，让你不仅能背出三个词，还能具体说清每一步的形态、来源和终止条件。**跑过一次、逐帧读懂一次，胜过读十遍理论。**

## 原理：8 行代码背后的完整循环

这是本书第一个完整可运行的真实 smolagents Agent（来源：官方仓库示例）[来源](https://github.com/huggingface/smolagents)：
```python
from smolagents import CodeAgent, WebSearchTool, InferenceClientModel

agent = CodeAgent(
    tools=[WebSearchTool()],          # 给 Agent 装一个「联网搜索」工具
    model=InferenceClientModel(),      # 决策用的大语言模型（LLM）
    stream_outputs=True,               # 流式输出，能看到它的思考过程
)

agent.run("2026 年最流行的轻量化 Agent 框架有哪些？给我三条理由。")
```
运行后，你会看到 Agent 的完整轨迹：它先**思考**「我需要查最新信息」，然后生成一段**调用搜索工具的 Python 代码**并执行，拿到**搜索结果**后，再判断信息是否足够，最后综合出答案。把这个过程对照第 4 章的 ReAct 循环——`Thought → Action → Observation`——你会发现它们完全一致，smolagents 只是把这个循环用极简代码封装了起来。

这 8 行代码看着简单，但它正对应第 12 章说的「框架封装的七层劳动」。把幕后每一轮循环发生的事拆开：
```text
你写的一行：agent.run("...问题...")
          │
          ▼
┌──────────────────────────────────────────────────────┐
│ smolagents 内部（每一轮循环）                            │
│                                                        │
│  1. 组装 prompt：系统提示 + 工具说明 + 历史 + 你的问题     │
│  2. 调用 model → 模型返回一段含 Python 代码的文本         │
│  3. 从文本里解析出 ```py ... ``` 代码块                  │
│  4. 用 Python 执行器运行这段代码（可能调用了 web_search） │
│  5. 捕获执行结果 / print 输出 / 报错 → 作为 Observation  │
│  6. 把 Observation 拼回历史，判断是否调用了 final_answer │
│     ├─ 是 → 结束，返回答案                               │
│     └─ 否 → 回到第 1 步，进入下一轮（轮次 +1）           │
└──────────────────────────────────────────────────────┘
```
对照第 12 章的七层：第 1 步是「消息编排」，第 2 步用到「工具协议」（工具说明如何进 prompt），第 3 步是「输出解析」，第 4 步涉及「执行」，第 5-6 步是「状态管理 + 循环控制」，报错处理则贯穿其中。**你只写了一行 `agent.run`，框架把七层全默默做完了——这就是框架的价值，也是它的黑箱之处。而 smolagents 的好处是，这个黑箱是透明玻璃做的，你随时能看进去。**

## 现象与输入：一次真实运行的轨迹长什么样

`stream_outputs=True` 的意义在于把上面的循环「翻译」成你能读的日志。一次典型运行的轨迹长这样（示意，真实文本随模型而变）：
```text
━━━ Step 1 ━━━
Thought: 我需要最新信息，先联网搜索。
Code:
    results = web_search("2026 popular lightweight AI agent frameworks")
    print(results)
Observation: [搜索返回的若干条摘要文本...]

━━━ Step 2 ━━━
Thought: 信息够了，我来归纳三条理由并给出最终答案。
Code:
    final_answer("2026 年流行的轻量化框架有 smolagents、PydanticAI...三条理由：...")
Observation: (final_answer 被调用，循环结束)
```
**教学价值满分的地方**：你能亲眼看到「Thought（想）→ Code（做）→ Observation（看）」三段式在真实运行里逐字发生。第 4 章的 ReAct 循环，在这里从抽象概念变成了你屏幕上滚动的文字。把它拆成三个可回答的问题：

- **Action 是什么形态？** 在 smolagents 里，Action 就是一段可执行的 Python 代码（不是 JSON），这是 CodeAgent 的招牌。
- **Observation 从哪来？** 来自这段代码的执行结果——`print` 输出、返回值，或报错的 traceback（回溯）。
- **循环靠什么终止？** 靠代码里是否调用了 `final_answer`——调用了就结束，没调用就把 Observation 拼回历史进下一轮，直到触及 `max_steps` 上限强制停止。

## 最小可运行演示：不装 smolagents 也能看清循环

真实 smolagents 需要模型后端（可能没有稳定额度）。为了让你无论如何都能「看清循环」，下面用一个确定性假模型，完整复刻 CodeAgent 的循环轨迹，把每一步的 `Thought / Code / Observation` 都打印出来。它不联网、不需要 API（Application Programming Interface，应用程序编程接口）Key，用固定脚本让输出可逐字复核，正是「可执行版的 ReAct 轨迹」。
```python
"""复刻 CodeAgent 的 ReAct 循环轨迹（纯 Python，无需安装 smolagents，无需 API Key）。
用贯穿任务：查 3 种货币汇率、换算、判断是否超预算。"""
import re

## 固定假汇率（1 单位外币兑人民币）；真实项目里换成汇率 API
RATES = {"USD": 7.10, "EUR": 7.75, "JPY": 0.048}


class ScriptedModel:
    """确定性假模型：第 1 轮查汇率并计算，第 2 轮给最终答案。"""
    def __init__(self) -> None:
        self.step = 0

    def generate(self, history: list[dict]) -> dict:
        self.step += 1
        if self.step == 1:
            return {
                "thought": "我需要三种货币的汇率，用循环查出来再换算合计。",
                "code": (
                    'amounts = {"USD": 100, "EUR": 80, "JPY": 5000}\n'
                    'total = sum(get_rate(c) * n for c, n in amounts.items())\n'
                    'print(round(total, 2))'
                ),
            }
        last = history[-1]["observation"]
        return {
            "thought": "已拿到合计人民币金额，给出最终答案。",
            "code": f'final_answer("合计约 {last} 元人民币")',
        }


def get_rate(currency: str) -> float:      ## 这就是被代码动作调用的「工具」
    return RATES[currency]


def run() -> None:
    model, history, answer = ScriptedModel(), [], None

    def final_answer(x):
        nonlocal answer
        answer = x

    env = {"get_rate": get_rate, "final_answer": final_answer,
           "print": print, "round": round, "sum": sum}

    for step in range(1, 7):               ## max_steps=6 上限，防死循环
        act = model.generate(history)
        print(f"━━━ Step {step} ━━━")
        print(f"Thought: {act['thought']}")
        print(f"Code:\n    " + act["code"].replace("\n", "\n    "))
        buf = []
        env["print"] = lambda *a: buf.append(" ".join(map(str, a)))  ## 捕获 print 作 Observation
        exec(act["code"], env)             ## 执行代码动作（教学演示；生产必须沙箱，见第 5 节）
        obs = answer if answer is not None else (buf[-1] if buf else "(无输出)")
        print(f"Observation: {obs}\n")
        if answer is not None:             ## 调用了 final_answer = 自然终止
            print(f"循环结束（命中 final_answer）\nFINAL: {answer}")
            return
        history.append({"thought": act["thought"], "observation": obs})
    print("触及 max_steps 上限，强制降级返回")


if __name__ == "__main__":
    run()
```
保存为 `react_trace.py`，运行 `python react_trace.py`。完整预期输出：
```text
━━━ Step 1 ━━━
Thought: 我需要三种货币的汇率，用循环查出来再换算合计。
Code:
    amounts = {"USD": 100, "EUR": 80, "JPY": 5000}
    total = sum(get_rate(c) * n for c, n in amounts.items())
    print(round(total, 2))
Observation: 1570.0

━━━ Step 2 ━━━
Thought: 已拿到合计人民币金额，给出最终答案。
Code:
    final_answer("合计约 1570.0 元人民币")
Observation: 合计约 1570.0 元人民币

循环结束（命中 final_answer）
FINAL: 合计约 1570.0 元人民币
```
这段轨迹逐帧对应 ReAct：`Thought` 是模型生成的推理文本，`Code` 是 smolagents 里 Action 的具体形态（一段可执行代码），`Observation` 是这段代码的执行结果（`print` 输出或 `final_answer` 的值），三者拼回历史再进下一轮，直到 `final_answer` 终止。把 `ScriptedModel` 换成真实 `InferenceClientModel`、把 `get_rate` 换成真实汇率工具，这个循环骨架一行都不用改——这正是 ReAct 抽象的价值。注意第 1 轮的 `1570.0` 是解释器算出来的（`100×7.10 + 80×7.75 + 5000×0.048 = 710 + 620 + 240 = 1570`），不是模型心算——这正是「确定性计算交给解释器」的价值：结果永远精确、可复现。

## 真实系统对应

**官方公开机制**：smolagents 官方 README 直接给出了 CodeAgent 的 ReAct 循环图——把任务加入 memory、以聊天消息维护记忆、解析输出提取代码动作、未调用 `final_answer` 则存执行日志继续、调用 `final_answer` 则结束 [来源](https://github.com/huggingface/smolagents)；`stream_outputs`、`WebSearchTool`、`InferenceClientModel`、`final_answer` 都是官方公开的组件与机制 [来源](https://huggingface.co/docs/smolagents/guided_tour)。**通用工程模式**：把 Agent 建模成「Thought → Action → Observation」带上限循环，是可迁移到任何框架的骨架。**教学参考实现**：`ScriptedModel` 与用 `exec` 执行、用 lambda 捕获 `print` 仅为在无网络无依赖下复刻轨迹，不代表 smolagents 的真实执行方式（真实用 AST 解释执行，见第 5 节）。

需要点明边界：真实运行里 `Thought` 的措辞、模型是否一轮内多次调用工具、`WebSearchTool` 返回的具体内容都会随模型和网络变化，不像假模型那样可逐字复现。教学假模型的价值是让你先看清「循环结构」，真实模型的价值是让你体会「结构不变、内容多变」——两者结合，你对 ReAct 的理解才既有骨架又有血肉。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 只会背 ReAct 三个词说不出细节 | 没跑过、没看过真实轨迹 | 让人复述 Action 形态与 Observation 来源 | 开 stream_outputs 逐帧读一次运行 | 纯理论考试可能不深究 |
| 第一次跑不出思考过程 | 忘了开 stream_outputs=True | 关掉该参数只看到最终答案 | 学习期务必开启流式输出 | 生产为省日志可关闭 |
| 循环从不终止一直烧 token | 模型始终不调 final_answer | 提一个模型答不出会反复试的问题 | 设 max_steps 上限 + 系统提示强调 final_answer | 官方默认提示已含 final_answer 引导 |
| 换个弱模型就跑不出合法代码 | 代码动作对模型能力要求高 | 用能力差的模型跑复现 SyntaxError | 换更强模型后端 | 结构化任务可改 ToolCallingAgent |
| 把「模型联网查了」当事实排错 | 误以为模型直接执行了搜索 | 打印代码动作与执行时刻对比 | 记住执行发生在运行时（第 8 章铁律） | 服务端内置工具由厂商执行 |

## 思考：面试官问「ReAct 循环每一步具体在做什么」，跑过 smolagents 的人怎么答得比别人好？

### 回答

区别在于「有没有画面感」。没跑过的人只能复述三个名词：Thought、Action、Observation 循环。跑过 smolagents 的人能具体地说：Thought 是模型生成的一段推理文本，说明它下一步打算做什么；Action 在 smolagents 的 CodeAgent 里是一段可执行的 Python 代码（这是它区别于 JSON 工具调用的招牌），代码里可以循环调用工具、做组合计算；Observation 是这段代码的执行结果——`print` 输出、返回值，或者报错的 traceback；三者拼回历史后进入下一轮，直到模型生成的代码里调用了 `final_answer` 才自然终止，并且一定有 `max_steps` 上限兜底防止无限循环。更进一步，还能点明「模型只生成代码、真正执行发生在运行时」这条第 8 章的铁律，以及「确定性计算交给解释器比模型心算更准」这个代码动作的红利。从名词到形态、来源、终止条件、再到底层原则，层次一下就出来了，和背书的人立刻拉开差距。

### 面试精简表达

Thought 是模型推理文本，Action 在 smolagents 里是可执行代码（非 JSON），Observation 是代码执行结果（print/返回值/报错），三者拼回历史进下一轮，直到调用 final_answer 终止，且有 max_steps 兜底。

## 深入：为什么 final_answer 被设计成一个「工具」而不是特殊关键字

一个容易被忽略却极能体现设计品味的细节：smolagents 让「结束循环」这件事通过调用 `final_answer(...)` 这个「工具」来完成，而不是用某个特殊关键字或状态标志 [来源](https://github.com/huggingface/smolagents)。这个设计有两层好处。

第一层是**循环逻辑的统一**。如果「结束」是个特殊关键字，主循环里就要写「先看是不是关键字、再看是不是工具调用」两套分支；而把「结束」也统一成「调用工具」这一种动作，主循环只需要判断「模型这轮调了哪些工具、其中有没有 `final_answer`」，逻辑更简洁一致。你在第 6 节手写迷你 CodeAgent 时会亲身体会到：把终止收敛成一次工具调用，代码会干净很多。

第二层是**心智模型的统一**。对模型而言，「给出答案」和「查天气」在形式上是同一类事——都是「调用一个工具」。这降低了模型的认知负担：它不需要在「什么时候用特殊语法收尾」和「什么时候调工具」之间切换，一切都是「决定这轮调哪个工具」。这也让「循环必须有终止条件」这条第 4 章的原则落地得非常自然——终止不是一个外挂的特判，而是循环内一个普通动作的自然结果。

顺带把「反向验证」的思路演示一遍：拿 smolagents 的一个概念去「考」你的理论。`max_steps` 对应什么原理？——对应第 4 章「循环必须有终止条件」，防止 Agent 陷入无限循环导致复合错误累积和成本失控。为什么 CodeAgent 要在 prompt 里给模型「可用工具清单」？——对应第 6 章「工具描述是 prompt 的一部分」，模型只能用它「知道存在」的工具。**能做这种双向推导（理论↔框架），才算真正把它们焊死了。**
