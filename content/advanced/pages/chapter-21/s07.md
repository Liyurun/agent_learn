## 真实问题

面试进入收尾，也是压力最大的一段。面试官问：「你的客服 Agent 上周编了一个根本不存在的『退货工单接口』去调用，还煞有介事地告诉用户『工单已提交』。为什么会这样？这和普通大模型（Large Language Model，LLM）聊天时的幻觉一样吗？」候选人答「模型不够聪明呗，加个 prompt 让它别瞎编」。面试官不满意，开始连环追问：「那你怎么量化它幻觉多严重？」「检索到资料就不会幻觉了吗？」「多步任务里一步错了会怎样？」——一连三问，候选人越答越乱。**这既考『幻觉成因』这个概念本身，也考『连环追问下能不能守住阵脚』这个终极能力。** 这一节先讲透幻觉，再把全章 11 道题横向拉通，收敛成一套应对连环追问的「四层应答链」。

## 原理：幻觉的三种形态与四层治理，连环追问的四层应答链

### 幻觉：根因、Agent 特有形态、分层治理

幻觉的根源是：LLM 本质是「根据概率生成最像样的下一个 token」，它并不「知道」自己知不知道，所以在缺乏依据时也会自信地编造看似合理的内容。在 Agent 场景下，幻觉有两个特有的放大点：
```text
单轮 LLM 幻觉：      一次输出错误 → 影响这一次
Agent 幻觉（会累积）：步骤1错 → 作为观察进入步骤2 → 步骤2基于错误推理 → 步骤3更错...
                     （错误沿着链条放大，且更难定位是哪一步开始错的）
```
1. **内容幻觉**：编造看似合理但不真实的事实（和普通 LLM 一样）。
2. **工具/参数幻觉（行动幻觉）**：模型可能编造一个不存在的工具名、或给出不合法的参数——不只是「答错内容」，而是「编造行动」。导读里那个「编造退货工单接口」正是此类。
3. **错误累积**：Agent 是多步的，第一步的幻觉会作为「观察」进入后续步骤，被当成事实继续推理，导致错误像滚雪球一样放大。这是 Agent 幻觉比单轮问答更危险的地方。

治理要**分层**，而不是「加个 prompt」一招：
```text
检索层：保证有依据（RAG 召回真实资料）
  ↓
prompt 层：强制「无依据不作答」「不确定要说不确定」
  ↓
工具层：schema 校验挡住非法/不存在的工具调用（挡行动幻觉）
  ↓
输出层：要求附引用、对引用做校验
  ↓
流程层：设终止条件、关键步骤加校验，防止错误无限累积
```
### 连环追问：把全章拉通成「四层应答链」

概念题极少单独出现，面试官几乎一定会追问。应对连环追问的秘诀，是每个概念都提前准备好四层，被追问时顺着往下走：
```text
第一层·定义：一句话压缩，给面试官一个锚
   ↓ 追问「为什么这样设计」
第二层·原理：讲清机制与「为什么」
   ↓ 追问「它有什么缺点/什么时候不用」
第三层·边界：主动点出代价、不适用场景、对立面
   ↓ 追问「你实际怎么用的」
第四层·实践：给一个具体、30 秒能讲清的例子
```
把前面 10 道题横向拉通，会发现优秀回答有几个共同的「元技巧」：永远先给一句话定义；用对比来定位概念（Agent vs Workflow、ReAct vs Plan-and-Execute、Agentic RAG vs 传统 RAG、上下文工程 vs Prompt Engineering）；主动讲代价和边界；用一个具体例子落地；诚实标注不确定。

## 最小可运行演示

下面这段代码一次演示两件事：一个「幻觉四层治理」检查器（一条输出依次过检索/引用/工具校验/终止条件四道闸），和一个「连环追问四层应答」状态机（模拟被连续追问时如何逐层深入而不散架）。不联网、不需要 API Key。
```python
"""第21.7节：幻觉四层治理 + 连环追问四层应答（纯 Python，无需 API Key）。"""
from dataclasses import dataclass, field

VALID_TOOLS = {"query_order", "query_logistics", "create_ticket"}


@dataclass
class Output:
    text: str
    has_evidence: bool                 ## 检索层：是否有依据
    citations: list = field(default_factory=list)  ## 输出层：是否附引用
    tool_call: str = ""                ## 工具层：调了哪个工具
    step: int = 1                      ## 流程层：第几步


def guard(o: Output, max_step: int = 5) -> list:
    verdicts = []
    verdicts.append(("检索层", "通过" if o.has_evidence else "拦截：无依据不应作答"))
    verdicts.append(("输出层", "通过" if o.citations else "拦截：缺引用"))
    if o.tool_call:
        ok = o.tool_call in VALID_TOOLS
        verdicts.append(("工具层", "通过" if ok else f"拦截：不存在的工具 {o.tool_call}"))
    verdicts.append(("流程层", "通过" if o.step <= max_step else "拦截：超步数上限，防错误累积"))
    return verdicts


## 连环追问：每被追问一次，深入一层，而不是卡壳
LAYERS = ["定义：一句话压缩", "原理：为什么这样设计", "边界：代价与不适用", "实践：一个具体例子"]


def answer_chain(follow_ups: int) -> list:
    ## follow_ups=被追问次数；顺着四层往下走
    return LAYERS[:min(follow_ups + 1, len(LAYERS))]


def run():
    bad = Output("工单已提交", has_evidence=False, citations=[], tool_call="submit_refund_ticket", step=7)
    print("坏输出（编工具+无依据+超步数）：")
    for layer, v in guard(bad):
        print(f"  {layer}: {v}")
    good = Output("按7天无理由可退", has_evidence=True, citations=["KB-RETURN-3C"], tool_call="create_ticket", step=2)
    print("好输出：")
    for layer, v in guard(good):
        print(f"  {layer}: {v}")
    print("--- 连环追问四层应答 ---")
    for n in range(4):
        print(f"被追问{n}次 -> 讲到: {answer_chain(n)}")


if __name__ == "__main__":
    run()
```
保存为 `s7_hallucination.py`，运行 `python s7_hallucination.py`。预期输出：
```text
坏输出（编工具+无依据+超步数）：
  检索层: 拦截：无依据不应作答
  输出层: 拦截：缺引用
  工具层: 拦截：不存在的工具 submit_refund_ticket
  流程层: 拦截：超步数上限，防错误累积
好输出：
  检索层: 通过
  输出层: 通过
  工具层: 通过
  流程层: 通过
--- 连环追问四层应答 ---
被追问0次 -> 讲到: ['定义：一句话压缩']
被追问1次 -> 讲到: ['定义：一句话压缩', '原理：为什么这样设计']
被追问2次 -> 讲到: ['定义：一句话压缩', '原理：为什么这样设计', '边界：代价与不适用']
被追问3次 -> 讲到: ['定义：一句话压缩', '原理：为什么这样设计', '边界：代价与不适用', '实践：一个具体例子']
```
注意「坏输出」那条：它同时踩了「编造不存在的工具 `submit_refund_ticket`」「无依据」「无引用」「超步数」四个雷，四道闸全部拦下——**单靠一个 prompt 只能拦其中一层，分层治理才能形成纵深防御。** 而追问状态机则示范：被追问不是坏事，而是你「往下走一层」的信号，准备了四层就永远有下一句可讲。

## 真实系统对应

**官方公开机制**：Agentic RAG（Retrieval-Augmented Generation，检索增强生成）「无依据不作答 + 附引用」这类做法，本质是把 Anthropic《Building Effective Agents》里「检索—评估—再检索」的 agentic 循环加上溯源约束 [来源](https://www.anthropic.com/engineering/building-effective-agents)；工具层用 schema 校验挡住「不存在的工具/非法参数」，对应 OpenAI Function calling（函数调用）文档里用 `strict` 模式强制参数符合 schema 的机制 [来源](https://developers.openai.com/api/docs/guides/function-calling)；「设终止条件防错误累积」呼应 ReAct（Reasoning and Acting，推理与行动）循环必须配步数上限的工程共识 [来源](https://arxiv.org/abs/2210.03629)。**通用工程模式**：检索/prompt/工具/输出/流程五层纵深治理、连环追问的「定义→原理→边界→实践」四层应答链，都是可迁移到任何面试与系统的方法。**教学参考实现**：上面的守卫检查器与应答状态机是为讲清结构而构造。

一个必须澄清的边界：**检索到资料不等于不会幻觉。** 模型可能忽略检索结果、曲解资料、或在资料之外「自由发挥」。所以不能只做检索层，还要 prompt 约束（无依据不答）+ 输出层校验（答案必须能对应到引用）。把「上了 RAG 就安全了」当结论，是这道题的典型误区。

## 生产踩坑

| 现场表现 | 根因 | 如何观测复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 编造不存在的接口去调用 | 无工具 schema 校验（行动幻觉） | 看日志有无非注册工具名 | 工具白名单 + schema/strict 校验拦截 | 无工具调用的纯问答 |
| 多步任务错误滚雪球 | 无终止条件、无中间校验 | 复盘错误从哪一步开始放大 | 关键步骤加校验 + 设步数上限 + 人工介入点 | 单步任务无累积风险 |
| 上了 RAG 仍然瞎编 | 模型忽略/曲解检索结果 | 查答案是否真对应召回内容 | prompt 强制无依据不答 + 输出对引用校验 | 无需溯源的闲聊 |
| 只会「加 prompt」防幻觉 | 把治理当单点 | 追问「prompt 之外还有什么手段」 | 检索/prompt/工具/输出/流程五层纵深 | 极简场景单层够用时 |
| 幻觉严重程度说不清 | 没有评估集与量化指标 | 问「幻觉率是多少」看能否答 | 建带标准答案评估集，统计幻觉率/引用准确率 | 早期原型无评估集 |
| 被连环追问一问就卡 | 只准备第一层定义 | 让同伴连续追问三次 | 每题备好定义→原理→边界→实践四层 | 面试不追问的走过场 |

## 思考：为什么说 Agent 的幻觉比单轮 LLM 的幻觉更危险、更难治？

### 回答

因为 Agent 的幻觉多了两个单轮 LLM 没有的维度：**行动幻觉**和**错误累积**，这两者都把「一次说错」放大成了「连锁失控」。

先说行动幻觉。单轮 LLM 的幻觉，最多是「内容说错了」——它编了一个不存在的事实，用户看到、可能被误导，但危害止于「一条错误信息」。而 Agent 能调用工具、能执行有副作用的动作，它的幻觉就从「说错」升级成了「做错」：它可能编造一个根本不存在的工具名去调用、可能给真实工具传一个非法参数、可能「以为」自己提交了工单其实什么也没发生。导读里那个「编造退货工单接口、还告诉用户已提交」正是行动幻觉——它不是答错了一个问题，而是**编造了一次本不存在的行动，并基于这个虚构的行动继续对话**，用户以为事情办好了，其实一场空。

再说错误累积，这是更隐蔽也更致命的一点。Agent 是多步的，每一步的输出会作为「观察」进入下一步。这意味着**第一步的幻觉不会停在第一步，而是被当成事实喂给后续步骤，让后面所有推理都建立在错误的地基上**——步骤 1 错，步骤 2 基于错误推理，步骤 3 更错，像滚雪球一样放大。而且因为错误是逐步累积的，最终出问题时很难定位「到底是哪一步开始错的」，调试成本极高。这就是为什么 Agent 幻觉「更难治」：单轮幻觉只要治好「这一次」，Agent 幻觉却要防「错误沿着链条扩散」。所以治理必须是分层纵深的——检索层给依据、prompt 层约束、工具层用 schema 校验挡住行动幻觉、输出层附引用校验、流程层设终止条件和关键步骤校验来切断累积链。指望「加一个 prompt 让它别瞎说」，只能拦住内容幻觉的一小部分，对行动幻觉和错误累积几乎无能为力。

### 面试精简表达

Agent 幻觉多了两个维度：行动幻觉（编工具/编参数，把「说错」变成「做错」）和错误累积（多步任务里一步错会被当事实喂给下一步，滚雪球放大且难定位）。所以要分层纵深治理——检索/prompt/工具校验/输出引用/流程终止五层，单靠一个 prompt 治不了。

### 反例

有人说「那我把模型换成更强、幻觉更少的版本，不就解决了」——治标不治本。更强的模型能降低内容幻觉的概率，但只要它还是概率生成器，就仍会在缺乏依据时编造；更关键的是，行动幻觉和错误累积是**架构层面**的风险，不是模型能力单点能消除的——再强的模型也可能给非法参数，多步链条只要没有终止条件和校验，一次失误照样累积。工程护栏和模型能力是两件事，不能互相替代。

## 全章收敛：概念题的通用应答策略

把全章 11 道题横向拉通，优秀回答有五个共同的「元技巧」，值得作为全章收尾单独提炼：

1. **永远先给一句话定义**。不管题多难，第一句先压缩成一句话。它给面试官一个「锚」，也逼你自己想清核心。第 1 节的三信号里，这是「压缩能力」。
2. **用对比来定位概念**。本章大量概念本身就是通过「和什么不同」来定义的——Agent vs Workflow（第 2 节）、Function Calling vs 执行、MCP（Model Context Protocol，模型上下文协议）vs Function Calling（第 4 节）、ReAct vs Plan-and-Execute、上下文工程 vs Prompt Engineering（第 5 节）、Agentic RAG vs 传统 RAG（第 6 节）。讲清对立面，概念自然清晰。
3. **主动讲代价和边界**。这是区分「背题」和「真懂」的最强信号。全章反复出现同一个母题：**自主性带来能力，也带来代价**——单/多 Agent、ReAct/Plan、传统/Agentic RAG 的选型，本质都是「这个场景值不值得付这份代价」。
4. **用一个具体例子落地**。抽象讲完，给一个 30 秒能说清、且「只有这个概念才成立」的场景。
5. **诚实标注不确定**。遇到记不准的细节（某个具体数字、某个 SDK（Software Development Kit，软件开发工具包）方法名），就说「具体我记不准，但逻辑是……」，绝不硬编——这与 KV Cache（Key-Value Cache，键值缓存）、CLI（Command-Line Interface，命令行界面）这类会随版本变化的细节尤其相关，硬背反而危险。

**面试官经常用连环追问来探你的深度**——「那这个和那个有什么区别」「那它有什么缺点」「那你实际怎么用的」。应对秘诀就是每个概念都提前准备好「定义层 → 原理层 → 边界层 → 实践层」四层，被追问时顺着往下走即可，而不是被问一句卡一句。这套四层应答链，配合第 1 节的三种能力信号，就是本章想交给你的「答题引擎」：**它不是让你背更多答案，而是让你面对任何概念追问，都知道『下一句该讲哪一层』。**
