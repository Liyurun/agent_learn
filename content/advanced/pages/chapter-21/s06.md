## 真实问题

面试进入到检索与自我改进的话题。面试官问：「你的知识库问答，用户问『我买的这款 3C 产品和旗舰款比，哪个更适合送礼、退货政策一样吗』，你现在的 RAG（Retrieval-Augmented Generation，检索增强生成）为什么答得断章取义？」候选人答「可能是检索没检准」。面试官追问：「你现在是检索一次就生成，对吧？这种复合问题一次检索够吗？有没有更好的做法？」候选人没听过 Agentic RAG，卡住了。接着面试官换个角度：「模型生成的代码有 bug，怎么让它自己发现并改？这个机制叫什么？」候选人答「再让它跑一遍」——说不清 Reflection（反思）的本质。**这两问，一个考『检索能不能由模型自主多轮控制』，一个考『模型能不能自我批评改进』，都是近两年高频的进阶概念。** 这一节把它们讲透。

## 原理：Agentic RAG 的自主性，Reflection 的自我批评

### Agentic RAG：把检索变成模型可自主多轮调用的工具

传统 RAG 是一条固定流水线：**用户问题 → 检索 → 把检索结果拼进 prompt → 生成答案**，检索只发生一次、流程写死。Agentic RAG 是把检索变成 **Agent 可以自主决策和多轮使用的工具**：模型可以自己判断「要不要检索、检索什么、检索一次不够要不要改写查询再检索、检索到的东西够不够回答」。
```text
传统 RAG（固定流水线，检索一次）：
   问题 ──▶ 检索 ──▶ 拼 prompt ──▶ 生成答案
Agentic RAG（检索是可自主多轮调用的工具）：
   问题 ──▶ Agent 判断
             ├─ 需要检索吗？── 是 ──▶ 改写查询 ──▶ 检索 ──▶ 够了吗？
             │                                        ├─ 不够：再改写再检索
             │                                        └─ 够了：生成答案
             └─ 不需要 ──▶ 直接答
```
区别的本质还是「控制权」——传统 RAG 的检索由代码写死（永远先检索再生成），Agentic RAG 的检索由模型决定（是否检索、检索几次、怎么改写）。这种「让模型自主决定工具使用」的循环，正是 Anthropic 在《Building Effective Agents》里归为 agentic 模式的典型——把「检索—评估—再检索」交给模型自己驱动 [来源](https://www.anthropic.com/engineering/building-effective-agents)。它带来的好处是能处理更复杂的问题：多跳推理（先查 A 再根据 A 查 B）、需要多轮澄清的问题、检索一次召回不足时的自我补救。代价是更灵活也更贵更慢（多次检索 + 多次模型调用），且更难保证稳定性。

### Reflection：生成后自我评估并据此改进

Reflection（反思）是指 Agent 对自己的输出或执行过程做一次自我评估和批评，找出问题后再改进的机制。典型做法是：模型先给出一个答案/一段代码，然后用另一轮（或另一个「批评者」角色）来审视「这个结果有没有问题、哪里能改进」，再据此修正。
```text
无反思：   任务 ──▶ 生成 ──▶ 输出（错了也不知道）
有反思：   任务 ──▶ 生成 ──▶ 自我批评：「哪里有问题？」 ──▶ 修正 ──▶ 输出
                              ▲__________________________|（可多轮，直到满意或到上限）
```
它的价值是提升质量和可靠性：很多任务模型「一次做不好，但能看出自己哪里做得不好」。给它一次反思和重做的机会，往往比直接一次输出更准。Lilian Weng 的综述里也把 self-reflection（自我反思）作为 Agent 规划模块的重要一环 [来源](https://lilianweng.github.io/posts/2023-06-23-agent/)。但反思要额外的模型调用，增加延迟和成本；而且如果模型的判断力本身不够，反思可能「越改越错」或原地打转。所以要设反思轮数上限，最好配合外部信号（如真实测试结果、检索证据）来锚定反思，而不是纯靠模型自说自话。

## 最小可运行演示

下面这段代码一次演示两件事：一个「Agentic RAG 多轮检索」mock（模型判断够不够、不够就改写查询再检索，带次数上限），和一个「反思循环」mock（生成→自我批评→修正，用外部测试信号决定何时停）。不联网、不需要 API Key。
```python
"""第21.6节：Agentic RAG 多轮检索 + 反思循环（纯 Python，无需 API Key）。"""

## ---------- Agentic RAG：模型自主决定检索几次、怎么改写 ----------
KB = {
    "退货政策": "本店支持 7 天无理由退货",
    "旗舰款参数": "旗舰款支持无线充电、续航 30 小时",
    "标准款参数": "标准款支持有线充电、续航 20 小时",
}


def retrieve(query: str) -> str:
    for key, doc in KB.items():
        if key in query:            ## 精确匹配子查询关键词，区分旗舰款/标准款
            return doc
    return ""


def agentic_rag(question: str, max_rounds: int = 3) -> dict:
    ## 复合问题：一次检索不够，模型改写查询多轮补齐
    subqueries, gathered, rounds = [], [], 0
    ## 模型「判断」这个复合问题需要拆成两个子查询
    plan = []
    if "退货" in question:
        plan.append("退货政策")
    if "参数" in question or "比" in question:
        plan += ["旗舰款参数", "标准款参数"]
    for q in plan:
        if rounds >= max_rounds:
            break
        rounds += 1
        subqueries.append(q)
        hit = retrieve(q)
        if hit:
            gathered.append(hit)
    enough = len(gathered) >= len(plan) and plan
    return {"rounds": rounds, "subqueries": subqueries, "gathered": gathered, "enough": bool(enough)}


## ---------- 反思：生成→自我批评→修正，用外部测试信号停 ----------
def generate_code(v: int) -> str:
    return ["def div(a,b): return a/b",                      ## v0：没处理除零
            "def div(a,b): return a/b if b else None"][min(v, 1)]  ## v1：修正


def external_test(code: str) -> bool:
    ns = {}
    exec(code, ns)
    try:
        return ns["div"](1, 0) is None      ## 外部客观信号：除零应安全返回
    except ZeroDivisionError:
        return False


def reflect_loop(max_rounds: int = 3) -> dict:
    for v in range(max_rounds):
        code = generate_code(v)
        if external_test(code):             ## 用外部信号锚定反思，而非模型自说
            return {"final_version": v, "code": code, "passed": True}
    return {"final_version": max_rounds - 1, "code": code, "passed": False}


def run():
    r = agentic_rag("这款和旗舰款比参数如何，退货政策一样吗")
    print(f"Agentic RAG: 检索{r['rounds']}轮 子查询={r['subqueries']} 够了={r['enough']}")
    print(f"召回 {len(r['gathered'])} 条: {r['gathered']}")
    print("---")
    fr = reflect_loop()
    print(f"反思: 第{fr['final_version']}版通过外部测试={fr['passed']}")
    print(f"最终代码: {fr['code']}")


if __name__ == "__main__":
    run()
```
保存为 `s6_rag_reflect.py`，运行 `python s6_rag_reflect.py`。预期输出：
```text
Agentic RAG: 检索3轮 子查询=['退货政策', '旗舰款参数', '标准款参数'] 够了=True
召回 3 条: ['本店支持 7 天无理由退货', '旗舰款支持无线充电、续航 30 小时', '标准款支持有线充电、续航 20 小时']
---
反思: 第1版通过外部测试=True
最终代码: def div(a,b): return a/b if b else None
```
注意两点：Agentic RAG 部分把「和旗舰款比参数 + 退货政策」这个复合问题拆成三个子查询、多轮检索补齐——这是传统 RAG「一次检索」做不到的；反思部分用 `external_test`（外部客观信号）判断代码到底行不行，而不是让模型自己说「我改好了」——**这正是防止反思『越改越错』的关键：用真实信号锚定，而非模型主观自评。**

## 真实系统对应

**官方公开机制**：Anthropic 把「模型自主决定工具使用」的检索—评估—再检索循环归为 agentic 模式，与固定流水线区分开 [来源](https://www.anthropic.com/engineering/building-effective-agents)；Reflection / self-reflection 作为规划模块一环见 Lilian Weng 综述 [来源](https://lilianweng.github.io/posts/2023-06-23-agent/)；把检索变成模型可多轮调用的「工具」，底层依赖的正是 Function Calling（函数调用）与 ReAct（Reasoning and Acting，推理与行动）式的循环 [来源](https://arxiv.org/abs/2210.03629)。**通用工程模式**：Agentic RAG 的「判断是否检索 + 改写查询 + 多轮补齐 + 够不够判断」、反思的「生成—批评—修正 + 外部信号锚定 + 轮数上限」，都是可迁移到任意框架的工程共识。**教学参考实现**：上面的关键词检索、固定两版代码是为可复核而构造，真实系统请用向量检索与真实模型的多轮生成。

一个必须澄清的边界：**准确性优先、问题相对简单的场景（如企业 FAQ 问答），传统 RAG 往往就够了**；只有真需要多跳 / 自适应检索时，才上 Agentic RAG。同理，反思不是「加了就一定更好」——如果模型判断力不足，反思可能原地打转甚至越改越错，且每一轮都是额外成本。面试里能主动说出「什么时候不该上」，比夸它多强更能体现判断力。

## 生产踩坑

| 现场表现 | 根因 | 如何观测复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 复合问题被断章取义地答 | 传统 RAG 只检索一次 | 用「A 和 B 比 + 附加条件」复合问复现 | 上 Agentic RAG 拆子查询多轮检索 | 单跳明确问题 |
| Agentic RAG 无限检索停不下 | 无检索次数上限与「够了」判断 | 构造永远召回不足的问题 | 设 max_rounds + 够不够判断 + 无果如实说 | 检索一次必够的简单问 |
| 简单问题也上 Agentic 又慢又贵 | 不分场景滥用 | 统计简单问的平均检索轮数 | 简单准确优先场景退回传统 RAG | 确需多跳自适应时 |
| 反思越改越错 | 纯靠模型主观自评、无外部锚点 | 让模型反复反思看是否发散 | 用测试结果/检索证据等客观信号锚定 | 有明确客观判据时反而安全 |
| 反思陷入死循环 | 无轮数上限 | 构造模型反复纠结的任务 | 设反思轮数上限，到限即停 | 单轮即可判定停止 |
| Agentic RAG 仍然幻觉 | 未强制附引用、无依据也作答 | 查答案是否有检索来源支撑 | 强制答案附引用、无依据不作答 | 无需溯源的闲聊场景 |

## 思考：为什么 Agentic RAG 更强，却不该无脑取代传统 RAG？

### 回答

因为「更强」的代价是「更贵、更慢、更不稳定」，而很多场景根本不需要那份「更强」。Agentic RAG 的强，来自它把检索交给模型自主控制——能多跳、能改写查询、能判断够不够、能自我补救。但这份自主性不是免费的：**每一次「要不要再检索」的判断都是一次模型调用，每一轮检索都是一次额外的延迟和费用**，而且模型自主决策本身就引入了不确定性——它可能判断失误多检索好几轮，也可能在「够不够」上反复横跳。所以 Agentic RAG 天然比传统 RAG 慢、贵、且更难保证每次行为一致。

反观大量真实场景——企业 FAQ、标准政策问答、单跳事实查询——问题是明确的、单跳的、答案就在某一篇文档里。这类场景要的是**稳定、低延迟、低成本、可预测**，传统 RAG 的「一次检索 + 生成」恰好完美匹配：流程写死反而是优点，因为它每次行为一致、便于缓存、便于监控、出错好定位。硬给这种场景上 Agentic RAG，等于用一套又贵又不稳定的机制去解一个本来一步就能解的问题，是典型的过度设计。所以正确的判断标准是**问题复杂度**：单跳、明确、追求稳定 → 传统 RAG；多跳、需要改写和补救、追求覆盖 → Agentic RAG。这跟第 4 节「单 Agent vs 多 Agent」、第 5 节「ReAct vs Plan-and-Execute」是同一个母题——**自主性带来能力，也带来代价，选型永远看『这个场景值不值得付这份代价』，而不是『哪个听起来更高级』。**

### 面试精简表达

Agentic RAG 的强来自模型自主多轮控制，代价是每轮判断和检索都多一次模型调用、更慢更贵更不稳定。企业 FAQ、单跳事实查询这类要稳定低成本的场景，传统 RAG「一次检索+生成」正好匹配，硬上 Agentic 是过度设计。选型看问题复杂度，不看谁更高级。

### 反例

有人说「Agentic RAG 能自适应，那我全用它、简单问题它自然会只检索一次，不亏」——不成立。就算它对简单问题只检索一次，它仍然多付了「判断要不要检索、够不够」的模型调用开销，还引入了「万一判断失误多检索几轮」的不稳定性。对海量简单请求，这些多出来的调用累积起来就是可观的成本和延迟，而收益是零——因为简单问题传统 RAG 一步就答对了。

## 机制推导：反思为什么「用外部信号锚定」比「纯自评」可靠得多

反思的核心假设是「模型的判断力常强于一次生成的能力」——它能看出自己答案里的漏洞。这个假设在很多任务上成立（比如模型能一眼看出自己写的代码没处理边界情况），但它有一个致命前提：**模型得真的「知道」什么是对的。** 一旦这个前提不成立，纯靠模型自评的反思就会退化成「自我强化的幻觉」——模型基于错误的标准去评判，越评越偏，甚至把对的改成错的。

用外部信号锚定，本质是**给反思引入一个模型无法糊弄的客观裁判**。演示代码里的 `external_test` 就是这样一个裁判：它真的去跑「除以零」这个用例，代码到底安不安全，由运行结果说了算，模型说「我觉得改好了」不算数。这带来两个质变：其一，反思有了**收敛判据**——测试通过就停，不通过就继续，而不是让模型主观决定「够好了没」，从而避免死循环；其二，反思有了**方向**——测试失败的具体信息（除零异常）能明确告诉模型「哪里错了」，比模型自己空想「哪里可能有问题」精准得多。这也是为什么生产里高质量的反思机制，几乎都不是纯粹的「模型自省」，而是「模型生成 → 外部验证（单元测试、检索证据、规则校验、执行结果）→ 拿验证结果反思 → 再生成」。**能主动说出『反思要用外部信号锚定，而不是让模型自说自话』的候选人，说明他真正理解了反思的适用边界——它放大的是模型的判断力，而判断力本身需要一个可靠的锚。**
