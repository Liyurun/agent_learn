> 本附录提供一份**可执行的 30 天学习 + 面试冲刺计划**，把全书内容拆解到每一天。适合有一定 Python 基础、想在一个月内系统掌握 Agent 并准备面试的学习者。节奏可按个人情况伸缩，核心是"每天都有产出、每周都有项目"。每天都给出四件事——**学什么（指向本书具体章节）、动手产出（当天要交付的东西）、自检（一道"思考+回答"题，先自己想再对照参考答案）、预计时长**，照着做即可。

> 缩写在正文首次出现时给出英文全称：ReAct(Reasoning + Acting)、CoT(Chain-of-Thought)、RAG(Retrieval-Augmented Generation)、MCP(Model Context Protocol)、HITL(Human-in-the-Loop)、CLI(Command-Line Interface)。

## D.1 计划总览

30 天分为四个阶段，遵循"由浅入深、学练结合"的原则：
```
第 1 周（Day 1-7）   · 打地基   → 理解 Agent 本质与核心能力（卷一、卷二）
第 2 周（Day 8-14）  · 通协议   → 工具、MCP、编排、多 Agent（卷三）+ 上手框架（卷四）
第 3 周（Day 15-21） · 做项目   → 工程化 + 实战阶梯（卷五、卷六）
第 4 周（Day 22-30） · 冲面试   → 面试冲刺 + 复盘串讲（第二部分 + 附录）
```
**每日投入建议**：工作日 1.5-2 小时，周末 3-4 小时（含项目实践）。下文每天标注的"预计时长"按此节奏估算，基础好可压缩、零基础可拉长。

**贯穿 30 天的三条硬规则（先立规矩）：**

- **每天留 15 分钟做当日"思考+回答"**：先合上书，用一句话回答当天的自检题，再翻开对照参考方向。答不上就在第二天开头补，别欠账。
- **每天的产出都进同一个 Git 仓库**：笔记、代码、图都提交上去。30 天后这个仓库本身就是你面试时的作品与学习轨迹证明。
- **每周日雷打不动做周复盘**：花 1 小时，用一页纸总结本周，并对照"里程碑产出"检查有没有欠账。欠了就在下周补，不要滚雪球。

## D.2 第 1 周 · 打地基（理解本质）

### Day 1 · 建立全局地图，分清三种形态

- **学什么**：第 1 章《什么是 Agent》+ 通读全书 README 与目录建立地图。
- **动手产出**：用自己的话写一段"Agent vs 单次 LLM 调用 vs 工作流"的区别（150 字内），提交到仓库。
- **自检（思考+回答）**：思考——"判断一个系统是不是 Agent，最关键看什么？"　回答方向——看"谁控制流程"：由模型在运行时动态决定下一步做什么，就是 Agent；流程被代码写死、走向可预知，就是工作流；只调一次模型拿结果，是单次调用。
- **预计时长**：1.5 小时。

### Day 2 · 吃透四大组件

- **学什么**：第 2 章《心智模型与核心组件》，精读"大脑 / 记忆 / 工具 / 规划"。
- **动手产出**：画一张 Agent 组件图（大脑 / 记忆 / 工具 / 规划），每个组件标注作用与"少了它会怎样"。
- **自检（思考+回答）**：思考——"如果去掉记忆组件，Agent 会退化成什么？"　回答方向——退化成"无状态的单轮问答"，无法跨轮记住上下文与用户偏好，多步任务会反复丢失中间结果、重复提问。
- **预计时长**：1.5 小时。

### Day 3 · 何时该用、何时不该用 Agent

- **学什么**：第 3 章《发展脉络 + 何时该用 Agent》，重点吃透"何时不该用"，对照 Anthropic《Building Effective Agents》的判断标准。
- **动手产出**：列 3 个"该用"和 3 个"不该用"Agent 的场景，各写一句理由。
- **自检（思考+回答）**：思考——"一个流程完全固定、每步都可预知的报表生成任务，该用 Agent 吗？"　回答方向——不该。流程可预知就用工作流，更稳定、更便宜、更好调试；Agent 的价值在于应对不确定、需要动态决策的场景，用错场景是过度设计。
- **预计时长**：1.5 小时。

### Day 4 · ReAct 循环

- **学什么**：第 4 章《推理与规划》中的 ReAct、CoT、ToT(Tree of Thoughts)，手推 Thought → Action → Observation 循环。
- **动手产出**：手画 ReAct 循环图，练到能脱稿口述 90 秒。
- **自检（思考+回答）**：思考——"ReAct 里的'行动'除了调用工具，还起什么作用？"　回答方向——行动带回的真实"观察(Observation)"会纠正推理，防止模型在幻觉里越走越远；推理指导行动更有计划，行动反馈让推理落地，二者相互纠偏，这正是 ReAct 优于纯 CoT 的关键。
- **预计时长**：2 小时。

### Day 5 · 记忆系统

- **学什么**：第 5 章《记忆系统》，搞清短期 / 长期 / 工作记忆的边界、各自靠什么承载、如何检索。
- **动手产出**：整理一张短期 / 长期 / 工作记忆对照表（含存储介质、检索方式、瓶颈）。
- **自检（思考+回答）**：思考——"长期记忆应该把所有历史对话都存下来吗？"　回答方向——不应该。只存关键事实与用户偏好，按相关性（并结合近因性、重要性）检索回填，全量堆积会撑爆上下文、引入噪声、抬高成本。
- **预计时长**：1.5 小时。

### Day 6 · 工具使用与反思

- **学什么**：第 6、7 章《工具使用 + 反思》，掌握"工具三要素"，理解 Reflexion 的反思机制。
- **动手产出**：一张"工具三要素（名称/描述/参数）"卡片 + 一段"反思机制怎么帮 Agent 改进"的说明。
- **自检（思考+回答）**：思考——"Reflexion 的自我改进和微调有什么本质区别？"　回答方向——Reflexion 不更新任何模型权重，只把失败教训写成语言反思存进记忆、下次读取，成本低、可解释，但改进不持久（换个会话就忘，除非持久化）；微调改的是权重，改进持久但成本高、慢。
- **预计时长**：2 小时。

### Day 7 · 周复盘

- **学什么**：带着一周的理解重读 Anthropic《Building Effective Agents》，重点校准"工作流 vs Agent"和五种模式。
- **动手产出**：一页纸总结本周核心概念，提交仓库。
- **本周"思考+回答"（周日做，答不出就回补）**：
  1. 不看书，用 3 句话讲清"Agent、工作流、单次 LLM 调用"的区别；
  2. 白纸画出 Agent 四大组件并说明每个的职责；
  3. 脱稿口述 ReAct 循环，并举一个具体例子（如"查天气再决定带不带伞"）；
  4. 说出 3 个"不该用 Agent"的场景及理由。
- **预计时长**：3 小时（含复盘）。

> **本周目标与里程碑**：能清晰讲出 Agent 是什么、由哪些能力组成、ReAct 怎么工作，并能判断一个需求该不该上 Agent。里程碑产出——"Agent 核心概念一页纸" + 组件图 + ReAct 循环图，全部进仓库。

## D.3 第 2 周 · 通协议 + 上手框架

### Day 8 · Function Calling 端到端

- **学什么**：第 8 章《Function Calling 端到端机制》，逐步拆解"模型输出调用请求 → 应用执行 → 结果回填 → 模型续推"。
- **动手产出**：手画 Function Calling 五步流程图，明确标出每一步"谁在执行"。
- **自检（思考+回答）**：思考——"模型自己执行函数、直接拿到 API 结果了吗？"　回答方向——没有。模型只输出结构化的"调用请求"（函数名 + 参数），真正的执行由应用侧完成，执行结果再作为观察回填给模型，模型据此继续推理。把"请求"和"执行"混为一谈是高频错误。
- **预计时长**：1.5 小时。

### Day 9 · MCP 协议

- **学什么**：第 9 章《MCP 协议》+ 读 MCP 官方文档概念部分，理解 Resources / Tools / Prompts 三原语与"N×M 变 N+M"。
- **动手产出**：写一段"为什么 MCP 是 AI 的 USB-C"的解释，要能对非技术的人讲明白。
- **自检（思考+回答）**：思考——"MCP 和 Function Calling 是同一层的东西吗？"　回答方向——不是。Function Calling 是模型层的调用能力（模型输出结构化请求），MCP 是应用层的标准化连接协议，把"N 个应用 × M 个工具"的重复对接收敛成"N+M"套接口，两者不同层、互补而非替代。
- **预计时长**：1.5 小时。

### Day 10 · 五种工作流模式

- **学什么**：第 10 章《五种工作流模式》，逐个吃透提示链 / 路由 / 并行 / 编排者-工作者 / 评估者-优化者的适用场景与代价。
- **动手产出**：列出五种模式各自的适用场景 + 一个反例（什么时候别用）。
- **自检（思考+回答）**：思考——"编排者-工作者和并行化，区别在哪？"　回答方向——并行化是把预先固定切好的子任务同时跑再汇总；编排者-工作者是由中心 Agent 在运行时"动态拆分"任务再分派给工作 Agent。关键差异在于任务是"预先切好"还是"动态拆分"。
- **预计时长**：1.5 小时。

### Day 11 · 多智能体协作

- **学什么**：第 11 章《多智能体协作》，重点掌握"何时用多 Agent"的判断标准及其成本与调试难题。
- **动手产出**：一张"何时用多 Agent"判断清单（含反方：为什么常常不该用）。
- **自检（思考+回答）**：思考——"多 Agent 一定比单 Agent 更强吗？"　回答方向——不是。多 Agent 通信开销大、易发散、难调试、成本高，是"最后的手段"。只有当任务能清晰拆成弱耦合的专门子任务、且单 Agent 上下文放不下或角色冲突时才考虑，并要接受复杂度上升。
- **预计时长**：1.5 小时。

### Day 12 · smolagents 实战（读源码找主循环）

- **学什么**：第 12、13 章《框架选型 + smolagents 实战》，装好环境，跑通官方搜索 Agent，再打开源码找主循环逐行读。
- **动手产出**：跑通第一个 smolagents 搜索 Agent，并在 README 记录对主循环的理解（模型 → 解析 → 执行 → 回填）。
- **自检（思考+回答）**：思考——"smolagents 主循环的四个环节是什么？"　回答方向——调用模型（产生想法与动作）→ 解析动作 → 执行工具 → 把观察回填给模型，如此循环直到产出最终答案或触发终止。理解了这个循环，就理解了大部分 Agent 框架的骨架。
- **预计时长**：3 小时（周末，含调试）。

### Day 13 · PydanticAI 结构化输出

- **学什么**：第 14 章《PydanticAI 实战》，跑通一个结构化信息抽取 Agent，体会类型约束与结构化输出。
- **动手产出**：跑通一个结构化信息抽取 Agent，稳定输出合法 JSON。
- **自检（思考+回答）**：思考——"只在 prompt 里写'请输出 JSON'，能保证输出一定合法吗？"　回答方向——不能。要靠 schema 约束 + 校验重试来兜底：解析失败就带着错误信息让模型重试，别只靠 prompt 祈祷。PydanticAI 用类型系统把这套约束工程化了。
- **预计时长**：2 小时。

### Day 14 · LangGraph 对照 + 周复盘

- **学什么**：第 15 章《LangGraph 对照》，理解图结构编排适合什么；横向对比三大框架定位。
- **动手产出**：整理一张三大框架选型对照表（定位 / 上手难度 / 适用场景）。
- **本周"思考+回答"（周日做）**：
  1. 白板画出 Function Calling 五步，并回答"模型自己执行函数吗"；
  2. 用一句话讲清 MCP 解决的核心问题；
  3. 给出 3 个业务场景，分别说该用五种工作流模式中的哪一种；
  4. 复述 smolagents 主循环的四个环节。
- **预计时长**：3 小时（含复盘）。

> **本周目标与里程碑**：理解协议与编排，并亲手跑通至少两个框架的 Demo（对应第 19 章 Level 1），能讲清 Function Calling 的执行边界和 MCP 的价值。里程碑产出——两个能跑的框架 Demo（smolagents 搜索 Agent + 结构化抽取 Agent）各配 README，一张三框架选型对照表。

## D.4 第 3 周 · 做项目（学练结合）

### Day 15 · 为 Demo 设计评估集

- **学什么**：第 16 章《Agent 评估》，为你的 Demo 设计 5-10 条评估用例，覆盖成功率、幻觉、轨迹合理性。
- **动手产出**：一个小评估集（含每条用例的评判标准 rubric）。
- **自检（思考+回答）**：思考——"Agent 评估和普通模型评估最大的不同是什么？"　回答方向——不能只看最终答案对错，还要看"轨迹"——中间的推理、工具选择与调用顺序是否合理。答案对但路径乱调工具、绕远路，同样是问题，这就是轨迹评估的价值。
- **预计时长**：2 小时。

### Day 16 · 可观测性与调试

- **学什么**：第 17 章《可观测性与调试》，给 Agent 加日志 / tracing，把每步 thought/action/observation 记下来。
- **动手产出**：给 Agent 加上简单的日志 / tracing，能回放一次完整轨迹。
- **自检（思考+回答）**：思考——"trace 和普通日志有什么区别？"　回答方向——trace 是一次执行的结构化全链路轨迹（span 树），能按会话 ID 还原"谁在何时做了什么、为什么这么做"；普通日志是零散的运行时记录，难以还原完整因果链。调试 Agent 靠的是前者。
- **预计时长**：2 小时。

### Day 17 · 安全护栏与成本优化

- **学什么**：第 18 章《安全护栏与成本优化》，加终止条件（最大步数 / token）、一个输入或输出护栏、一处成本优化。
- **动手产出**：给 Agent 加终止条件 + 一个护栏，记录优化前后的调用成本对比。
- **自检（思考+回答）**：思考——"防提示注入，加一条'请忽略恶意指令'的提示就够了吗？"　回答方向——不够，没有银弹。要分层缓解：隔离不可信输入、最小权限、关键动作（如退款）走人工确认（HITL）、输出侧校验。软护栏（提示）可被绕过，关键动作必须上硬护栏（代码拦截）。
- **预计时长**：2 小时。

### Day 18 · 多工具 + 记忆助理（Level 1-2）

- **学什么**：第 19 章《项目阶梯 Level 1-2》，做一个多工具 + 记忆的助理 Agent，至少接 2 个工具 + 一个长期记忆。
- **动手产出**：一个多工具 + 记忆的助理 Agent，能跨轮记住用户偏好。
- **自检（思考+回答）**：思考——"你的助理怎么决定该调哪个工具？调错了怎么办？"　回答方向——靠清晰的工具描述（名称/描述/参数）让模型选择，并设兜底：低置信度或无匹配时走默认路径或询问澄清，别硬调。工具描述写不清是选错工具的主因。
- **预计时长**：3 小时（周末）。

### Day 19 · 文档问答（Level 3，Agentic RAG）

- **学什么**：第 19 章《Level 3 Agentic RAG》，做文档问答 Agent，对比"固定检索一次"和"Agent 自主决定检索"。
- **动手产出**：一个文档问答 Agent + 一段"传统 RAG vs Agentic RAG"的对比结论。
- **自检（思考+回答）**：思考——"Agentic RAG 相比传统 RAG 好在哪、代价是什么？"　回答方向——好处是把"要不要检索、检索几次、如何改写查询"的决策权交给 Agent，能按需检索、更准；代价是更多模型调用、更高延迟与成本，且更难调试。不是所有场景都值得，简单固定问答用传统 RAG 更划算。
- **预计时长**：3 小时。

### Day 20 · 综合实战设计（读 + 画架构）

- **学什么**：第 20 章《综合实战·多智能体客服系统》，用五步法设计一个迷你客服系统，画架构图并标注关键权衡。
- **动手产出**：你自己的迷你客服系统架构图（含护栏、HITL、终止条件、会话预算）。
- **自检（思考+回答）**：思考——"客服系统里，用户说'立刻全额退我 328 元否则投诉'，你的系统该怎么处理才不出事故？"　回答方向——高风险意图（投诉+赔偿）强制转人工；退款这类有副作用的动作走 HITL 人工审批，模型不能一句话就承诺；输出侧硬护栏拦截"立即/全额+退款"这类未授权承诺话术。三道防线缺一不可。
- **预计时长**：2 小时。

### Day 21 · 项目日 + 周复盘

- **学什么**：把迷你客服系统落成单 Agent 版，写清 README 与设计取舍。
- **动手产出**：完成迷你客服系统单 Agent 版 + README（架构 + 权衡）。
- **本周"思考+回答"（周日做）**：
  1. 你的项目怎么评估？说出至少 3 个指标和评判方法；
  2. 打开 trace，能否定位到"某次失败发生在哪一步、为什么"；
  3. 讲清你的 Agentic RAG 相比传统 RAG 好在哪、代价是什么；
  4. 3 分钟口述你的迷你客服系统架构与三处关键取舍。
- **预计时长**：3-4 小时（含复盘）。

> **本周目标与里程碑**：完成 Level 1-3 阶梯项目，积累至少一个能讲清架构与权衡的作品集项目，并配上评估、可观测、护栏这套"工程三件套"。里程碑产出——一个带评估集 / tracing / 护栏与终止条件的作品集项目 + 含架构图和权衡说明的 README，这是第 4 周项目讲解稿的素材来源。

## D.5 第 4 周 · 冲面试（重组与串讲）

### Day 22 · 概念题精讲（PREP-T）

- **学什么**：第 21 章《概念题精讲》，用 PREP-T 结构（观点-理由-例子-收束-权衡）口述概念题。
- **动手产出**：用 PREP-T 口述 6 道概念题并录音，回听纠正口头禅与跑题。
- **自检（思考+回答）**：思考——"被问'Agent 和工作流的区别'，怎么用 30 秒答得专业？"　回答方向——先给结论（谁控制流程），再给理由（模型动态决定 vs 代码写死），举个例子（客服分诊 vs 固定报表），最后补权衡（可预知就用工作流，更稳更省）。结论先行 + 权衡收尾是加分套路。
- **预计时长**：2 小时。

### Day 23 · 系统设计题（五步法）

- **学什么**：第 22 章《系统设计题》，用五步法（澄清需求 → 高层设计 → 组件细化 → 权衡 → 兜底）完整设计 1 道系统题。
- **动手产出**：用五步法完整设计 1 道系统题，画出架构图。
- **自检（思考+回答）**：思考——"系统设计题一上来就画架构图，是好做法吗？"　回答方向——不是。应先澄清需求、把模糊要求翻译成可验收指标（如 SLO：P95 延迟、成功率），再做高层设计、组件细化，主动讲权衡和兜底。跳过澄清直接画图是常见扣分点。
- **预计时长**：2 小时。

### Day 24 · 框架实操题（白板手写）

- **学什么**：第 23 章《框架实操题》，白板手写最小 ReAct Agent（不看资料），再做几道"代码找茬"题。
- **动手产出**：白板手写最小 ReAct Agent，做找茬题并记录易错点。
- **自检（思考+回答）**：思考——"手写 Agent 循环时，最容易漏掉的一处是什么？"　回答方向——退出条件。很多人写了"调用-执行-回填"却忘了终止判定，导致死循环。要设最大步数 / token 上限 + 完成判定 + 无进展检测，这是面试官必查的点。
- **预计时长**：2 小时。

### Day 25 · 场景与实战题

- **学什么**：第 24 章《场景与实战题》，针对 6 个典型场景各写一段应对思路，突出"权衡"而非背标准答案。
- **动手产出**：针对 6 个场景各写一段应对思路。
- **自检（思考+回答）**：思考——"面试官问'RAG 能不能彻底消除幻觉'，标准回答姿势是什么？"　回答方向——先给结论"不能，只能大幅降低"，再补手段（引用校验、grounded 标记、工具核实、允许说'不知道'）。凡是"能不能彻底/是不是更好"的问题都在设陷阱，要用"看情况+权衡+代价"作答。
- **预计时长**：1.5 小时。

### Day 26 · 答题框架 + 红旗清单

- **学什么**：第 25 章《答题框架 + 红旗清单》，对照"面试红旗清单"自查，标出自己最易踩的 3 个雷并写对策。
- **动手产出**：对照红旗自查，列出个人易踩雷点 + 对策。
- **自检（思考+回答）**：思考——"哪类回答会立刻被面试官打上红旗？"　回答方向——非黑即白的绝对化断言（"Agent 一定更好""多 Agent 更高级""加个提示就能防注入"）、只谈优点不谈代价、答不出就编。把这些换成"结论+条件+代价"的表达即可拆雷。
- **预计时长**：1.5 小时。

### Day 27 · 论文导读（附录 B）

- **学什么**：附录 B《经典论文导读》，背熟 ReAct / Toolformer / Reflexion / RAG 的话术模板。
- **动手产出**：能脱稿用三句话讲清 ReAct / Toolformer / Reflexion / RAG 各自的核心。
- **自检（思考+回答）**：思考——"用一句话串起 CoT → ReAct → Reflexion 的演进关系。"　回答方向——CoT 让模型"会一步步想"，ReAct 在推理上加"会边想边做"（行动反馈纠正推理），Reflexion 再加"做错了会反思重来"（把失败写成语言反思存进记忆）。一条演进线串起半部 Agent 史。
- **预计时长**：2 小时。

### Day 28 · 术语速查（附录 C）+ 打磨项目讲解

- **学什么**：附录 C《术语速查表》，扫一遍把"面试怎么用"过一遍；打磨第 3 周项目的 3 分钟讲解稿。
- **动手产出**：一份 3 分钟项目讲解稿（问题 - 方案 - 架构 - 权衡 - 结果）。
- **自检（思考+回答）**：思考——"KV Cache 和 Prompt Caching 是一回事吗？"　回答方向——不是。KV Cache 是单次生成内部省重复注意力计算、加速生成；Prompt Caching 是把重复的长系统提示/文档前缀跨请求复用以省成本降延迟，把稳定前缀放最前面命中率最高。别混。
- **预计时长**：2 小时。

### Day 29 · 模拟面试

- **学什么**：找人（或录音自问自答）按第 21-24 章题目实战演练，全程计时。
- **动手产出**：完成一次完整模拟面试，记录卡壳点。
- **自检（思考+回答）**：思考——"模拟面试后，最该优先补的是哪一类问题？"　回答方向——优先补"卡壳/答偏/被追问到没词"的题，尤其是概念辨析和系统设计的权衡部分；把这些整理成"待补清单"，Day 30 集中攻克。模拟面试的价值就在于精准暴露短板。
- **预计时长**：2-3 小时。

### Day 30 · 总复盘（查漏补缺 + 心态调整）

- **学什么**：针对模拟面试暴露的短板做最后补强；整理"我的核心竞争力"话术。
- **动手产出**：一页纸"我的核心竞争力"总结 + 常见问题应答清单。
- **自检（思考+回答）**：思考——"面试官问'你这一个月是怎么学 Agent 的'，你怎么答最有说服力？"　回答方向——亮出这份 30 天计划的产出："我按打地基、通协议、做项目、冲面试四周推进，每周有里程碑产出，项目仓库、评估集、trace、答题复盘都在这里，可以展开讲任意一块。"有轨迹、有产出、有方法论，胜过空谈努力。
- **预计时长**：2-3 小时。

> **本周目标与里程碑**：把知识重组为面试能力，完成至少一次模拟面试，形成稳定答题框架，能用 3 分钟讲清作品集项目。里程碑产出——一份录音复盘的答题集 + 一份 3 分钟项目讲解稿 + 一页"核心竞争力"总结，至此 30 天所有产出汇成一个完整的面试作品包。

## D.6 计划使用建议

- **进度可伸缩**：基础好的可压缩到 3 周，零基础的可拉长到 6 周，核心是保持"学-练-讲"闭环；
- **项目优先**：如果时间紧张，优先保证第 3 周的项目实践——作品集比多刷几道题更有说服力；
- **每周复盘不能省**：每周日花 1 小时回顾，用一页纸总结，是知识内化的关键；
- **面试驱动学习**：即使不马上面试，也建议做第 4 周的题目——它能反过来检验你第 1-3 周学得扎不扎实。

**给不同起点的人的三种改法：**

- **零基础（建议拉长到 6 周）**：把第 1、2 周各拆成两周，多留时间给"敲代码"，前两周宁可慢也别跳过动手。第 3、4 周按原样。
- **有工程经验、缺 Agent 概念（可压到 3 周）**：第 1 周压缩到 3-4 天快速过概念，把省下的时间加到第 3 周做深项目。
- **临近面试、时间只剩 1-2 周（急救版）**：直接做"第 1 周的思考+回答题 + 第 4 周全部"，用暴露的短板反向决定回补哪几章，项目用一个能讲清的小 Demo 顶上。

## D.7 每日复盘模板（照着填，5 分钟）

每天结束花 5 分钟填这四行，比写长笔记更有效：
```
今日最重要的 1 个概念：______________________
我能不能讲清（能/不能，不能则明天补）：______
今天动手跑/写了什么（贴命令或提交号）：______
明天第一件事：________________________________
```
> **经验**：坚持填这个模板，30 天后你会有 30 条"最重要概念"——这就是一份天然的面试速记卡，考前扫一遍胜过临时抱佛脚。

## D.8 冲刺期的三个心态提醒

1. **不求全，求通**：30 天不可能精通所有细节，目标是建立完整框架 + 一两个深入的项目；
2. **动手 > 阅读**：读十遍不如跑一遍，每个概念尽量都动手验证；
3. **能讲清 > 记得住**：能给别人讲明白，才是真的懂——多用费曼学习法。

> **面试会怎么问**：面试官常在最后问"你是怎么学 Agent 的、这一个月做了什么"。这时直接亮出这份 30 天计划的产出——"我用四周分别打地基、通协议、做项目、冲面试，每周都有里程碑产出，项目仓库和答题复盘都在这里"。有轨迹、有产出、有方法论，比空谈"我很努力"强太多。

## D.9 常见执行问题与对策（提前想好，别中途放弃）

30 天计划最大的敌人不是难度，而是中途掉队。下面把学习者最常遇到的问题和对策列出来，遇到时对号入座。

| 常见问题 | 根因 | 对策 |
|---|---|---|
| 某天任务没做完，滚成一堆欠账 | 单日目标定太满 / 临时有事 | 设"最小完成量"，实在没时间就只做当日那 15 分钟"思考+回答"；欠账集中放周日补，不带进下周 |
| 代码总跑不通，卡一整天 | 环境 / 版本 / Key 配置问题 | 先按 README 对齐版本与 Key，自查 15 分钟仍不行就换一个已知能跑的最小示例，别死磕 |
| 概念看懂了但不会写代码 | 只读不练，缺手感 | 强制"每个概念至少动手跑一次"，哪怕只是改别人的例子跑通 |
| 学了后面忘了前面 | 没有复盘和串联 | 坚持每日复盘模板 + 每周日一页纸总结，用"演进线"把知识串成网 |
| 项目做得太大做不完 | 贪多求全 | 砍到"一个能讲清的最小可用版本"，先跑通再迭代，功能少不丢人，讲不清才丢分 |
| 越临近面试越焦虑 | 追求"全都会" | 回到"不求全求通"，锁定一两个能深聊的项目 + 核心概念，其余会讲思路即可 |

**关于时间管理的三条实操建议：**

- **固定时段而非固定时长**：与其规定"今天学 2 小时"，不如固定"每晚 8-10 点雷打不动学 Agent"。固定时段更容易形成习惯。
- **番茄钟拆动手环节**：读文档可以整块时间，但写代码 / 调试建议用 25 分钟番茄钟拆开，每个番茄钟聚焦一个小目标（跑通一个函数、加一个工具）。
- **周末做"重活"**：把需要大块时间的项目实践（第 3 周尤其）安排在周末，工作日则做概念学习和轻量练习，符合精力分布。

## D.10 30 天产出清单（对照验收）

30 天结束时，你应该攒下这样一份"作品包"。把它当验收清单，缺哪补哪：
```
□ 一份"Agent 核心概念一页纸"（第 1 周）
□ 组件图 + ReAct 循环图 + Function Calling 五步图（第 1、2 周）
□ 三大框架选型对照表（第 2 周）
□ 两个可运行的框架 Demo（smolagents + 结构化抽取）（第 2 周）
□ 一个带评估集/tracing/护栏的作品集项目 + README（第 3 周）
□ 文档问答 Agent + 传统/Agentic RAG 对比结论（第 3 周）
□ 迷你客服系统架构图（第 3 周）
□ 6 道概念题录音 + 一道系统设计题设计稿（第 4 周）
□ 白板手写最小 ReAct Agent（第 4 周）
□ 3 分钟项目讲解稿 + 一页"核心竞争力"总结（第 4 周）
□ 30 条"每日最重要概念"速记卡（贯穿全程）
```
> **经验**：这份清单本身就是你面试时最硬的底气。当被问到任何一个方向，你都能说"我做过、在这里、可以展开讲"。学习的终点不是"看完了"，而是"能拿出东西并讲清楚"。

## 本附录小结

- 30 天分四阶段：**打地基（卷一二）→ 通协议+框架（卷三四）→ 做项目（卷五六）→ 冲面试（第二部分+附录）**。
- 每天都给出"学什么（指向章节）/ 动手产出 / 自检（思考+回答）/ 预计时长"四件事；每周补齐"每周目标 / 本周思考+回答 / 里程碑产出"。
- 三条硬规则贯穿始终：每日 15 分钟思考+回答、产出进同一仓库、每周日复盘；D.7 给了 5 分钟每日复盘模板。
- 开头配了一张"30 天 Agent 学习路线图"的图片生成描述，可据此出一张导览信息图。
- 计划可按起点伸缩，给出了零基础、有工程经验、临近面试三种改法；D.9 备好"常见执行问题与对策"，D.10 给出可对照验收的"30 天产出清单"。
- 贯穿始终的三个心态：**不求全求通、动手优先、能讲清才算懂**。

> **全书完结语**：学习 Agent 没有捷径，但有正确的路径。你已经拥有了从"认识 Agent"到"生产落地"再到"从容面试"的完整地图。剩下的，就是动手走完它。祝你学有所成、面试顺利！
