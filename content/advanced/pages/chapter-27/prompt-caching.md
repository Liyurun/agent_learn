## 真实问题

一个多轮 Agent 的系统指令和工具定义共 20,000 Token，本应是稳定前缀；工程师却把当前时间和随机请求 ID 放在最前，每轮第一个字节都变化，缓存复用机会消失，延迟和账单异常上升。

## 现象与输入

KV Cache（Key-Value Cache，键值缓存）通常指一次生成中复用注意力键值；Prompt Caching（提示缓存）是 API 对重复提示前缀提供的跨请求复用能力。二者相关但不能混称。缓存阈值、期限、计价和支持模型会变化，必须查当前官方文档。

## 原理

把稳定且共享的内容放前，动态内容放后：
```text
[系统规则][稳定工具定义][共享参考资料] | [历史][当前请求][随机 ID]
                  可复用前缀          |         动态后缀
```
计算命中率时同时记录 cache creation、cache read、普通 input 与 output，避免只看总 Token。缓存是性能优化，不改变内容是否应该进入上下文的判断。

## 最小可运行演示
```python
from hashlib import sha256

def prefix_key(system: str, tools: str) -> str:
    return sha256((system + "\n" + tools).encode()).hexdigest()[:12]

def main() -> None:
    system, tools = "只读审查", "[read,diff,test]"
    first = prefix_key(system, tools)
    second = prefix_key(system, tools)
    changed = prefix_key("时间=动态\n" + system, tools)
    print("稳定前缀命中:", first == second)
    print("前缀改变命中:", first == changed)

if __name__ == "__main__":
    main()
```
运行 `python cache_demo.py`，预期输出：
```text
稳定前缀命中: True
前缀改变命中: False
```
哈希相等只演示“完全相同前缀”的概念，不模拟厂商缓存键、隐私隔离或计费。

## 真实系统对应

Anthropic Prompt Caching 官方文档公开缓存断点、前缀匹配和用量字段；价格与最短可缓存长度等参数依模型和时间变化。本文不固定抄录易过时数字。把稳定内容前置是基于公开接口的工程建议，不代表服务端缓存实现细节。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| cache read 长期为零 | 时间戳或随机 ID 前置 | 对请求前缀做规范化哈希对比 | 动态字段后移；稳定块版本化 | 请求间无共享前缀时无需强求 |
| 命中高但总成本仍高 | 动态历史无限增长 | 分拆四类用量和输出长度 | 压缩后缀、限制工具结果、优化输出 | 不可为省钱删除必要证据 |

## 思考：为了缓存命中是否应永不压缩？

### 回答

不应。历史持续增长最终会增加成本、延迟和退化风险。应比较压缩造成的一次缓存重建成本与后续节省，设置批量压缩和滞回阈值，而不是每轮改写或永不改写。

## 思考：缓存命中会改善回答质量吗？

### 回答

缓存主要改变计算复用、延迟和费用；相同前缀在语义上没有因缓存自动变好。质量仍取决于上下文选择与模型能力。缓存布局不能成为保留无关内容的理由。

## 真实场景：一个时间戳让稳定前缀全部失效

工单 Agent 每轮都发送约两万 Token 的系统政策、工具定义和产品手册。团队已启用提示缓存，却连续一周观察到缓存读取量接近零。请求对比显示，组装器在最前面插入 `request_id`、当前时间和轮次；后面的稳定内容虽然逐字相同，但从首字节开始已不再共享前缀。

工程师把动态元数据移动到历史之后，稳定规则、工具定义和共享资料放在前面，并给每个稳定块记录内容哈希和版本。第二轮起可以观察到缓存读取字段变化。与此同时，团队没有为了命中而永久保留已经废止的工具：工具版本变化时主动接受一次缓存重建，换取语义正确。

这类优化必须看供应商返回的用量字段，而不是自行计算哈希后宣布“命中”。本地哈希只说明两个字符串相同，实际缓存还受支持模型、最小长度、缓存断点、有效期和服务端策略影响。

## 前缀设计的机制推导

自回归模型按序处理输入，提示缓存接口利用重复前缀减少重复计算。由此前缀应从稳定到动态排列：组织级安全规则、版本固定的工具定义和共享资料在前；会话历史、当前请求、追踪 ID 与时间在后。稳定块内部也应确定性序列化，避免字典键顺序、空格或随机工具排序造成无语义差异。

稳定不等于永恒。安全政策更新、工具 schema 变化或资料版本升级时，缓存失效是正确行为。工程目标是减少无意义变化，而不是阻止必要变化。可以把版本号纳入内容，并按发布批次更新，便于说明哪次重建来自真实变更。

成本分析至少分四项：缓存创建输入、缓存读取输入、未缓存输入和输出。若读取命中很高但动态历史每轮增长，总成本仍会上升；若为了短前缀频繁压缩，缓存创建次数可能增加。应在完整会话上比较总费用和延迟，而不是挑一轮最好看的数字。

## 可运行的规范化前缀示例
```python
import json
from hashlib import sha256

def stable_prefix(policy: dict, tools: list[dict]) -> str:
    payload = {
        "policy": policy,
        "tools": sorted(tools, key=lambda item: item["name"]),
    }
    return json.dumps(payload, ensure_ascii=False, sort_keys=True, separators=(",", ":"))

def digest(text: str) -> str:
    return sha256(text.encode("utf-8")).hexdigest()[:12]

def main() -> None:
    policy = {"mode": "只读", "version": 3}
    tools_a = [{"name": "test"}, {"name": "read"}]
    tools_b = [{"name": "read"}, {"name": "test"}]
    a = stable_prefix(policy, tools_a)
    b = stable_prefix(policy, tools_b)
    changed = stable_prefix({"mode": "只读", "version": 4}, tools_b)
    print(f"顺序变化仍相同={digest(a) == digest(b)}")
    print(f"版本变化仍相同={digest(a) == digest(changed)}")
    print(f"前缀长度={len(a)}")

if __name__ == "__main__":
    main()
```
保存为 `stable_prefix.py`，运行 `python stable_prefix.py`。完整预期输出：
```text
顺序变化仍相同=True
版本变化仍相同=False
前缀长度=75
```
程序通过排序和规范化 JSON 消除工具输入顺序造成的抖动，并让政策版本变化显式改变摘要。长度是字符数，不是 Token 数；哈希也不是厂商缓存键。真实请求应按官方 SDK 的消息结构设置缓存控制，并读取 API 返回的实际用量。

## 官方案例与边界

Anthropic Prompt Caching 文档公开前缀匹配、缓存断点和相关用量字段，支持本页的布局与观测建议。具体模型支持、最短可缓存长度、写入和读取价格、缓存期限可能更新，因此正文不写死数值。KV Cache 是模型推理中的通用术语，不应把 API 提示缓存描述成用户可直接管理的底层注意力缓存。

缓存不能跨越安全边界。多租户系统即使前缀文本相同，也必须遵守供应商和自身的数据隔离要求；不能设计一个共享业务缓存把租户私有内容暴露给其他请求。缓存命中也不是“模型记住了用户”，它不应承担长期记忆或状态恢复。

## 优化前后与定位

| 现象 | 优化前 | 优化后 | 观测证据 |
|---|---|---|---|
| 相同任务读缓存为零 | 时间、请求 ID 在最前 | 动态字段移到后缀 | 规范化前缀哈希与 API 用量 |
| 工具顺序随机导致重建 | 从无序集合序列化 | 按稳定键排序 | 保存发送前字节摘要 |
| 命中率高但账单增长 | 历史后缀无限增长 | 批量压缩并清理工具结果 | 分项 Token 与整会话成本 |
| 为命中保留旧政策 | 把缓存当目标 | 内容版本变化主动失效 | 政策版本和任务正确率 |
| 测试环境命中、线上不命中 | 模型或缓存配置不同 | 记录模型、断点和配置版本 | 请求元数据与响应字段 |

一次优化实验应选取完整的二十轮会话，分别运行原布局和稳定前缀布局，统计首轮创建、后续读取、普通输入、输出与延迟分位数。若质量指标下降，先检查是否为了稳定删除了必要动态证据；不能用成本收益掩盖任务失败。
