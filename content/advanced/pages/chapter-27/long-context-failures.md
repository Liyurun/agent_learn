## 真实问题

法律检索系统把正确条款放在 70 段材料的第 35 段，模型却引用首尾两段的次相关解释。调大窗口后材料都能送入，但准确率没有同步提高。

## 现象与输入

Lost in the Middle（中间信息遗失）研究显示，长上下文任务的表现会受相关信息位置影响，关键信息在中部时可能比首尾更难利用。它是实验现象，不应被简化为“所有模型必然呈固定 U 形曲线”。生产中还要区分：

- **冲突**：同一事实有多个版本。
- **干扰**：相关但不回答当前问题的内容过多。
- **污染**：网页或工具结果夹带指令。
- **位置退化**：关键证据被大量文本包围。

## 原理

先检索、再去重、再按可信度与相关性排序，最后把规则放头部、当前请求和最关键证据放尾部附近。对多个证据块可采用“高分块分布到两端”的启发式，但必须用任务集评估，不能当作普适定律。

## 最小可运行演示
```python
def edge_pack(items: list[tuple[str, float]]) -> list[str]:
    ranked = [text for text, _ in sorted(items, key=lambda x: x[1], reverse=True)]
    packed = [""] * len(ranked)
    left, right = 0, len(ranked) - 1
    for i, text in enumerate(ranked):
        pos = left if i % 2 == 0 else right
        packed[pos] = text
        left += i % 2 == 0
        right -= i % 2 == 1
    return packed

def main() -> None:
    docs = [("法规A", .99), ("解释B", .86), ("背景C", .42), ("旧版D", .10)]
    print(edge_pack(docs))

if __name__ == "__main__":
    main()
```
运行 `python edge_pack.py`，预期输出：
```text
['法规A', '背景C', '旧版D', '解释B']
```
最相关两块位于首尾，弱证据位于中间。真实系统还应保留文档 ID、版本和分数，并处理相互矛盾的证据。

## 真实系统对应

“Lost in the Middle: How Language Models Use Long Contexts”论文提供了位置敏感的实验依据。LangSmith 等追踪工具可记录实际发送消息、检索文档与调用成本，帮助把“模型忘了”拆解为检索漏召回、排序错误或组装错误。可观察能力是公开接口；具体生产排序器属于用户系统实现。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 正确证据已检索仍答错 | 高价值块在中部且噪声过多 | 固定内容，仅交换块位置做对照 | 去重、裁剪、重排，尾部重申问题 | 极短上下文无需复杂重排 |
| 引用了废止规则 | 版本冲突未显式化 | 记录 source/version/effective_at | 过滤失效版本；冲突时拒答并升级 | 历史研究需同时展示旧版 |

## 思考：只把最相关文档放在最后是否足够？

### 回答

不够。相关性分数可能错误，文档之间可能冲突，最后位置还要容纳当前问题和输出约束。应同时验证召回、版本、可信来源和证据覆盖，并通过消融实验比较布局；位置优化只能补充内容选择，不能挽救错误证据。

## 思考：如何证明问题来自组装而非模型？

### 回答

固定模型、温度和问题，对同一证据做位置交换与噪声删减；记录每次实际请求和结果。如果仅改变布局即可稳定改变表现，说明组装是主要变量。仍需多样本重复，避免把随机波动误判为因果。

## 真实场景：同一法规、三个位置、三种答案

合同审查系统需要判断一份供应协议能否自动续期。检索返回七十段材料，其中第十四段是已废止旧规，第三十五段是当前有效条款，第六十九段是内部操作说明。线上回答引用旧规并判断“可自动续期”。排查人员首先怀疑检索，因为正确条款没有出现在答案里；查看最终请求后才发现，正确条款确实进入窗口，却夹在大量相似解释之间，且没有版本字段。

团队构造三份请求，只改变当前条款的位置，其他字节保持一致：放在开头、放在中间、放在问题前。然后对每种布局重复运行固定任务集，记录引用条款 ID 和结论。中间布局错误更多，删掉重复解释后差异缩小。这个结果能证明该模型和该任务存在位置敏感，不能外推为所有模型都服从同一曲线。

修复不是机械地把所有高分文档放最后。团队先按 `effective_at` 去掉废止版本，再将当前法规与内部操作说明分组；系统规则放开头，关键证据及其来源放在当前问题之前，次要背景进入摘要。若两个有效来源仍矛盾，输出“需法务确认”而不是让排序分数替代法律判断。

## 四类故障的可观测差异

缺失意味着正确证据根本不在最终请求，需查召回与过滤；冲突意味着多个互斥版本同时出现，需查版本和生效范围；干扰意味着正确证据存在但被大量相似内容稀释，可通过去重和消融验证；污染意味着外部文本包含“忽略系统规则”等指令，需要把数据与指令分隔，并在工具和权限层防护。只统计上下文长度无法区分这四类问题。

位置调整必须在内容正确之后发生。把废止法规移到结尾只会让错误更醒目；把恶意网页提示移到开头或结尾都不安全。可靠流水线先验证来源、版本与权限，再做布局实验。

## 可运行的位置消融程序
```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Evidence:
    text: str
    score: float
    version: int
    active: bool

def prepare(items: list[Evidence]) -> list[str]:
    valid = [item for item in items if item.active]
    best_by_text: dict[str, Evidence] = {}
    for item in valid:
        current = best_by_text.get(item.text)
        if current is None or item.version > current.version:
            best_by_text[item.text] = item
    ranked = [(f"v{x.version}:{x.text}", x.score) for x in best_by_text.values()]
    return edge_pack(ranked)

def main() -> None:
    docs = [
        Evidence("允许自动续期", .91, 1, False),
        Evidence("禁止默认自动续期", .99, 2, True),
        Evidence("转人工复核", .82, 3, True),
        Evidence("一般背景", .30, 1, True),
    ]
    print("\n".join(prepare(docs)))

if __name__ == "__main__":
    main()
```
保存为 `layout_ablation.py`，执行 `python layout_ablation.py`，完整预期输出：
```text
v2:禁止默认自动续期
v1:一般背景
v3:转人工复核
```
旧版“允许自动续期”因 `active=False` 被过滤，最高相关证据位于开头，第二条关键证据位于末尾。若把旧版错误标为有效，程序会保留冲突；真实系统此时还需按主题检测互斥结论，不能只相信版本号。数据类和排序函数是教学实现，不是论文复现实验。

## 从“模型忘了”到具体定位

排查时保存四份工件：检索候选、过滤后证据、最终序列和模型引用。候选无正确条款是召回问题；候选有而过滤后无，是过滤器问题；最终序列有但引用错，可做位置与噪声消融；引用正确而业务动作错误，应查解析与执行。这个分层能避免团队在没有证据时反复调温度或升级模型。

优化前请求含七十段未编号材料，无法判断答案引用哪一版；优化后每块携带 `source_id`、版本、生效时间与相关分数，废止版本不进入生成请求，当前问题紧邻关键证据。离线评估不只判断答案文本，还检查引用 ID 是否覆盖金标准。

## 论文与产品边界

《Lost in the Middle》研究通过受控任务展示长上下文利用具有位置敏感性，支持开展布局评估；它没有证明任何固定位置策略能普遍最优。LangSmith 的公开能力可保存运行、输入输出和元数据，便于做对照；平台不会自动替用户定义何为有效法规，也不会替代版本治理。本文的边缘交错算法是一种可测试启发式，不应直接成为高风险系统的唯一排序器。

## 生产优化对比

| 维度 | 优化前 | 优化后 | 失败时查看 |
|---|---|---|---|
| 版本 | 新旧条款同时发送 | 先按生效状态过滤 | 文档 ID 与 `effective_at` |
| 去重 | 同义解释重复十余次 | 同来源与语义近重复合并 | 过滤前后块数 |
| 布局 | 依检索返回顺序拼接 | 关键证据靠近首尾与问题 | 最终序列快照 |
| 评估 | 单次主观阅读 | 固定任务集做位置消融 | 引用准确率与拒答率 |
