## 真实问题

团队把编码规范写进一次性对话，换会话后 Agent 又使用被禁用的库；又把整份 200 页手册贴进每轮提示，成本和干扰随之上升。正确做法不是猜测产品内部“记忆层数”，而是使用文档公开的入口并明确作用域。

## 现象与输入

- 项目约束：需要随仓库共享并审查。
- 目录专用约束：只应在特定路径相关任务中生效。
- 用户偏好与项目观察：需要跨会话复用，但可被查看和修正。
- 高噪声探索：不应永久污染主会话。

## 原理与公开边界

根据 Claude Code 官方文档（检索日期 2026-08-23）：

- `CLAUDE.md` 用于提供持久指令，作用域取决于文件位置。
- `.claude/rules/` 可组织项目规则，并可按路径限定适用范围。
- Auto Memory（自动记忆）保存 Claude 从工作中记录的内容；它不是应用数据库，重要业务事实仍应由业务系统负责。
- Compaction（上下文压缩）在会话接近限制时总结较早内容；压缩有损，不能代替源记录。
- Subagent（子智能体）拥有独立上下文，适合隔离探索。
- Skill（技能）把说明与资源按需加载。

以上是公开功能层面的描述。本章不声称知道优先级算法、存储服务、摘要提示或缓存实现。

## 最小可运行演示
```python
from pathlib import Path

def scoped_rules(root: Path, target: Path) -> list[str]:
    rules = [root / "CLAUDE.md"]
    if target.suffix == ".py":
        rules.append(root / ".claude/rules/python.md")
    return [p.read_text(encoding="utf-8").strip() for p in rules if p.exists()]

def main() -> None:
    root = Path("demo_project")
    (root / ".claude/rules").mkdir(parents=True, exist_ok=True)
    (root / "CLAUDE.md").write_text("提交前运行测试", encoding="utf-8")
    (root / ".claude/rules/python.md").write_text("使用类型标注", encoding="utf-8")
    print(scoped_rules(root, root / "app.py"))

if __name__ == "__main__":
    main()
```
运行 `python scoped_rules.py`，预期输出：
```text
['提交前运行测试', '使用类型标注']
```
这是“按作用域选规则”的教学参考实现，并非 Claude Code 的规则解析器。

## 真实系统对应

官方入口解决的是不同生命周期信息的安放问题：共享项目约束放版本库，路径规则靠近作用域，可纠正观察进入自动记忆，高噪声任务交给子智能体。通用原则是“信息拥有明确所有者、作用域和失效方式”，而不是把所有内容塞进一个全局文件。

## 生产踩坑

| 症状 | 根因 | 如何观测与复现 | 修复与预防 | 不适用边界 |
|---|---|---|---|---|
| 同一规则多处冲突 | 用户、项目、目录规则重复 | 列出实际加载文件和冲突句 | 单一事实源；规则写明范围和理由 | 合规覆盖可有意提高优先级 |
| 自动记忆长期错误 | 把推测当稳定事实 | 新会话复核记忆内容 | 定期审阅，重要事实由项目文件承载 | 不把密码、令牌写入记忆 |

## 思考：`CLAUDE.md` 是否应该越长越好？

### 回答

不应该。它应保存跨任务稳定且可执行的约束。临时任务、冗长教程和可从代码直接读取的信息会降低信号密度。更细的路径规则放到对应作用域，高噪声资料按需读取；规则还应可验证，例如“提交前运行 `pytest -q`”优于“保证高质量”。

## 思考：自动记忆能否取代业务状态库？

### 回答

不能。自动记忆面向辅助协作，业务状态需要事务、权限、审计、模式约束和恢复保证。订单状态、授权决策等必须存入受控系统；记忆最多保存工作偏好或可纠正的项目观察。

## 场景：单体仓库中的规则串扰

一家支付团队的单体仓库同时包含 Python 风控服务、TypeScript 管理台和 Terraform 基础设施。根目录规则要求“修改后运行对应测试”，前端目录要求使用 `pnpm`，基础设施目录要求任何变更先生成计划且禁止自动应用。工程师曾把三套命令全部写进根 `CLAUDE.md`。Agent 修改一个 React 组件时，不但尝试运行 Python 测试，还读取了基础设施说明；修改 Terraform 时又沿用了“可自动修复”的前端习惯。

问题不在于规则数量本身，而在于作用域丢失。共享约束适合根目录，语言和目录专用规则应靠近适用路径，临时任务条件留在当前请求。若两条规则冲突，还要能指出各自来源，不能把最终加载文本当作无来源的“大提示”。

优化后的规则分布可以是：
```text
repo/CLAUDE.md
  - 修改后运行对应测试
  - 禁止输出密钥
repo/.claude/rules/frontend.md
  paths: apps/web/**
  - 使用 pnpm test
repo/.claude/rules/infra.md
  paths: infra/**
  - 只生成 terraform plan，禁止 apply
```
这里展示的是作用域思想。具体规则语法、搜索位置和优先关系应以当前 Claude Code 官方文档为准，不能只依据教学片段复制配置。

## 六类入口的生命周期

`CLAUDE.md` 适合团队共同维护、能够代码审查的稳定指令；路径规则适合局部技术约束；自动记忆适合可纠正的个人或项目观察；压缩处理已发生的长会话；子智能体隔离一次探索；技能按任务加载说明和资源。它们不是互相替代的“六级存储”。同一句“生产库只读”若属于组织权限，应由数据库凭证强制；在项目文件中重复它，只是帮助模型提前选择安全计划。

选择入口时，可问三个问题：谁应修改它，何时生效，错误后如何纠正。需要经评审且对所有贡献者生效的内容放仓库；个人偏好不能冒充团队政策；会频繁变化的部署状态不应写进长期说明；审计事实不能只留在有损压缩结果里。这样可防止一个全局文件同时承担规范、状态库、教程和日志。

## 可运行的范围匹配示例
```python
from pathlib import Path
from fnmatch import fnmatch

RULES = [
    ("**", "修改后运行对应测试"),
    ("apps/web/**", "使用 pnpm test"),
    ("infra/**", "禁止 terraform apply"),
]

def rules_for(relative_path: str) -> list[str]:
    return [text for pattern, text in RULES if pattern == "**" or fnmatch(relative_path, pattern)]

def main() -> None:
    for target in ["apps/web/Button.tsx", "infra/main.tf"]:
        print(target)
        for rule in rules_for(target):
            print(f"- {rule}")

if __name__ == "__main__":
    main()
```
保存为 `rule_scope.py` 并运行 `python rule_scope.py`。完整预期输出：
```text
apps/web/Button.tsx
- 修改后运行对应测试
- 使用 pnpm test
infra/main.tf
- 修改后运行对应测试
- 禁止 terraform apply
```
这个程序不读取 Claude Code 配置，也没有模拟其匹配器；它只证明“同一目标应接收共享规则和局部规则”。生产实现还应输出命中的文件、规则版本和冲突项。若目标同时命中“允许自动部署”和“禁止 apply”，高风险规则应触发人工决策，而不是依赖列表顺序覆盖。

## 一次记忆污染的定位过程

团队发现新会话总把包管理器写成 `npm`。第一步检查当前模型输入，确认错误是否来自项目文件、路径规则、自动记忆或用户消息。第二步在仓库中查找同义规则，核对适用目录。第三步新建最小会话，只询问包管理命令；若错误稳定复现，再修正对应来源。删除所有记忆虽然可能暂时消失症状，却会损失其他有效观察，也无法证明根因。

优化前，团队在三个位置分别写“使用 pnpm”“默认 npm”“跟随现有 lockfile”，没有生效范围；优化后，仓库根只写“跟随锁文件”，前端路径明确 `pnpm-lock.yaml` 对应命令，自动记忆不再保存团队规范。每次规则加载报告附来源，冲突能在执行前暴露。

## 官方边界与不适用情形

官方文档能够证明上述入口存在及其用户可见行为，不能证明本页的生命周期表就是产品内部模型。Auto Memory 的内容可被用户查看和管理，不等于具备数据库事务、外键或强一致性。Compaction 可以延长会话可用性，不承诺逐字无损。Subagent 有独立上下文，不等于操作系统沙箱。Skill 按需加载资源，不代表任何任务都应封装成技能。

对于只有一个文件、一次问答的任务，建立复杂规则目录没有收益；对监管要求明确的流程，规则文件也不能替代策略引擎和审计系统。产品能力应放在它能负责的层次：帮助模型获得适当信息，而不是承担最终授权。

## 优化前后与排错证据

| 问题 | 优化前 | 优化后 | 定位证据 |
|---|---|---|---|
| 跨目录串扰 | 所有规范塞入根文件 | 稳定共享规则与路径规则分离 | 目标路径、命中规则及来源 |
| 换会话忘记 | 临时对话承载团队约束 | 受版本控制的项目说明 | 新会话最小复现 |
| 错误观察持续出现 | 推测写入长期记忆 | 记忆可审阅，事实回归项目文件 | 记忆内容与提交历史 |
| 探索噪声污染 | 所有日志留主会话 | 独立子任务只回传证据摘要 | 子任务输入、返回 schema |
