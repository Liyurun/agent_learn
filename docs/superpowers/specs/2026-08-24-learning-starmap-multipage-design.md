# 学习星图与多页面发布设计

日期：2026-08-24

## 目标

将当前一次加载整本内容的 GitHub Pages 站点改为多页面静态站点：

- 首页以已确认的“知识星图”为核心，展示六篇、章节关系和学习进度。
- 用户点击章节后进入独立 URL，只下载和渲染该页内容。
- 保留现有完整 HTML 与 PDF 导出，不改变离线整书和 PDF 的行为。
- 保留主题、字号、章节目录、代码复制、问答、测验等已有交互。

不引入前端框架、服务端运行时、登录系统、八周计划或今日任务。

## 信息架构与路由

GitHub Pages 发布目录使用目录式静态路由：

| 页面 | 路径 | 内容 |
| --- | --- | --- |
| 学习星图首页 | `/` | 星图、六篇概览、全书进度、章节入口 |
| 导读 | `/guide/` | 学习模式、知识地图和使用说明 |
| 模块复盘 | `/quiz/` | 模块复盘交互 |
| 大牛观点 | `/insights/` | 观点墙 |
| 正文章节 | `/ch1/` 至 `/ch24/` | 每页一章 |
| 实战工坊导读 | `/labs/` | Lab 使用说明 |
| 实战章节 | `/lab1/` 至 `/lab4/` | 每页一个 Lab |
| 参考资源 | `/resources/` | 参考来源和页脚说明 |

所有发布页面均生成成 `<route>/index.html`，因此 GitHub Pages 可直接提供无扩展名的尾斜杠 URL。页面内三级标题继续使用 fragment，例如 `/ch7/#ch7-section-03`。

`content/book.json` 仍是内容顺序和标题的唯一事实来源。章节与 Lab 路由由其 `id` 派生；特殊聚合页由构建器中的显式页面定义管理，避免给每个内容项增加重复配置。

## 首页视觉

首页采用深色“知识星图”，不使用课程表、今日任务或仪表盘卡片墙。

### 桌面端

- 顶部保留品牌、学习星图、章节库、实战工坊、面试冲刺等导航。
- 六篇各自形成一个星座，章节是星座内的星点，连线只表达同篇章节顺序。
- 已完成章节为发光实心星；当前章节为金色呼吸星；未完成章节为空心星。
- 默认展示全部星座。悬停某个星座时，其余星座降低透明度。
- 点击星座或底部图例后，右侧“星轨”面板展示该篇章节清单。
- 点击星点或星轨条目进入独立章节 URL。
- 底部只显示星座图例和全书点亮进度，不显示时间计划。

### 移动端

移动端不缩小整张二维星图。它改为纵向“星座轨道”：

- 每篇是一个可展开区块，标题、篇章色和完成数始终可见。
- 展开后按顺序显示章节星点和连接线。
- 当前篇默认展开，其余篇折叠。
- 点击章节直接进入独立 URL。

这样保留星图概念，同时保证文字尺寸、触控目标和导航效率。

### 视觉语言

- 主背景使用近黑夜空色，辅以深青、蓝、金、珊瑚、紫、绿色区分六篇。
- 标题延续书籍感衬线字体，导航和状态使用无衬线及等宽字体。
- 星点、连线和轻微呼吸效果承担识别，不增加装饰性渐变球或大面积卡片。
- 动画遵守 `prefers-reduced-motion`；关闭动画后当前章节仍通过颜色和描边区分。

## 页面构建架构

### 完整书构建保持不变

`tools/build.py` 继续生成根目录 `agent-learning-handbook.html`。它仍包含全书内容，供：

- 本地完整阅读；
- `tools/export_pdf.js` 导出 PDF；
- 现有完整 HTML 校验。

### Pages 构建改为多页面

`tools/build_pages.py` 调用共享构建函数，生成：

- `dist/index.html`：学习星图首页；
- 各路由目录下的 `index.html`；
- `dist/assets/`、`dist/_shared/`；
- `dist/Agent学习与面试宝典.pdf`。

构建过程先写入临时目录，通过后原子替换 `dist/`，保持当前失败不覆盖旧产物的性质。

### 模板边界

- 新增 `templates/learning-map.html`，只负责星图首页。
- 现有 `templates/handbook.html` 增加少量页面参数占位符，用同一套样式和交互生成完整书及单内容页。
- 页面参数至少包含标题、资源前缀、封面可见性和当前页面数据。
- 星图样式与行为分别放入 `assets/learning-map.css` 和 `assets/learning-map.js`，不继续扩大现有内联脚本。

### 页面上下文

每个内容页注入只读的 `window.HANDBOOK_PAGE`：

- 当前页面 ID、标题和路由；
- 全部章节与 Lab 的顺序、标题和路由；
- 当前条目的上一篇、下一篇；
- 锚点到所属路由的映射。

`learner-guide.js` 使用该上下文生成全书序号和跨页上一篇/下一篇，不再仅依赖当前 DOM 中的章节数量。

## 链接与资源处理

### 静态链接

构建器先为所有渲染内容建立全局锚点索引，再改写内部链接：

- 当前页面内目标保留为 `#target`。
- 其他页面目标改为相对站点根路径，例如 `../resources/#cite-1`。
- 导航中的章节、篇章和资源链接直接使用页面路由。

所有发布路由深度统一为一层，因此内容页资源前缀固定为 `../`，首页固定为 `./`。不写死仓库名，保证站点可部署在 GitHub Pages 项目子路径下。

### 动态链接

`handbook-interactions.js` 中由 `handbook-data.js` 生成的内部链接统一经过路由解析函数。外部 HTTP(S) 链接保持原样。

### 静态资源

章节页只加载通用 CSS、通用交互和当前章节需要的 DOM。现阶段保留共享 `handbook-data.js`，避免拆分数据带来额外维护成本；图表和组件初始化继续在挂载点不存在时安全跳过。

## 学习进度

继续使用浏览器 `localStorage`，不增加账号系统。

- 已有键 `ah-read-chapters` 保持兼容。
- 星图根据该键点亮章节。
- 当前章节读取固定键 `ah-last-chapter`；没有记录或记录无效时选择第 1 章。
- 增加最近访问记录时，只保存章节 ID，不保存阅读内容或个人信息。
- `localStorage` 不可用时，页面仍可正常浏览，星图显示默认未完成状态。

## 可访问性与降级

- 星图 SVG 提供整体 `aria-label`；每颗可点击星同时提供可聚焦链接和可读名称。
- 所有交互支持键盘聚焦、Enter 激活和清晰的焦点样式。
- 颜色不是唯一状态信号：已完成、当前、未完成分别使用实心、双环、空心形状。
- JavaScript 不可用时，首页仍显示六篇章节链接列表；章节页正文完整可读。
- 尊重 `prefers-reduced-motion`，禁用星点呼吸和过渡动画。
- 移动端触控目标不小于 44px，正文不依赖横向缩放。

## SEO 与元数据

- 每个页面有独立 `<title>`，格式为“章节标题 · Agent 学习与面试宝典”。
- 每个页面设置简短 description。
- 首页和内容页使用规范 URL 结构，不依赖 hash 路由。
- 生成 `sitemap.xml`，包含首页和所有内容路由。
- 旧的 `/#ch7` 等书签由首页脚本读取 hash，并跳转到对应新路由，保留已有链接兼容性。

## 错误处理

构建阶段遇到以下情况直接失败，不发布不完整目录：

- 一个锚点归属多个页面；
- 内部链接目标不存在；
- 两个内容项生成同一路由；
- 页面引用的本地资源不存在；
- 页面缺少标题、内容或当前页上下文；
- 路由输出文件写入失败。

运行时找不到进度数据或浏览器禁用存储时，只降级进度展示，不影响导航和正文。

## 测试与验收

### 单元测试

- 路由生成覆盖 24 章、4 个 Lab 和聚合页。
- 内部锚点正确改写为页内或跨页 URL。
- 导航在首页和内容页使用正确的相对路径。
- 上一篇/下一篇跨页面链接顺序正确。
- 路由冲突、悬空锚点和缺失资源会导致构建失败。

### 构建测试

- `npm test` 通过。
- `npm run build` 继续生成完整 HTML。
- `npm run pages` 生成全部路由，且单章 HTML 不包含其他章节正文。
- `npm run verify` 同时校验完整 HTML 和 `dist/` 多页面产物。
- `npm run pdf` 继续从完整 HTML 生成 PDF。

### 浏览器验收

- 桌面端检查星图默认、悬停聚焦、点击切换星轨和章节跳转。
- 移动端检查纵向星座轨道、展开收起、文字尺寸和触控区域。
- 直接访问 `/ch7/` 可加载正文，刷新后不返回 404。
- 从章节引用跳到 `/resources/#cite-*` 可准确定位。
- 浏览器控制台无错误，资源请求无 404。

## 不在本次范围

- 用户登录、云端进度同步或排行榜。
- 搜索后端、全文索引服务或服务端渲染。
- 对正文视觉体系进行全面重做。
- 将 PDF 拆成多份。
- 八周计划、今日任务、学习打卡提醒。
